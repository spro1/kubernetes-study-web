# Helm과 GitOps

매니페스트가 많아지면 "무엇을 한 번에 설치했는지"와 "지금 클러스터가 맞는 상태인지"를 따로 관리해야 한다. Helm은 앞의 문제를, GitOps는 뒤의 문제를 푼다. 여기서는 Helm 릴리스와 GitOps 동기화 도구(예: Argo CD, Flux)가 클러스터를 맞추는 원리를 따라가 본다.

## 밀어 넣기와 끌어오기

| 비교 | 밀어 넣기 방식 (CI/CD 파이프라인 배포) | 끌어오기 방식 (GitOps) |
| --- | --- | --- |
| 적용 주체 | 바깥의 CI/CD 도구 | 클러스터 안의 GitOps 도구 |
| 적용 시점 | 실행을 요청한 시점 한 번 | 계속 (주기적 비교) |
| 정본 | 도구의 배포 설정과 실행 이력 | Git 저장소 |
| 되돌리기 | 이력에서 이전 판을 골라 다시 적용 | Git에서 이전 커밋으로 되돌리면 도구가 따라간다 |
| 직접 수정 | 다음 배포 전까지 그대로 남는다 | 드리프트로 감지되고 되돌려질 수 있다 |

## 직접 확인해 보기

```bash
helm list -A                                         # 릴리스와 현재 리비전
helm history <릴리스> -n <네임스페이스>              # 롤백까지 포함한 리비전 이력
helm get values <릴리스> -n <네임스페이스>           # 차트를 채운 values
argocd app get <앱>                                  # Argo CD: Synced인지 OutOfSync인지
argocd app diff <앱>                                 # Git과 클러스터의 어긋남
flux get kustomizations -A                           # Flux: 준비 상태와 적용된 리비전
```
