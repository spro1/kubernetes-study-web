# 스테이트풀셋과 데이터베이스

데이터베이스처럼 파드마다 정체성과 데이터가 있는 앱은 디플로이먼트로 돌리기 어렵다. 스테이트풀셋(StatefulSet)이 이름·순서·저장소를 어떻게 고정하는지 따라가 본다. PVC가 실제 저장 공간이 되는 과정은 [저장 공간이 붙기까지](../k8s/storage-volume.mdx)에서 다룬다.

## 동작별 결과

| 동작 | 파드 | PVC | 확인할 것 |
| --- | --- | --- | --- |
| 처음 만든다 | `db-0`부터 순서대로 생긴다 | 파드마다 `data-db-N`이 생긴다 | 앞 번호 파드가 Ready가 못 되면 다음 번호가 생기지 않는다 |
| `db-1`을 지운다 | 같은 이름으로 다시 생긴다 | 같은 `data-db-1`에 다시 연결된다 | 데이터가 그대로인지 |
| 3 → 2로 줄인다 | `db-2`가 지워진다 | `data-db-2`는 남는다 | 다시 늘리면 그 데이터로 돌아온다 |
| 스테이트풀셋을 지운다 | 모두 지워진다 | 기본적으로 모두 남는다 | 남은 PVC가 공간을 차지한다 |

딸린 파드는 `kubectl get pods -l <셀렉터>`, PVC는 `kubectl get pvc`로 확인한다. 줄이거나 지울 때 PVC를 함께 지울지는 `persistentVolumeClaimRetentionPolicy`로 정할 수 있다.
