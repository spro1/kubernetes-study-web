# 헬스 체크 — 살아 있나, 받을 준비가 됐나

컨테이너가 실행 중이라고 애플리케이션이 제대로 일한다는 보장은 없다. kubelet이 세 가지 정기 점검(프로브)으로 무엇을 묻고, 답에 따라 무엇을 하는지 따라가 본다. 컨테이너가 죽은 뒤 되살아나는 과정은 [파드가 죽으면 (자가 치유)](../k8s/self-healing.mdx)에서 다룬다.

## 프로브 설정 실수와 결과

| 프로브 | 흔한 실수 | 결과 | 바로잡기 |
| --- | --- | --- | --- |
| liveness | DB 연결까지 확인한다 | DB가 잠깐 느려지면 모든 파드가 동시에 재시작된다 | 프로세스가 살아 있는지만 확인한다 |
| liveness | 시작 시간보다 짧은 대기 시간 | 준비 전에 재시작이 반복되어 `CrashLoopBackOff` | startup 프로브를 두거나 대기 시간을 늘린다 |
| readiness | 아예 설정하지 않는다 | 준비되지 않은 새 파드로 요청이 가서 업데이트 때마다 오류가 난다 | 요청을 받을 준비가 됐는지 답하는 주소를 둔다 |
| readiness | 항상 성공만 응답한다 | 의존 서비스가 끊겨도 요청을 받아 오류를 사용자에게 돌려준다 | 필요한 의존성이 준비됐는지 여기서 본다 |
| startup | 시작이 느린 앱에 두지 않는다 | liveness가 먼저 실패해 시작하다가 재시작된다 | 시작에 걸리는 최대 시간만큼 기다리게 둔다 |
