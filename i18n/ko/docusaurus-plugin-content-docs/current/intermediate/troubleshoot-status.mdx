# 상태를 세 단계로 읽고 문제 확인하기

파드 목록의 "상태" 칸 하나에는 서로 다른 세 가지 정보가 섞여 있다. 이것을 풀어 읽고, 상황마다 이벤트와 로그 중 어디부터 볼지 따라가 본다. 파드가 뜨는 과정의 어느 단계에서 멈추는지는 [파드가 뜨기까지](../k8s/pod-startup.mdx)에서 다룬다.

## 상황별 먼저 볼 곳

| 상태 칸에 보이는 것 | 세 가지로 나누면 (단계 / 컨테이너 / 사유) | 먼저 볼 곳 | 확인할 것 |
| --- | --- | --- | --- |
| `Pending` | Pending / 아직 없음 / FailedScheduling | 이벤트 | `Insufficient cpu`·`memory`면 요청값·쿼터·노드 여유, taint면 배치 조건 |
| `ImagePullBackOff` | Pending / Waiting / ImagePullBackOff | 이벤트 | `not found`는 이름·태그, `unauthorized`는 인증, `timeout`은 저장소 주소·네트워크 |
| `CrashLoopBackOff` | Running / Waiting / CrashLoopBackOff | 직전 컨테이너 로그 | 앱 오류 메시지, Last State의 사유와 종료 코드 |
| `OOMKilled` | Running / Terminated / OOMKilled | 메모리 사용량 | 메모리 상한값과 실제 사용량 비교 |
| `CreateContainerConfigError` | Pending / Waiting / CreateContainerConfigError | 이벤트 | 참조한 컨피그맵·시크릿이 있는지, 키 이름이 맞는지 |
| `Unknown`, 여러 파드 동시 이상 | Unknown / - / - | 노드 상태 | NotReady, 압박 조건 |

이벤트는 `kubectl describe pod <이름>`, 직전 컨테이너 로그는 `kubectl logs <이름> --previous`로 본다. 로그는 파드에만 있으므로 디플로이먼트에서 문제를 발견하면 그 아래 파드로 내려간다. 네임스페이스 전체 이벤트는 `kubectl get events --sort-by=.lastTimestamp`로 본다.
