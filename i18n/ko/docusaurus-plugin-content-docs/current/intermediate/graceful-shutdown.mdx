# 정상 종료 — 요청을 잃지 않고 내려가기

배포·축소·노드 비우기는 모두 결국 "파드 하나를 지운다"로 끝난다. 그 파드가 처리하던 요청을 잃지 않고 내려가는 순서를 따라가 본다. 배포 전체 흐름은 [무중단 배포](../k8s/rolling-update.mdx), 노드 정비 흐름은 [노드 비우기와 업그레이드](../k8s/node-drain.mdx)에서 다룬다.

## 종료 순서 한눈에

| 차례 | 무엇이 일어나나 | 앱·설정이 할 일 |
| --- | --- | --- |
| 1 | 파드가 Terminating으로 바뀌고 유예 시간이 돌기 시작한다 | 긴 작업이 있으면 `terminationGracePeriodSeconds`를 늘린다(기본 30초) |
| 2 | 요청 대상에서 빠지는 일과 종료가 동시에 시작된다 | 순서가 보장되지 않는다는 것을 전제로 설계한다 |
| 3 | `preStop` 훅이 실행된다 | 몇 초 기다리게 해 요청 대상에서 빠지는 소식이 퍼질 시간을 번다 |
| 4 | SIGTERM 신호가 온다 | 새 요청을 받지 않고, 처리 중인 요청을 끝내고, 스스로 종료한다 |
| 5 | 유예 시간이 지나면 SIGKILL로 강제 종료된다 | 여기까지 오면 처리 중이던 요청은 실패한다 |

`terminationGracePeriodSeconds`와 `preStop`은 파드 템플릿의 `spec`에 적는다. 적용된 값은 `kubectl get pod <이름> -o yaml`로 확인한다.
