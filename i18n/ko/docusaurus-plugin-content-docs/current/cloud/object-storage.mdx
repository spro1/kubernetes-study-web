# 오브젝트 스토리지는 이렇게 움직인다

쇼핑몰 앱이 상품 사진을 오브젝트 스토리지에 저장하고 사용자에게 보여 준다. 여기서는 Amazon S3를 예로 든다. Google Cloud Storage, Azure Blob Storage, MinIO도 이름만 다를 뿐 같은 방식으로 움직인다. 사진 한 장이 올라가서 보관 등급으로 옮겨질 때까지 따라가며, 단계마다 누가 읽을 수 있는지 본다.

## 블록·파일·오브젝트 스토리지

| | 블록 스토리지 | 파일 스토리지 | 오브젝트 스토리지 |
|---|---|---|---|
| 예 | Amazon EBS, Persistent Disk, Azure Disk | Amazon EFS, Filestore, Azure Files, NFS | Amazon S3, Cloud Storage, Azure Blob, MinIO |
| 쓰는 방법 | 서버 한 대에 디스크로 마운트하고 파일 시스템을 올린다 | 여러 서버가 공유 폴더로 마운트한다 | HTTP API (PUT, GET, DELETE, LIST) |
| 단위 | 블록 | 디렉터리 안의 파일 | 평평한 키 아래 통째 객체 |
| 일부만 고치기 | 된다 | 된다 | 안 된다. 객체를 통째로 바꾼다 |
| 여러 클라이언트 공유 | 보통 한 번에 노드 하나 | 된다 | 된다. 네트워크로 어디서나 |
| 쿠버네티스에서 | PersistentVolume (ReadWriteOnce) | PersistentVolume (ReadWriteMany) | 앱이 API로 호출하거나, 제약을 감수하고 CSI 드라이버로 마운트 |
| 어울리는 곳 | 데이터베이스, 부트 디스크 | 오래된 앱의 공유 파일 | 이미지, 백업, 로그, 데이터셋, 모델 파일 |

```bash
aws s3 ls s3://shop-images/photos/                         # 접두사("폴더") 나열
aws s3 cp ./123.jpg s3://shop-images/photos/123.jpg        # 업로드 (큰 파일은 자동으로 멀티파트)
aws s3api head-object --bucket shop-images --key photos/123.jpg   # 크기, ETag, 스토리지 클래스, VersionId
aws s3 presign s3://shop-images/photos/123.jpg --expires-in 600   # 10분짜리 임시 URL
aws s3api get-public-access-block --bucket shop-images     # 퍼블릭 액세스가 막혀 있나
aws s3api get-bucket-versioning --bucket shop-images       # Enabled / Suspended / (비어 있으면 켠 적 없음)
aws s3api list-object-versions --bucket shop-images --prefix photos/123.jpg   # 버전과 삭제 마커
aws s3api list-multipart-uploads --bucket shop-images      # 요금만 나가는 미완료 업로드
```
