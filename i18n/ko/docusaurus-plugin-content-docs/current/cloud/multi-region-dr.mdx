## 네 가지 DR 전략

범위는 AWS 재해 복구 백서를 따른다. 실제 숫자는 훈련에서 나온다.

| 전략 | 리전 B에서 도는 것 | RPO | RTO | 평소 비용 |
|---|---|---|---|---|
| 백업과 복원 | 백업 사본만. 인프라는 당일 IaC로 만든다 | 몇 시간 (마지막 백업 이후) | 몇 시간 | $ |
| 파일럿 라이트 | 살아 있는 데이터(복제본). 앱은 꺼짐 또는 0대 | 몇 초~몇 분 (복제 지연) | 수십 분 | $$ |
| 웜 스탠바이 | 바로 트래픽을 받을 수 있는 작은 전체 스택 | 몇 초~몇 분 | 몇 분 | $$$ |
| 멀티 사이트 액티브-액티브 | 전체 용량, 늘 사용자를 받음 | 거의 0 | 거의 0 | $$$$ |

어떤 전략이든 백업은 따로 둔다. 지운 테이블이나 암호화된 데이터를 되돌리는 것은 특정 시점의 사본뿐이다.

## 직접 확인해 보기

AWS 예시다. 다른 클라우드에도 이름만 다른 같은 부품이 있다.

```bash
# DB 스냅샷을 복구 리전으로 복사 (대상 리전에서 실행, 암호화된 스냅샷은 --kms-key-id 도 필요)
aws rds copy-db-snapshot --region ap-northeast-1 \
  --source-db-snapshot-identifier arn:aws:rds:ap-northeast-2:<계정>:snapshot:<스냅샷> \
  --target-db-snapshot-identifier <스냅샷>-dr

aws ec2 copy-snapshot --region ap-northeast-1 --source-region ap-northeast-2 --source-snapshot-id <snap-id>   # 디스크 스냅샷 복사

aws backup describe-backup-vault --backup-vault-name <볼트>          # Locked: 볼트 잠금이 켜져 있는지
aws route53 list-health-checks                                        # DNS 장애 조치 뒤의 헬스 체크
aws route53 get-health-check-status --health-check-id <id>            # 지금 각 확인 지점이 보는 상태
dig +noall +answer shop.example.com                                   # 클라이언트가 캐시할 TTL
```

복원 훈련 체크리스트: 백업 하나를 무작위로 고른다 → 빈 환경에 복원한다 → 그 데이터로 앱을 띄운다 → 가장 최근 레코드의 시각을 본다(RPO) → 걸린 전체 시간(RTO)과 모든 수작업을 적는다.
