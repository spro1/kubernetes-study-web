# 서버리스 함수는 이렇게 실행된다

코드만 올리고 어떤 이벤트가 그 코드를 실행할지만 정한다. 실행할 자리는 플랫폼이 찾고, 이벤트가 몰리면 복사본을 늘리고, 아무 일도 없으면 치운다. AWS Lambda를 예로 함수 하나가 **이벤트 → 실행 환경 → 결과**로 가는 길을 따라간다. Google Cloud Run, Azure Functions, 쿠버네티스 위의 Knative도 한도만 다를 뿐 같은 틀로 움직인다.

## VM, 쿠버네티스 위 컨테이너, 함수 중 무엇을 쓸까

| | 가상 머신 | 쿠버네티스 위 컨테이너 | 서버리스 함수 |
|---|---|---|---|
| 내가 관리하는 것 | OS, 런타임, 앱, 확장 | 이미지, 매니페스트, 클러스터(또는 관리형) | 코드와 설정만 |
| 확장 단위 | VM 전체(분 단위) | 파드(초 단위) | 요청마다 실행 환경(밀리초~초 단위) |
| 놀 때 비용 | 켜 둔 동안 낸다 | 노드를 켜 둔 동안 낸다 | 거의 0 (0까지 줄어듦) |
| 실행 길이 | 제한 없음 | 제한 없음 | 상한 있음 (Lambda 30분) |
| 상태 | 로컬 디스크가 남는다 | 필요하면 볼륨(PV) | 호출 사이에 없음, 외부 저장소 사용 |
| 잘 맞는 곳 | 기존 앱, 특수한 OS 요구 | 꾸준한 서비스, 많은 마이크로서비스 | 몰렸다 끊기는 이벤트, 연결 코드, 웹훅, 파일 처리 |

Knative는 함수 방식(0까지 줄이기, 동시성 기준 확장)을 직접 운영하는 쿠버네티스 클러스터 위로 가져온다.

```bash
  --payload '{"id": 1}' out.json && cat out.json                  # 동기 호출

  --query '[Runtime,MemorySize,Timeout]'                          # 비용과 한도를 정하는 설정
aws logs tail /aws/lambda/demo --since 10m                        # REPORT 줄: Duration, Billed Duration, Init Duration
aws lambda get-account-settings --query 'AccountLimit.ConcurrentExecutions'   # 계정 동시성 한도
aws lambda put-function-concurrency --function-name demo \
  --reserved-concurrent-executions 50                             # 함수 하나에 동시성 예약(상한도 됨)
aws lambda put-provisioned-concurrency-config --function-name demo \
  --qualifier live --provisioned-concurrent-executions 5          # 환경 5개를 미리 초기화해 둔다(과금)
```
