# CDN이 요청에 답하는 방식

CDN(Content Delivery Network, 콘텐츠 전송 네트워크)은 사용자 가까운 여러 엣지 위치에 응답 사본을 둔다. 파일 하나가 처음 미스가 났다가 히트가 되기까지를 따라가고, 배포 직후와 개인 페이지에서 무엇이 잘못되는지 본다. 웹 요청의 기본 흐름은 [주소창에 주소를 입력하면](../basic/web-request.mdx)에서 먼저 볼 수 있다.

## 읽어야 할 응답 헤더

| 헤더 | 예 | 알려 주는 것 |
|---|---|---|
| Cache-Control | `public, max-age=31536000, immutable` | 누가 얼마나 저장해도 되는지. `s-maxage` 는 공유 캐시에만 적용된다. `private`, `no-store` 는 CDN에 저장되지 않게 한다 |
| Age | `120` | 응답이 캐시에 있던 초. 없거나 0이면 보통 오리진에서 막 온 것이다 |
| ETag | `"5d8c72a5"` | 내용의 버전 표시. `If-None-Match` 에 담아 `304 Not Modified` 를 받는다 |
| Last-Modified | `Tue, 24 Nov 2026 03:10:00 GMT` | `If-Modified-Since` 로 다시 확인하는 예전 방식 |
| Vary | `Accept-Encoding` | 캐시 키에 들어가는 요청 헤더. `Vary: *` 나 값이 많으면 히트율이 떨어진다 |
| 히트 헤더(업체마다 다름) | `X-Cache: Hit from cloudfront`, `cf-cache-status: HIT` | CDN 자체 판정: HIT, MISS, EXPIRED, BYPASS 등. 이름과 값은 업체마다 다르다 |

## 직접 확인해 보기

```bash
dig +short www.example.com                         # CDN 호스트 이름으로 가는 CNAME이면 CDN이 앞에 있다
curl -sI https://<내-사이트>/<파일> | grep -iE 'cache-control|^age|etag|x-cache|cf-cache-status'   # 첫 번째: 대개 MISS
curl -sI https://<내-사이트>/<파일> | grep -iE 'cache-control|^age|etag|x-cache|cf-cache-status'   # 두 번째: HIT, Age 가 커진다
curl -sI -H 'If-None-Match: "<위에서 본 etag>"' https://<내-사이트>/<파일> | head -1     # 안 바뀌었으면 304
curl -sI https://<내-사이트>/account | grep -i cache-control   # 개인 페이지는 private 이나 no-store 여야 한다
```
