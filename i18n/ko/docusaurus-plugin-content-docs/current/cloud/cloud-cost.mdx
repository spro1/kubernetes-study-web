# 클라우드 청구서는 어디서 나오나

이번 달 청구서가 예산보다 30% 많이 나왔는데 아무도 이유를 모른다. 청구서를 줄 단위로 따라가 본다. **컴퓨팅, 스토리지, 데이터 전송, 관리형 서비스**를 차례로 보고, 쿠버네티스 클러스터 안으로 들어가 파드 요청값이 노드 수를 조용히 정하는 모습을 본다. 이름과 가격은 AWS를 예로 든다. 다른 클라우드도 같은 종류의 항목에 요금을 매긴다.

## 비용 요인과 흔한 낭비

| 비용 요인 | 흔한 낭비 | 고치는 법 |
|---|---|---|
| 컴퓨팅 (VM, 노드) | 전부 온디맨드, 너무 큰 인스턴스 유형 | 꾸준한 부하는 약정, 견디는 작업은 스팟, 인스턴스 유형 크기 조정 |
| 쿠버네티스 요청값 | 사용량보다 훨씬 큰 요청값 때문에 꽉 찼지만 노는 노드 | 측정한 사용량으로 요청값 설정, 노드 통합 켜기 |
| 블록 스토리지 | 연결 안 된 볼륨, 너무 크게 잡은 크기 | `available` 볼륨을 찾아 지우거나 스냅샷으로 남기기 |
| 스냅샷과 백업 | 보존 규칙 없이 몇 년 쌓인 스냅샷 | 보존·수명 주기 정책 |
| 오브젝트 스토리지 | 가장 비싼 클래스에 남은 오래된 데이터 | 더 차가운 클래스로 옮기거나 지우는 수명 주기 규칙 |
| NAT 게이트웨이 | GB당 처리되는 이미지 다운로드와 클라우드 API 트래픽 | 클라우드 서비스용 프라이빗 엔드포인트, VPC 안 풀스루 캐시나 레지스트리 |
| 가용 영역 간 트래픽 | 여러 영역에 흩어진 대화 많은 서비스 | 토폴로지 인식 라우팅, 많이 주고받는 서비스는 한 영역에 |
| 인터넷 송신 | 큰 파일을 서버에서 바로 내보냄 | 앞단에 CDN, 압축 |
| 관리형 서비스 | 24시간 켜 둔 운영 외 데이터베이스 | 업무 시간 밖 중지·축소 일정, 잔여물 삭제 |
| 태그 없는 자원 | 주인 없는 지출 | 만들 때 필수 태그 강제 |

## 직접 확인해 보기

```bash
# 지난달 서비스별 비용 (AWS Cost Explorer)
aws ce get-cost-and-usage --time-period Start=2026-10-01,End=2026-11-01 \
  --granularity MONTHLY --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE

# 활성화한 비용 할당 태그로 묶어 보기
aws ce get-cost-and-usage --time-period Start=2026-10-01,End=2026-11-01 \
  --granularity MONTHLY --metrics UnblendedCost --group-by Type=TAG,Key=team

# 연결 안 된 채 과금 중인 볼륨
aws ec2 describe-volumes --filters Name=status,Values=available \
  --query 'Volumes[].[VolumeId,Size,CreateTime]' --output table

# 쿠버네티스: 실제 사용량과 요청값 비교
kubectl top pods -A --sort-by=cpu
kubectl get pods -A -o custom-columns='NS:.metadata.namespace,POD:.metadata.name,CPU_REQ:.spec.containers[*].resources.requests.cpu,MEM_REQ:.spec.containers[*].resources.requests.memory'
kubectl describe nodes | grep -A 8 'Allocated resources'   # 노드마다 요청된 비율
```
