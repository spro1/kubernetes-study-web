# 테라폼으로 하는 코드형 인프라

클라우드 콘솔에서 버튼을 눌러 만드는 방식은 한 번은 된다. 하지만 검토하기 어렵고, 똑같이 다시 만들기 어렵고, 무엇을 바꿨는지 잊기 쉽다. 코드형 인프라(IaC, Infrastructure as Code)는 원하는 서버와 방화벽을 파일에 적고 도구가 클라우드를 그 모습에 맞추게 한다. 테라폼으로 **코드 → init → plan → apply → 상태**를 따라간다. 오픈소스 포크인 OpenTofu도 같은 파일과 명령을 쓴다(`terraform` 대신 `tofu`). 여기서 만드는 네트워크는 [VPC 안에서 요청이 가는 길](../cloud/vpc-request.mdx)에서 설명한다.

## plan 기호 읽기

| 기호 | 동작 | 뜻 |
|---|---|---|
| `+` | create | 코드에는 있고 상태에는 없다. 새로 만든다 |
| `-` | destroy | 상태에는 있고 코드에서는 빠졌다. 지운다 |
| `~` | update in place | 있는 객체의 속성 일부만 바꾼다. ID는 그대로다 |
| `-/+` | replace | 먼저 지우고 새 객체를 만든다. `# forces replacement` 를 찾아본다 |
| `+/-` | replace (먼저 생성) | `create_before_destroy` 가 켜져 있어 새 객체를 먼저 만들고 옛 객체를 지운다 |
| `<=` | read | 아직 모르는 값에 기대는 데이터 소스를 apply 중에 읽는다 |

모든 plan의 마지막 줄이 요약이다: `Plan: X to add, Y to change, Z to destroy.` 무엇보다 Z부터 본다.

## 직접 확인해 보기

```bash
terraform init                      # 프로바이더 내려받기, 백엔드 설정
terraform fmt -check && terraform validate   # 형식과 문법 검사
terraform plan -out=tfplan          # 코드·상태·클라우드 비교, 계획 저장
terraform show tfplan               # 저장한 계획 검토
terraform apply tfplan              # 바로 그 계획만 적용
terraform plan -refresh-only        # 테라폼 밖에서 바뀐 것(드리프트)만 보기
terraform state list                # 테라폼이 관리하는 자원 목록
terraform state show aws_instance.web   # 기록된 속성과 실제 ID
terraform destroy                   # 상태에 있는 것 전부 삭제 (먼저 묻는다)
# OpenTofu: terraform 대신 tofu 로 같은 명령
```
