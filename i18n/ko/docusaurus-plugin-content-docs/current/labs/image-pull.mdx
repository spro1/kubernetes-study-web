# 실습 03 · 도착하지 않는 이미지

이 실습은 [노트북에 실습 클러스터 만들기](../basic/lab-cluster.mdx)에서 만든 kind 클러스터에서 한다. 노드가 Docker Hub에서 이미지를 받아야 하니 인터넷 연결이 필요하다. 먼저 `kubectl config current-context`가 `kind-lab`인지 확인한다.

## 목표

디플로이먼트 `web`과 `api`가 컨테이너를 하나도 시작하지 못한다. 이미지 받기 오류를 읽어 두 원인을 구분하고, 둘 다 실행되게 한다.

## 준비

```bash
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: lab-03
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: lab-03
spec:
  replicas: 1
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:1.27-alpnie
---
# The team's private mirror of nginx
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
  namespace: lab-03
spec:
  replicas: 1
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
        - name: api
          image: registry.lab.invalid/mirror/nginx:1.27
EOF
```

## 증상

```bash
kubectl -n lab-03 get pods
```

```text
NAME                   READY   STATUS             RESTARTS   AGE
api-5f7d9b8c6-wq4lz    0/1     ImagePullBackOff   0          50s
web-6c8f7d5b9-h2kxn    0/1     ErrImagePull       0          50s
```

몇 번 더 실행해 본다. 각 파드는 `ErrImagePull`(방금 받기에 실패함)과 `ImagePullBackOff`(다음 시도까지 기다리는 중이고, 기다리는 시간이 점점 길어짐)를 오간다.

## 살펴보기

```bash
kubectl -n lab-03 describe pod -l app=web     # Events: 이미지 받기 오류 전문
kubectl -n lab-03 describe pod -l app=api
kubectl -n lab-03 get events --sort-by=.lastTimestamp
kubectl -n lab-03 get deploy -o wide          # IMAGES 칸
```

두 파드의 상태는 같다. 차이는 `Failed to pull image` 이벤트의 마지막 몇 단어에 있다.

## 힌트

<details>
<summary>힌트 1</summary>

이미지 받기 오류는 세 무리로 나뉜다. **not found**: 레지스트리는 답했지만 그 이름이나 태그가 없다. **unauthorized / access denied**: 레지스트리가 인증 정보를 요구한다. **no such host / timeout**: 노드가 레지스트리에 아예 닿지 못한다. 각 파드는 어느 무리인가?

</details>

<details>
<summary>힌트 2</summary>

`web`은 태그를 한 글자씩 읽어 본다. 공식 nginx 이미지에는 `-alpine` 태그가 있다. `nginx`처럼 짧은 이름은 `docker.io/library/nginx`로 풀린다.

</details>

<details>
<summary>힌트 3</summary>

`api`의 오류는 `no such host`로 끝난다. 이미지 받기용 Secret을 넣으면 달라질까? 인증 정보는 노드가 레지스트리에 연결된 뒤에야 쓰인다.

</details>

## 정답

<details>
<summary>정답</summary>

**문제 1: 태그 오타.** `web`의 이벤트는 참조를 풀 수 없다며 `not found`로 끝난다. 예를 들면 다음과 같다.

```text
Warning  Failed  ...  Failed to pull image "nginx:1.27-alpnie": ... docker.io/library/nginx:1.27-alpnie: not found
```

레지스트리에는 닿았지만 `1.27-alpnie`라는 태그가 없다. 올바른 태그를 쓴다.

```bash
kubectl -n lab-03 set image deployment/web nginx=nginx:1.27-alpine
```

**문제 2: 노드가 쓸 수 없는 사설 레지스트리.** `api`의 이벤트는 DNS 오류 `... lookup registry.lab.invalid ...: no such host`로 끝난다. `.invalid` 도메인은 절대 풀리지 않는다. 여기서는 주소를 잘못 적었거나 다른 네트워크에서만 닿는 사설 레지스트리를 흉내 낸다.

노드가 닿을 수 있는 진짜 사설 레지스트리라면 흔한 오류는 인증 오류(`401 Unauthorized`, `authorization failed`, `access denied`)다. 그때는 이미지 받기용 Secret을 만들고 파드 스펙에서 참조한다.

```bash
# For a real private registry (not needed to finish this lab)
kubectl -n lab-03 create secret docker-registry regcred \
  --docker-server=registry.example.com --docker-username=<user> --docker-password=<token>
kubectl -n lab-03 patch deployment api \
  -p '{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"regcred"}]}}}}'
```

이 실습에서는 노드가 로그인 단계까지 가지도 못하니 Secret이 소용없다. 미러가 없어졌으니 `api`를 공개 이미지로 되돌린다.

```bash
kubectl -n lab-03 set image deployment/api api=nginx:1.27
```

주의할 점이 있다. Docker Hub는 없는 저장소를 받으려 하면 `not found`가 아니라 인증 오류로 답한다. 그래서 "unauthorized" 오류가 이미지 이름 오타를 뜻할 수도 있다.

</details>

## 확인

```bash
kubectl -n lab-03 rollout status deployment web
kubectl -n lab-03 rollout status deployment api
kubectl -n lab-03 get pods
```

```text
NAME                   READY   STATUS    RESTARTS   AGE
api-7b9c5d6f8-p8vjs    1/1     Running   0          25s
web-58d7c4f9b6-xr5tm   1/1     Running   0          40s
```

두 파드 모두 `Running`이고 `1/1`이다. 이제 `describe` 이벤트에 `Pulled`와 `Started`가 보인다.
