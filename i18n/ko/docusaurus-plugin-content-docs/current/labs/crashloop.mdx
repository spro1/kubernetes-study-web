# 실습 02 · 계속 쓰러지는 컨테이너

이 실습은 [노트북에 실습 클러스터 만들기](../basic/lab-cluster.mdx)에서 만든 kind 클러스터에서 한다. 먼저 `kubectl config current-context`가 `kind-lab`인지 확인한다.

## 목표

작은 앱이 ConfigMap에서 로그 레벨을 읽고 설정 파일을 출력한다. 그런데 준비 상태가 되지 않는다. 실수 두 개를 찾아 파드를 재시작 없이 `Running`으로 만든다.

## 준비

```bash
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: lab-02
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: lab-02
data:
  log-level: info
  app.conf: |
    greeting=hello
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app
  namespace: lab-02
spec:
  replicas: 1
  selector:
    matchLabels:
      app: app
  template:
    metadata:
      labels:
        app: app
    spec:
      containers:
        - name: app
          image: busybox:1.36
          command: ["sh", "-c", "echo \"log level: $LOG_LEVEL\"; cat /etc/app/settings.conf && sleep 86400"]
          env:
            - name: LOG_LEVEL
              valueFrom:
                configMapKeyRef:
                  name: app-config
                  key: LOG_LEVEL
          volumeMounts:
            - name: config
              mountPath: /etc/app
      volumes:
        - name: config
          configMap:
            name: app-config
EOF
```

## 증상

```bash
kubectl -n lab-02 get pods
```

```text
NAME                   READY   STATUS                       RESTARTS   AGE
app-6d4b8c9f7b-zk2pw   0/1     CreateContainerConfigError   0          30s
```

파드 이름 끝부분은 다를 수 있다. 첫 번째 문제를 고치면 새 파드의 상태가 바뀌니, 고칠 때마다 `kubectl get pods`를 다시 본다.

## 살펴보기

```bash
kubectl -n lab-02 describe pod -l app=app        # State, Last State, Events
kubectl -n lab-02 get configmap app-config -o yaml
kubectl -n lab-02 logs deploy/app                 # 지금 컨테이너
kubectl -n lab-02 logs deploy/app --previous      # 직전에 종료된 컨테이너
```

두 가지를 차례로 묻는다. 컨테이너가 시작은 했는가? 시작했다면 왜 종료됐는가?

## 힌트

<details>
<summary>힌트 1</summary>

`CreateContainerConfigError`는 kubelet이 컨테이너 설정조차 만들지 못했다는 뜻이라 아직 로그가 없다. 이유는 `kubectl describe pod`의 이벤트에 있다. 이벤트에 나온 키를 ConfigMap의 키와 비교한다.

</details>

<details>
<summary>힌트 2</summary>

ConfigMap 키는 대소문자를 가리는 문자열이다. `LOG_LEVEL`과 `log-level`은 다른 키다. 키를 고치면 파드는 `Error`를 거쳐 `CrashLoopBackOff`로 넘어간다.

</details>

<details>
<summary>힌트 3</summary>

`describe`에서 Last State를 본다. `Terminated`, Reason `Error`, Exit Code `1`이다. 그다음 `kubectl logs --previous`를 읽는다. 명령은 어떤 파일을 여는가? ConfigMap 볼륨은 `/etc/app`에 실제로 어떤 파일을 만드는가?

</details>

## 정답

<details>
<summary>정답</summary>

**문제 1: ConfigMap에 없는 키.** 파드 이벤트에 다음과 같은 `Failed` 이벤트가 있다.

```text
Warning  Failed  ...  Error: couldn't find key LOG_LEVEL in ConfigMap lab-02/app-config
```

환경 변수는 `LOG_LEVEL` 키를 가리키는데 ConfigMap에는 `log-level`과 `app.conf`만 있다. 참조한 키가 없으면 컨테이너를 만들지 못하므로 상태는 `CreateContainerConfigError`이고 아무것도 실행되지 않는다. (참조에 `optional: true`를 붙이면 변수 없이 시작하지만, 이 앱에는 값이 필요하다.)

**문제 2: 종료 코드 1로 끝나는 명령.** 키를 고치면 컨테이너가 시작해 한 줄을 출력하고 종료된다. `kubectl logs --previous`는 다음을 보여 준다.

```text
log level: info
cat: can't open '/etc/app/settings.conf': No such file or directory
```

ConfigMap 볼륨은 키마다 파일을 하나씩 만들기 때문에 `/etc/app`에는 `log-level`과 `app.conf`가 있다. `cat`이 종료 코드 1로 실패하면 `&&` 때문에 `sleep`이 건너뛰어지고 셸이 1로 끝난다. kubelet은 재시작 간격을 점점 늘리며 다시 띄우는데, 이것이 `CrashLoopBackOff`로 보인다.

두 줄을 고쳐 디플로이먼트를 다시 적용한다.

```bash
kubectl apply -f - <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app
  namespace: lab-02
spec:
  replicas: 1
  selector:
    matchLabels:
      app: app
  template:
    metadata:
      labels:
        app: app
    spec:
      containers:
        - name: app
          image: busybox:1.36
          command: ["sh", "-c", "echo \"log level: $LOG_LEVEL\"; cat /etc/app/app.conf && sleep 86400"]
          env:
            - name: LOG_LEVEL
              valueFrom:
                configMapKeyRef:
                  name: app-config
                  key: log-level
          volumeMounts:
            - name: config
              mountPath: /etc/app
      volumes:
        - name: config
          configMap:
            name: app-config
EOF
```

</details>

## 확인

```bash
kubectl -n lab-02 rollout status deployment app
kubectl -n lab-02 get pods
kubectl -n lab-02 logs deploy/app
```

```text
deployment "app" successfully rolled out
NAME                   READY   STATUS    RESTARTS   AGE
app-7f5c6d8b9c-m4r7t   1/1     Running   0          15s
log level: info
greeting=hello
```

`RESTARTS`가 `0`에 머문다. 1분쯤 기다렸다가 다시 확인하면 확실하다.
