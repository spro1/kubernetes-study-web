# 노드를 늘리고 줄이기 (Cluster Autoscaler와 Karpenter)

HPA는 파드를 늘리지만, 파드가 올라갈 기계는 다른 누군가가 늘려야 한다. Pending 파드 하나를 **Cluster Autoscaler**와 **Karpenter**로 따라가 보고, 두 도구가 노드를 다시 지우는 과정과 그것을 막는 것을 본다.

## Cluster Autoscaler와 Karpenter 비교

| | Cluster Autoscaler | Karpenter |
|---|---|---|
| 다루는 단위 | 노드 그룹(ASG, 노드 풀, VM 스케일 세트) | NodePool에서 나온 NodeClaim |
| 인스턴스 타입 | 그룹마다 고정 | 허용 조건 안에서 파드 묶음마다 고름 |
| 확장 방식 | 그룹 템플릿에 파드를 올려 보고 desired 크기를 올림 | 컴퓨트 API를 직접 부름 |
| 축소 | 사용률 기준 아래이고 파드가 다른 곳에 들어가는 상태가 기본 10분 이어질 때 | 통합: 지우거나 더 싼 것으로 교체(`consolidationPolicy`, `consolidateAfter`) |
| 파드가 있는 노드를 못 지우게 | `cluster-autoscaler.kubernetes.io/safe-to-evict: "false"` | `karpenter.sh/do-not-disrupt: "true"` |
| 노드를 못 지우게 | 노드 주석 `cluster-autoscaler.kubernetes.io/scale-down-disabled: "true"` | 노드 주석 `karpenter.sh/do-not-disrupt: "true"`, 또는 `nodes: "0"` 예산 |
| 스팟 중단 | 제공자나 별도 핸들러에 맡김 | 중단 큐로 직접 처리 |
| 쓸 수 있는 곳 | 여러 클라우드 | AWS, Azure, Karpenter 연동이 있는 다른 제공자 |

## 직접 확인해 보기

```bash
kubectl get pods -A --field-selector=status.phase=Pending      # 노드를 기다리는 파드
kubectl describe pod <pod>                                     # Events: TriggeredScaleUp / NotTriggerScaleUp, 또는 Karpenter 이벤트
kubectl get nodes -L node.kubernetes.io/instance-type,topology.kubernetes.io/zone

# Cluster Autoscaler
kubectl -n kube-system get configmap cluster-autoscaler-status -o yaml   # 그룹별 확장·축소 상태

# Karpenter
kubectl get nodepools                                          # 풀, 준비 상태, 사용 중인 자원
```
