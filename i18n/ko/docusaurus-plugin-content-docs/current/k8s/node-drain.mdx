## 업그레이드에 대한 흔한 오해

| 오해 | 실제 |
| --- | --- |
| 최신 버전으로 한 번에 올리면 된다 | 부 버전은 한 단계씩만 올린다 |
| drain은 파드를 무중단으로 옮긴다 | 지우고 다른 곳에서 새로 만든다. 복제본이 하나면 중단이 생긴다 |
| PDB를 걸면 노드 고장에도 안전하다 | PDB는 drain 같은 정비 작업에만 효력이 있다 |
| 엔진 업그레이드가 성공하면 애플리케이션도 문제없다 | 새 버전에서 제거된 API를 쓰는 배포는 다음 배포 때 실패한다 |

## 직접 확인해 보기

```bash
kubectl version                                      # 서버(컨트롤 플레인) 버전
kubectl get nodes                                    # 노드별 kubelet VERSION, SchedulingDisabled
kubectl get pdb -A                                   # ALLOWED DISRUPTIONS가 0이면 drain이 멈춘다
kubectl get pods -A -o wide --field-selector spec.nodeName=<노드>   # 그 노드에 있는 파드
kubectl drain <노드> --ignore-daemonsets --dry-run=client   # 내보낼 파드 미리 보기, 바꾸는 것 없음
```
