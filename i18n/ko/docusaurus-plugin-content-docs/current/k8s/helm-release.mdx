# 헬름 릴리스의 설치·업그레이드·롤백

shop이라는 릴리스 하나를 **차트 + values → 렌더링 → 적용 → 리비전** 순서로 따라간다. 헬름이 이력을 어디에 두는지, 망가진 업그레이드가 왜 "deployed"라고 나올 수 있는지, 롤백이 실제로 무엇을 하는지 본다.

## 릴리스 상태 읽기

`helm status shop`과 `helm history shop`은 리비전마다 상태 하나를 보여 준다.

| 상태 | 뜻 | 할 일 |
|---|---|---|
| deployed | 현재 리비전. API 서버가 객체를 받아들였다 | 그래도 파드를 본다. `--wait` 없이는 deployed가 준비됨을 뜻하지 않는다 |
| superseded | 교체된 옛 리비전 | 없다. 롤백할 수 있는 이력이다 |
| failed | 적용이 거부됐거나, 훅이 실패했거나, `--wait`가 시간 초과됐다 | `helm history`와 파드 이벤트를 읽고, values를 고쳐 다시 업그레이드하거나 롤백한다 |
| pending-install / pending-upgrade / pending-rollback | 작업이 시작됐지만 끝나지 않았다(예: CLI가 강제 종료됨) | 새 작업이 "another operation is in progress"로 실패한다. 마지막 정상 리비전으로 롤백한다 |
| uninstalled | `helm uninstall --keep-history`로 지웠다 | `helm rollback`으로 되살릴 수 있다 |

## 직접 확인해 보기

```bash
helm create demo                                        # 차트 뼈대 만들기: Chart.yaml, values.yaml, templates/
helm show values ./demo | head -20                      # 덮어쓸 수 있는 기본값
helm template shop ./demo --set replicaCount=3          # 렌더링만, 클러스터는 안 건드림
helm install shop ./demo -n shop --create-namespace --set replicaCount=3
helm upgrade shop ./demo -n shop --set replicaCount=2 --wait --timeout 3m
helm history shop -n shop                               # REVISION, STATUS, DESCRIPTION
helm get values shop -n shop                            # 내가 넘긴 values
kubectl get secret -n shop -l owner=helm                # 리비전마다 시크릿 하나
helm rollback shop 1 -n shop                            # 새 리비전을 쓴다
```
