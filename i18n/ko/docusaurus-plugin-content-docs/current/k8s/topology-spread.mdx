# 파드를 존에 고르게 펼치기 (토폴로지 분산 제약)

레플리카 6개가 한 존에 몰려 있으면 존 장애 한 번에 다 잃는다. **topologySpreadConstraints**가 존별·노드별로 파드를 세고, 균형을 깨는 자리를 거절하고, 죽은 존과 롤링 업데이트를 만나는 과정을 스케줄러와 함께 따라간다.

## 필드 한눈에 보기

| 필드 | 하는 일 | 주의할 점 |
|---|---|---|
| `topologyKey` | 값이 도메인이 되는 노드 레이블(`topology.kubernetes.io/zone`, `kubernetes.io/hostname`) | 레이블이 없는 노드는 통째로 건너뛴다 |
| `maxSkew` | 한 도메인과 전체 최솟값 사이에 허용하는 가장 큰 차이 | 1 이상이어야 한다 |
| `whenUnsatisfiable` | `DoNotSchedule`(기본값)은 노드를 거른다. `ScheduleAnyway`는 점수만 매긴다 | DoNotSchedule은 장애 중 파드를 Pending으로 남길 수 있다 |
| `labelSelector` | 셀 파드. 같은 네임스페이스만 | 파드가 자기 셀렉터와 맞아야 자기 자신을 센다 |
| `matchLabelKeys` | 이 레이블 키에 대한 이 파드의 값을 셀렉터에 더한다(예: `pod-template-hash`) | 실행 중인 파드에서 고치는 레이블은 쓰지 않는다 |
| `minDomains` | 도메인이 이만큼 생길 때까지 전체 최솟값을 0으로 본다 | `DoNotSchedule`과만 |
| `nodeAffinityPolicy` | `Honor`(기본값): 파드의 노드 어피니티와 맞는 노드만 센다 | `Ignore`는 모든 노드를 센다 |
| `nodeTaintsPolicy` | `Ignore`(기본값): 테인트를 따지지 않는다. `Honor`: 견디지 못하는 테인트가 있는 노드는 뺀다 | 기본값은 테인트 달린 노드도 도메인으로 센다 |

```bash
kubectl get nodes -L topology.kubernetes.io/zone          # 노드마다 어느 존인지
kubectl explain pod.spec.topologySpreadConstraints        # 이 클러스터 버전이 지원하는 필드

# app=web 파드의 존별 개수
for n in $(kubectl get pods -l app=web -o jsonpath='{.items[*].spec.nodeName}'); do
  kubectl get node "$n" -o jsonpath='{.metadata.labels.topology\.kubernetes\.io/zone}{"\n"}'
done | sort | uniq -c

kubectl get pods -l app=web --field-selector=status.phase=Pending
kubectl describe pod <pending-pod>                        # "didn't match pod topology spread constraints"
kubectl get deploy web -o jsonpath='{.spec.template.spec.topologySpreadConstraints}'
```
