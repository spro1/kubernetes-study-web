# 사설 레지스트리에서 이미지 받기

## 풀 오류와 그 뜻

| 이벤트 메시지나 reason | 원인 | 고치는 법 |
|---|---|---|
| `401 Unauthorized`, `unauthorized`, `authorization failed` | 이 레지스트리에 쓸 자격 증명이 없거나 틀렸다 | 시크릿의 서버 이름이 이미지의 레지스트리와 정확히 같은지, 사용자와 토큰이 맞는지 본다 |
| `FailedToRetrieveImagePullSecret` | 지정한 풀 시크릿이 파드의 네임스페이스에 없다 | 그 네임스페이스에 시크릿을 만들거나 이름을 고친다 |
| `manifest unknown`, `not found` | 이름이나 태그가 없다(또는 이 CPU 아키텍처용 이미지가 없다) | 이미지 이름이나 태그를 고치고 레지스트리 화면에서 확인한다 |
| `403 Forbidden`, `denied` | 로그인은 됐지만 이 계정은 이 저장소를 읽을 수 없다 | 계정이나 토큰에 풀 권한을 준다 |
| `429 Too Many Requests`, `toomanyrequests` | 레지스트리 요청 한도. Docker Hub 익명 풀은 IP마다 걸리는 경우가 많다 | 로그인해서 받거나, 풀스루 캐시를 쓰거나, 이미지를 미러링한다 |
| `i/o timeout`, `no such host` | 노드에서 본 네트워크, DNS, 프록시, 방화벽 문제 | 노드에서 `crictl pull` 등으로 시험하고 나가는 경로를 본다 |
| `x509: certificate signed by unknown authority` | 노드가 레지스트리 인증서를 믿지 않는다 | 노드나 런타임 레지스트리 설정에 CA를 넣는다 |

## 직접 확인해 보기

```bash
kubectl create secret docker-registry regcred -n shop \
  --docker-server=registry.example.com \
  --docker-username=robot-pull --docker-password="$TOKEN"         # 타입 kubernetes.io/dockerconfigjson
kubectl get secret regcred -n shop -o jsonpath='{.data.\.dockerconfigjson}' | base64 -d   # 서버 이름 확인
kubectl patch serviceaccount default -n shop \
  -p '{"imagePullSecrets":[{"name":"regcred"}]}'                  # 새 파드가 저절로 받는다
kubectl get pod web -n shop -o jsonpath='{.spec.imagePullSecrets}{"\n"}'   # 파드가 실제로 받은 것
kubectl describe pod web -n shop | grep -A8 Events                 # Failed 메시지를 읽는다
kubectl get events -A --field-selector reason=FailedToRetrieveImagePullSecret   # 네임스페이스에 시크릿이 없는 경우
```
