## 자주 보는 apply 오류

| 메시지(줄임) | 뜻 | 고치는 법 |
|---|---|---|
| `error converting YAML to JSON: yaml: line 7: ...` | 올바른 YAML이 아니다: 들여쓰기, 탭, 빠진 콜론 | 표시된 줄을 고친다. 들여쓰기는 공백만 쓴다 |
| `no matches for kind "Deployment" in version "extensions/v1beta1"` | 그 그룹/버전에 이 종류가 없거나, CRD가 설치되지 않았다 | `kubectl api-resources`로 맞는 짝을 찾는다. CRD를 먼저 설치한다 |
| `strict decoding error: unknown field "spec.replica"` | 오타, 또는 들여쓰기 수준이 틀린 필드 | `kubectl explain`으로 경로를 확인한다 |
| `cannot unmarshal string into Go struct field ... of type int32` | 타입이 틀렸다(예: `replicas: "3"`) | 따옴표를 빼거나 `kubectl explain`이 보여 주는 타입에 맞춘다 |
| `AlreadyExists` | 이미 있는 오브젝트에 `kubectl create`를 했다 | `kubectl apply`를 쓴다 |
| `field is immutable` | 만든 뒤에는 바꿀 수 없는 필드다(예: 디플로이먼트의 `spec.selector`) | 새 오브젝트를 만들거나 지우고 다시 만든다 |
| `namespaces "shop" not found` | 대상 네임스페이스가 아직 없다 | 네임스페이스를 먼저 만들거나 파일 앞쪽에 둔다 |
| `Apply failed with 1 conflict: conflict with "..."` | 서버 사이드 적용: 다른 필드 매니저가 그 필드를 가졌다 | 파일에서 그 필드를 빼거나 `--force-conflicts`로 가져온다 |

## 직접 확인해 보기

```bash
kubectl api-resources | grep -i deploy               # NAME, APIVERSION, NAMESPACED, KIND
kubectl explain deployment.spec.strategy             # 클러스터 스키마의 필드 타입과 뜻
kubectl explain deployment.spec --recursive | head -40
kubectl apply -f web.yaml --dry-run=server           # 검증과 어드미션을 모두 거치되 저장하지 않는다
kubectl diff -f web.yaml                             # apply가 바꿀 내용(종료 코드 1 = 차이 있음)
kubectl apply -f web.yaml
kubectl get deploy web -o yaml | grep -A3 last-applied   # 클라이언트 사이드 apply가 남긴 내 파일 기록
kubectl apply -f web.yaml --server-side
kubectl get deploy web -o yaml --show-managed-fields | grep -B2 -A8 managedFields   # 필드별 주인
```
