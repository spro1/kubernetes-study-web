# 답이 한 토큰씩 만들어지기까지

LLM은 답을 한 번에 쓰지 않는다. 질문을 **토큰**(모델이 읽는 글자 조각)으로 바꾸고, 다음에 올 토큰을 **하나** 고르고, 그 토큰을 붙여 다시 계산하는 일을 답이 끝날 때까지 반복한다. 채팅에서 답이 타자 치듯 조금씩 나오는 것도 이 때문이다.

## 쿠버네티스에서 운영할 때

- vLLM, KServe 같은 추론 서버는 대개 OpenAI 호환 API(`/v1/chat/completions` 등)로 이 생성 과정을 노출한다. 요청에 `stream: true`를 주면 토큰이 만들어지는 대로 SSE로 흘러나온다.
- 스트리밍이 한꺼번에 몰려 도착하거나 중간에 끊기면 앞단 인그레스나 게이트웨이를 먼저 본다. 응답 버퍼링이 켜져 있거나 읽기 타임아웃이 긴 답보다 짧으면 이런 일이 생긴다.
- vLLM은 `/metrics`로 입력 토큰 누적(`vllm:prompt_tokens_total`)과 출력 토큰 누적(`vllm:generation_tokens_total`)을 내보낸다. 두 값의 증가 속도를 나눠 보면 부하가 긴 질문에서 오는지 긴 답에서 오는지 알 수 있다.
- 답이 문장 중간에 끊긴다는 문의가 오면 클라이언트의 `max_tokens`와 서버의 최대 문맥 길이 설정부터 확인한다.
