# 모델을 여러 GPU에 나눠 싣기 (TP·PP·EP)

16비트 가중치로 된 70B 모델은 약 140GB다. 80GB GPU 한 장에는 가중치도, KV 캐시도 들어가지 않는다. 같은 모델을 **복사하고, 층을 가로로 쪼개고, 층 묶음을 세로로 나누고, 전문가를 흩어 놓으며** 각 방법이 GPU 사이에 무엇을 주고받는지 따라간다.

## 네 가지 나누기 비교

| 방식 | 무엇을 나누나 | GPU 사이 통신 | 어디에 맞나 |
|---|---|---|---|
| 데이터 병렬(DP) | 나누지 않음: 전체 사본 | 서빙 중 없음 | 사본 하나가 들어갈 때 처리량 늘리기 |
| 텐서 병렬(TP) | 모든 층 안의 행렬 | 스텝마다 층당 두 번쯤 all-reduce | 한 노드 안, NVLink 같은 링크 위 |
| 파이프라인 병렬(PP) | 층 묶음을 단계로 | 단계 경계마다 활성값, 일대일 | 노드 하나로 모자랄 때 노드 사이 |
| 전문가 병렬(EP) | MoE 전문가를 GPU마다 | MoE 층마다 all-to-all 토큰 라우팅 | MoE 모델, 어텐션은 DP나 TP와 함께 |

서로 섞어 쓴다. 큰 배포는 노드 안에서 TP, 노드 사이에서 PP, 그런 레플리카 여럿을 DP로 둔다.

## 직접 확인해 보기

```bash
nvidia-smi topo -m                                    # NV# = GPU 사이 NVLink, SYS/PHB = 느린 경로
vllm serve <모델> --tensor-parallel-size 4            # 예: vLLM. 한 노드, GPU 4장
vllm serve <모델> --tensor-parallel-size 4 \
  --pipeline-parallel-size 2                          # 노드 2대, GPU 8장 (Ray 같은 멀티 노드 런타임 필요)
vllm serve <MoE모델> --tensor-parallel-size 8 --enable-expert-parallel   # MoE 전문가를 GPU에 흩어 놓기
kubectl get leaderworkerset -A                        # 그룹과 그룹 크기
kubectl get pods -L leaderworkerset.sigs.k8s.io/worker-index   # 0 = 리더, 1부터 = 워커
```
