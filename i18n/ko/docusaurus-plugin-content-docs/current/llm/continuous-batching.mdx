# 요청을 묶어 처리하기 (연속 배칭)

가속기 한 장으로 수십 명이 동시에 쓸 수 있는 것은 **배칭(batching)** 덕분이다. 여러 요청을 한 묶음으로 계산하는 방법이다. 다만 묶는 방식에 따라 가속기가 놀기도 하고 꽉 차기도 한다. 요즘 엔진이 쓰는 **연속 배칭(continuous batching)** 이 무엇을 바꿨는지 따라가 본다.

## 쿠버네티스에서 볼 것

- 연속 배칭은 엔진 안에서 일어난다. 파드 수를 늘리기 전에 파드 하나가 감당하는 동시 요청 수부터 잰다. 동시 요청 수를 단계별로 올리며 처리량·TTFT·TPOT을 기록하면 꺾이는 지점이 보인다.
- 엔진이 내보내는 지표 중 실행 중인 요청 수와 대기 중인 요청 수를 함께 본다. vLLM이라면 `vllm:num_requests_running`, `vllm:num_requests_waiting`이다. 대기 수가 계속 0보다 크면 묶음이 이미 꽉 찼다는 뜻이다.
- 대기 요청 수는 가속기 사용률보다 확장 기준으로 쓰기 좋다. 디코드 중에는 사용률이 높게 찍혀도 여유가 있을 수 있다. HPA나 KEDA에 외부 지표로 연결해 레플리카 수를 조정할 수 있다.
- 최대 동시 요청 수를 올리면 처리량은 늘지만 KV 캐시가 부족해져 요청이 밀려날 수 있다. 설정을 바꾼 뒤에는 KV 캐시 사용률도 함께 확인한다.
