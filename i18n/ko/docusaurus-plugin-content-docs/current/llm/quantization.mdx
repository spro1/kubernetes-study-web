# 모델을 작게 만들기 (양자화)

**양자화**는 모델의 숫자를 더 적은 비트로 저장하는 것이다. 예를 들어 16비트 대신 8비트나 4비트를 쓴다. 그러면 가속기가 덜 필요하고, KV 캐시에 쓸 메모리가 늘고, 토큰이 더 빨리 나온다. 대신 정확도가 조금 떨어지고, 얼마나 떨어지는지는 직접 재야 한다.

## 정밀도와 가중치 크기

70B 모델의 가중치만 센 크기다. KV 캐시와 작업용 메모리는 따로 더 든다.

| 정밀도 | 파라미터당 바이트 | 70B 가중치 | 참고 |
|---|---|---|---|
| FP32 | 4 | ~280GB | 학습에 쓰고 서빙에는 안 쓴다 |
| BF16 / FP16 | 2 | ~140GB | 보통의 기준 체크포인트 |
| FP8 (W8A8) | 1 | ~70GB | Hopper·Ada·Blackwell의 FP8 텐서 코어. 대개 기준에 가까운 정확도 |
| INT8 (W8A8 또는 W8A16) | 1 | ~70GB | INT8 텐서 코어는 Ampere에도 있다. W8A8은 활성값 이상치를 다뤄야 한다(예: SmoothQuant) |
| INT4 (W4A16: AWQ, GPTQ) | 0.5 + 스케일 | ~35–40GB | 메모리 절약이 가장 크고 디코드가 빨라진다. 계산은 16비트. 정확도 위험이 더 크다 |
| FP4 (예: NVFP4, MXFP4) | 0.5 + 스케일 | ~35–40GB | Blackwell의 FP4 텐서 코어 |

## 쿠버네티스에서 운영할 때

- 양자화는 미리 한 번 해 두고, 결과를 모델 레지스트리에 별도 체크포인트로 두거나 OCI 아티팩트로 저장한다. 그러면 여느 모델과 똑같이 올리고, 체크포인트가 작아 콜드 스타트 때 내려받기도 빨라진다.
- 미리 양자화된 체크포인트는 대개 자기 형식을 적어 둔다(vLLM이라면 `config.json`의 `quantization_config`). 엔진이 플래그 없이도 맞는 커널을 고른다. `--quantization`은 방법을 강제하거나 올릴 때 바로 양자화하려 할 때만 준다.
- 형식을 Deployment의 노드 선택에 반영한다. FP8 모델을 FP8 텐서 코어가 없는 노드에 올리면 돌기는 하지만 계획한 속도는 안 나온다.
- 지표는 전과 같은 엔진 지표를 본다. KV 캐시 사용률, 대기 요청 수, TTFT와 TPOT이다. 양자화가 효과가 있다면 같은 부하에서 KV 캐시 사용률이 내려가거나, 레플리카 하나가 더 많은 요청을 받는다.

## 직접 해 보기

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ                       # 미리 양자화된 4비트 체크포인트. 방법은 config.json에서 읽는다
vllm serve <모델> --quantization fp8_per_tensor               # BF16 가중치를 올리면서 FP8로 양자화(예전 vLLM: fp8)
vllm serve <모델> --kv-cache-dtype fp8                        # KV 캐시를 FP8로. 가중치 정밀도와 따로
nvidia-smi --query-gpu=name,memory.used,memory.total --format=csv   # 예: NVIDIA. GPU 모델과 메모리
curl -s http://<엔진>:8000/metrics | grep -E 'vllm:(kv_cache_usage_perc|num_requests_running)'   # 같은 부하에서 KV 여유
```
