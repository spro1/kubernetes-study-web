# 미리 추측하고 한 번에 확인하기 (추측 디코딩)

디코드는 한 단계에 토큰 하나를 쓰고, 단계마다 모델 가중치 전체를 메모리에서 읽는다. **추측 디코딩(speculative decoding)** 은 값싼 *초안(draft)* 이 토큰 몇 개를 먼저 추측하게 하고, 큰 *목표(target)* 모델이 그 추측을 **한 번의** 계산으로 모두 확인하게 한다. 추측이 잘 맞으면 비싼 계산 한 번으로 토큰 여러 개를 얻고, 답은 이 기법을 쓰지 않을 때와 같다.

## 초안 방식 비교

| 방식 | 추측의 출처 | 추가 메모리 | 특히 잘 맞는 경우 |
|---|---|---|---|
| 초안 모델 | 토크나이저가 같은 별도의 작은 모델 | 그 모델의 가중치와 KV 캐시 | 좋은 작은 형제 모델이 있을 때, 일반 대화 |
| n-gram (프롬프트 조회) | 질문 앞부분에서 그대로 가져온 토큰 | 없음 | 출력이 입력을 반복할 때: 요약, 코드 수정, RAG 답변 |
| EAGLE 계열 헤드 | 목표 모델의 은닉 상태를 읽는 가벼운 층 | 작음 | 일반 업무. 보통 별도 초안보다 수락률이 높다 |
| MTP 모듈 | 모델과 함께 학습된 다중 토큰 예측 층 (예: DeepSeek-V3) | 작음. 체크포인트에 같이 들어 있는 경우가 많다 | MTP 가중치를 함께 배포하는 모델 |

어느 방식이든 최종 결정은 목표 모델이 내린다. 방식은 속도를 바꿀 뿐 답을 바꾸지 않는다.

## 쿠버네티스에서 운영할 때

- 추측 디코딩은 엔진을 띄울 때 정한다. 그래서 서빙 파드의 실행 인자에 들어간다. 다른 설정 변경처럼 카나리 레플리카로 배포한다.
- 실제 동시 요청 수에서 켰을 때와 껐을 때를 부하 테스트로 비교한다. TPOT, TTFT, 초당 전체 출력 토큰을 함께 본다. 사용자 1명일 때의 이득이 64명일 때는 손해일 수 있다.
- 초안 몫의 메모리 여유를 남긴다. 초안 모델은 자기 가중치와 KV 캐시를 더하므로 같은 가속기에 들어가는 요청 수가 줄어든다.
- 수락률을 계속 지켜본다. 트래픽이 창작이나 높은 temperature 요청 쪽으로 바뀌면 이득이 조용히 사라질 수 있다.

## 직접 해 보기

```bash
# vLLM: n-gram 초안은 모델이 더 필요 없다 (쓰는 버전의 추측 디코딩 문서를 확인한다)
vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --speculative-config '{"method": "ngram", "num_speculative_tokens": 4, "prompt_lookup_max": 4}'

# vLLM: 별도의 작은 초안 모델
vllm serve meta-llama/Llama-3.1-70B-Instruct \
  --speculative-config '{"model": "meta-llama/Llama-3.2-1B-Instruct", "num_speculative_tokens": 4}'

# 같은 동시 요청 수에서 추측 디코딩을 켰을 때와 껐을 때의 TPOT 비교
vllm bench serve --model meta-llama/Llama-3.1-8B-Instruct --max-concurrency 8 --num-prompts 200

# 수락률: 수락된 초안 토큰 / 제안된 초안 토큰
```
