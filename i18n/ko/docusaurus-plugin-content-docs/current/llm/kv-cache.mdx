# KV 캐시가 차오르기까지

**KV 캐시**는 모델이 앞에서 읽고 쓴 토큰의 계산 결과를 모아 둔 것이다. 이것 덕분에 답을 빠르게 이어 쓰지만, 대화가 길어지고 동시 요청이 많아질수록 가속기 메모리를 빠르게 채운다. 서빙에서 "몇 명까지 동시에 받을 수 있나"를 정하는 것이 대개 이 캐시다.

## 쿠버네티스에서 운영할 때

- `nvidia-smi`나 DCGM 익스포터의 GPU 메모리 사용률은 vLLM이 뜨자마자 높게 나온다. vLLM은 `--gpu-memory-utilization`(기본 0.9) 비율만큼 메모리를 잡고, 가중치를 뺀 나머지를 KV 캐시로 쓴다.
- 실제 여유는 vLLM `/metrics`의 KV 캐시 사용률(`vllm:kv_cache_usage_perc`, 이전 버전은 `vllm:gpu_cache_usage_perc`)로 본다. 대기 요청 수(`vllm:num_requests_waiting`)와 선점 횟수가 함께 오르면 캐시가 모자란 상태다.
- 캐시가 모자랄 때 손볼 곳은 `--max-model-len`(요청 하나의 최대 길이), `--max-num-seqs`(동시 처리 요청 수), 레플리카 수, 더 큰 메모리의 가속기다. HPA로 레플리카를 늘린다면 GPU 사용률 대신 대기 요청 수나 KV 캐시 사용률 같은 엔진 지표를 기준으로 삼는 편이 맞다.
- 프리픽스 캐시 효과는 같은 앞부분을 가진 요청이 같은 레플리카로 갈 때 커진다. 이 내용은 [요청을 어느 레플리카로 보낼까 (추론 라우팅)](../ai/inference-routing.mdx)에서 다룬다. 넘치는 캐시를 CPU 메모리나 디스크로 내리는 방법은 [넘치는 KV 캐시 내려 두기 (오프로딩)](../llm/kv-offloading.mdx)에서 본다.
