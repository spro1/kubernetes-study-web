# kubeadm으로 클러스터 업그레이드 (CKA)

CKA의 Cluster Architecture, Installation and Configuration(25%) 영역 중 "클러스터 생명주기 관리(업그레이드)"와 관련 있다. kubeadm(쿠버네티스 공식 설치 도구)으로 만든 1.36 클러스터를 1.37로 올리며, 노드마다 어떤 명령을 어떤 순서로 치는지 따라가 본다.

왜 컨트롤 플레인을 먼저 올리는지, drain이 PDB를 어떻게 지키는지는 [노드 비우기와 클러스터 업그레이드](../k8s/node-drain.mdx)에서 다룬다. 여기서는 kubeadm 명령의 순서에 집중한다.

## 시험에서 자주 묻는 것

| 상황 | 해야 할 일·명령 | 함정 |
| --- | --- | --- |
| 컨트롤 플레인을 한 버전 올려라 | 저장소 주소 변경 → kubeadm 설치 → `kubeadm upgrade plan` → `kubeadm upgrade apply v1.37.x` | 마이너 버전을 건너뛸 수 없다. 저장소 주소가 옛 버전이면 새 패키지가 안 보인다 |
| 두 번째 컨트롤 플레인 노드 | `kubeadm upgrade node` | `upgrade apply`는 첫 노드에서 한 번만 친다 |
| apply가 끝났는데 노드 버전이 그대로다 | kubelet·kubectl 설치 → `systemctl daemon-reload` → `systemctl restart kubelet` | `kubectl get nodes`의 VERSION은 kubelet 버전이다 |
| 워커 노드를 올려라 | kubeadm 설치 → `kubeadm upgrade node` → `kubectl drain <노드> --ignore-daemonsets` → kubelet 설치·재시작 → `kubectl uncordon <노드>` | 워커에서 `upgrade apply`를 치지 않는다. drain은 kubectl이 있는 곳에서, 패키지 설치는 그 노드에서 한다 |
| 작업이 끝났다 | `kubectl uncordon`, `kubectl get nodes`로 Ready·VERSION 확인 | uncordon을 빼먹으면 노드가 SchedulingDisabled로 남는다 |

## 직접 확인해 보기

```bash
kubectl get nodes                                    # VERSION = 노드별 kubelet 버전
apt-cache madison kubeadm                            # 지금 저장소에 있는 버전
kubeadm version                                      # kubeadm을 먼저 올렸는지
sudo kubeadm upgrade plan                            # 구성 요소 버전, 아무것도 바꾸지 않는다
sudo kubeadm certs check-expiration                  # apply가 갱신한 인증서
kubelet --version                                    # 이 노드의 kubelet
```
