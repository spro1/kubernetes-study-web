# 노드 NotReady와 구성요소 장애 (CKA)

CKA의 Troubleshooting(30%) 영역 중 "클러스터·노드"와 "클러스터 구성요소" 문제 해결과 관련 있다. 워커 노드 하나가 NotReady가 된 장면과, 컨트롤 플레인의 API 서버가 죽어 kubectl조차 듣지 않는 장면을 차례로 풀어 본다.

노드가 멈췄을 때 파드가 다른 노드에서 다시 만들어지는 과정은 [파드가 죽으면 (자가 치유)](../k8s/self-healing.mdx)에서, 인증서 만료로 통신이 끊기는 과정은 [클러스터 인증서 만료](../advanced/cluster-cert.mdx)에서 다룬다. 여기서는 노드에 들어가 원인을 찾는 순서에 집중한다.

## 시험에서 자주 묻는 것

| 상황 | 해야 할 일·명령 | 함정 |
| --- | --- | --- |
| 노드가 NotReady다 | `kubectl describe node <노드>` → `ssh <노드>` → `systemctl status kubelet` → `journalctl -u kubelet` | 컨트롤 플레인 노드에서 로그를 보면 안 된다. 문제 노드에 들어가야 한다 |
| kubelet이 꺼져 있다 | `systemctl start kubelet`, `systemctl enable kubelet` | enable을 빼먹으면 재부팅 뒤 다시 NotReady가 된다 |
| kubelet 설정 파일을 고쳤다 | `systemctl daemon-reload` → `systemctl restart kubelet` | 고치기만 하고 재시작하지 않으면 반영되지 않는다 |
| kubectl이 connection refused다 | 컨트롤 플레인 노드에서 `crictl ps -a`, `crictl logs <컨테이너ID>` | `kubectl logs`는 API 서버가 있어야 동작한다 |
| 정적 파드 설정이 틀렸다 | `/etc/kubernetes/manifests/` 아래 파일을 직접 수정 | `kubectl edit`·`kubectl delete`로는 고칠 수 없다. 파일을 고쳐야 kubelet이 다시 만든다 |
