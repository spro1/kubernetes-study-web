# CIS 쿠버네티스 벤치마크와 kube-bench (CKS)

CKS의 Cluster Setup 영역 중 "CIS 벤치마크로 쿠버네티스 구성요소의 보안 설정 점검"에 해당한다. kubeadm 클러스터에서 kube-bench를 돌리고, 무엇이 실패했는지 읽고, 알맞은 파일에서 고친 뒤 다시 돌린다.

## kubeadm 클러스터에서 흔한 지적 사항

아래 ID는 kube-bench의 `cis-2.0` 설정 기준이다. 벤치마크 버전에 따라 번호가 바뀔 수 있으니 문구로도 맞춰 본다.

| ID | 항목 | 고칠 곳 | 조치 |
|---|---|---|---|
| 1.1.1 | API 서버 매니페스트 권한 600 이하 | `/etc/kubernetes/manifests/kube-apiserver.yaml` | `chmod 600` |
| 1.2.6 | `--authorization-mode`가 `AlwaysAllow`가 아님 | API 서버 매니페스트 | `--authorization-mode=Node,RBAC` |
| 1.2.15 | `--profiling=false` | API 서버 매니페스트 | `--profiling=false` 추가 (컨트롤러 매니저 1.3.2, 스케줄러 1.4.1도) |
| 1.2.16 | `--audit-log-path` 설정 | API 서버 매니페스트 | 정책 파일, 로그 경로, hostPath 볼륨과 마운트 |
| 4.2.1 | kubelet 익명 인증 끔 | `/var/lib/kubelet/config.yaml` | `authentication.anonymous.enabled: false`, kubelet 재시작 |
| 4.2.2 | kubelet 인가가 `AlwaysAllow`가 아님 | `/var/lib/kubelet/config.yaml` | `authorization.mode: Webhook`, kubelet 재시작 |

| 결과 | 뜻 | 할 일 |
|---|---|---|
| `[PASS]` | 점검이 돌았고 통과 | 없음 |
| `[FAIL]` | 점검이 돌았고 실패(또는 Scored 항목을 돌리지 못함) | 조치를 적용하고 다시 돌린다 |
| `[WARN]` | 살펴봐야 함, 보통 수동 항목 | 조치 문구를 읽고 직접 판단한다 |
| `[INFO]` | 참고용이거나 건너뛴 항목 | 없음 |

```bash
kubectl apply -f https://raw.githubusercontent.com/aquasecurity/kube-bench/main/job-master.yaml
kubectl wait --for=condition=complete job/kube-bench-master --timeout=120s
kubectl logs job/kube-bench-master | grep '^\[FAIL\]'                 # 실패한 항목
kubectl logs job/kube-bench-master | grep -A4 '^== Summary'            # PASS/FAIL/WARN/INFO 개수

# 워커 점검
kubectl apply -f https://raw.githubusercontent.com/aquasecurity/kube-bench/main/job-node.yaml
kubectl logs job/kube-bench-node | grep -A3 '4.2.1'

# 컨트롤 플레인 노드에서 고치기
sudo cp /etc/kubernetes/manifests/kube-apiserver.yaml /root/kube-apiserver.yaml.bak   # 백업은 manifests/ 밖에
sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml                                 # 예: --profiling=false 추가
sudo crictl ps --name kube-apiserver                                                  # 새 컨테이너가 뜰 때까지 기다린다

# 다시 돌리기
kubectl delete job kube-bench-master && kubectl apply -f https://raw.githubusercontent.com/aquasecurity/kube-bench/main/job-master.yaml
```
