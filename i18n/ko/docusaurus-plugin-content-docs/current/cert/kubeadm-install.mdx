# kubeadm으로 클러스터 만들기 (CKA)

CKA의 Cluster Architecture, Installation and Configuration 영역 중 "클러스터 설치를 위한 기반 준비"와 "kubeadm으로 클러스터 만들고 관리하기"에 해당한다. 빈 리눅스 머신 두 대를 v1.37 클러스터로 만들며, 단계마다 디스크와 클러스터에 무엇이 생기는지 본다.

이미 있는 클러스터의 버전을 올리는 법은 [kubeadm으로 클러스터 업그레이드 (CKA)](./kubeadm-upgrade.mdx)에, kubeadm이 만든 인증서가 만료되면 생기는 일은 [클러스터 인증서 만료](../advanced/cluster-cert.mdx)에 있다.

## 단계마다 남기는 것

| 단계 (kubeadm init) | 하는 일 | 확인할 곳 |
|---|---|---|
| preflight | 스왑, 포트, 런타임, sysctl, 권한 점검 | 오류 문구. `--ignore-preflight-errors`는 이유를 알 때만 |
| certs | 클러스터 CA, API 서버·etcd·front-proxy 인증서 | `/etc/kubernetes/pki/`, `kubeadm certs check-expiration` |
| kubeconfig | admin, super-admin, kubelet, controller-manager, scheduler용 kubeconfig | `/etc/kubernetes/*.conf` |
| etcd · control-plane | 정적 파드 매니페스트 | `/etc/kubernetes/manifests/` |
| kubelet-start | kubelet 설정을 쓰고 시작 | `/var/lib/kubelet/config.yaml`, `journalctl -u kubelet` |
| upload-config | kubeadm·kubelet 설정을 컨피그맵으로 | `kubectl -n kube-system get cm kubeadm-config kubelet-config` |
| upload-certs (`--upload-certs`일 때) | 암호화한 컨트롤 플레인 인증서, 2시간 뒤 삭제 | kube-system의 시크릿 `kubeadm-certs` |
| mark-control-plane | 노드에 레이블과 `NoSchedule` 테인트 | `kubectl describe node cp-1` |
| bootstrap-token | 조인 토큰, 기본 TTL 24시간 | `kubeadm token list` |
| addon | CoreDNS와 kube-proxy | `kubectl -n kube-system get pods` |

| 증상 | 그럴듯한 원인 | 고치는 법 |
|---|---|---|
| preflight가 스왑을 경고하거나 kubelet이 뜨지 않는다 | 스왑이 켜져 있고 `failSwapOn`이 true(기본값) | `swapoff -a` 하고 `/etc/fstab`에서 지우거나 `failSwapOn: false` |
| preflight: `/proc/sys/net/ipv4/ip_forward`가 1이 아님 | IP 포워딩 꺼짐 | `net.ipv4.ip_forward = 1`을 넣고 `sysctl --system` |
| init 뒤 컨트롤 플레인 파드가 계속 재시작 | kubelet과 런타임의 cgroup 드라이버가 다름 | containerd에 `SystemdCgroup = true`, 재시작 |
| 노드 NotReady, CoreDNS Pending | CNI 없음 | 파드 네트워크 애드온을 하나 깐다 |
| join: 토큰이 없거나 만료 | 토큰이 TTL을 넘김 | `kubeadm token create --print-join-command` |
| 컨트롤 플레인 join이 인증서를 못 찾음 | `kubeadm-certs` 시크릿 만료 | `kubeadm init phase upload-certs --upload-certs` |

## 직접 확인해 보기

```bash
# 모든 노드: 준비
sudo swapoff -a                                       # /etc/fstab에서도 스왑을 지운다
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.ipv4.ip_forward = 1
EOF
sudo sysctl --system && sysctl net.ipv4.ip_forward    # 1이 나와야 한다
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml   # 버전에 따라 키가 있는지 확인
sudo systemctl restart containerd

# 모든 노드: pkgs.k8s.io에서 패키지 설치 (v1.37)
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
sudo apt-get update && sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

# cp-1: init (CIDR은 CNI에 따라 다르다)
sudo kubeadm init --pod-network-cidr 192.168.0.0/16
mkdir -p $HOME/.kube && sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config && sudo chown $(id -u):$(id -g) $HOME/.kube/config
kubectl get nodes                                     # CNI를 깔기 전까지 NotReady
ls /etc/kubernetes/manifests                          # etcd, kube-apiserver, ...

# 나중에: 새 join 명령과 토큰 목록
sudo kubeadm token create --print-join-command
sudo kubeadm token list
```
