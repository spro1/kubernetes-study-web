# 샌드박스 컨테이너 런타임 — gVisor, Kata, RuntimeClass (CKS)

CKS의 Minimize Microservice Vulnerabilities 영역 중 "격리 기법 이해와 적용(멀티 테넌시, 샌드박스 컨테이너 등)"에 해당한다. 믿을 수 없는 파드 하나를 일반 런타임에서 돌려 왜 위험한지 보고, RuntimeClass로 샌드박스에 옮긴다.

네임스페이스와 cgroup이 컨테이너를 격리하는 방식은 [리눅스는 컨테이너를 어떻게 격리하나](../basic/linux-isolation.mdx)에, seccomp·AppArmor·Falco는 [런타임 보안 — 이상 행동 잡기 (CKS)](./runtime-security.mdx)에 있다. 여기서는 커널 자체를 더는 공유하지 않을 때 무엇이 달라지는지 본다.

## runc, gVisor, Kata 비교

| | runc (기본) | gVisor (runsc) | Kata Containers |
|---|---|---|---|
| 앱이 이야기하는 커널 | 호스트 커널 | 사용자 공간 커널 Sentry | VM 안의 게스트 커널 |
| 호스트와 가르는 것 | 네임스페이스, cgroup, seccomp, AppArmor | Sentry와 걸러 낸 적은 수의 호스트 시스템 콜 | 하드웨어 가상화 |
| 흔한 containerd `runtime_type` | `io.containerd.runc.v2` | `io.containerd.runsc.v1` | `io.containerd.kata.v2` |
| 노드에 필요한 것 | 따로 없음 | runsc 설치 | 가상화 지원(KVM, 중첩 또는 베어메탈) |
| 비용 | 가장 적음 | 느린 시스템 콜과 I/O, 지원 안 되는 시스템 콜 | 파드마다 VM 시작 시간과 메모리 |
| 어울리는 곳 | 믿을 수 있는 워크로드 | I/O가 많지 않은 믿을 수 없는 코드 | 온전한 리눅스 동작이 필요한 믿을 수 없는·멀티 테넌트 워크로드 |

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| `FailedCreatePodSandBox`: no runtime for "runsc" is configured | 노드에 그 이름의 핸들러가 없다 | 런타임을 깔고 설정하거나 `scheduling.nodeSelector`를 쓴다 |
| 만들 때 파드가 거부됨(conflict) | RuntimeClass의 nodeSelector와 파드의 nodeSelector가 충돌 | 레이블을 맞춘다 |
| 파드 거부: RuntimeClass not found | `runtimeClassName`이 틀렸다 | `kubectl get runtimeclass`로 이름을 고친다 |
| 샌드박스 파드가 많아지면 노드 메모리가 바닥 | `overhead`를 안 적었다 | RuntimeClass에 `overhead.podFixed`를 적는다 |
| 샌드박스에서만 앱 오류 | 지원 안 되는 시스템 콜이나 커널 기능 | 샌드박스에서 시험하거나 그 앱은 runc에 둔다 |

## 직접 확인해 보기

```bash
# 노드에서: 핸들러가 설정돼 있는가?
grep -n 'runtimes.runsc\|runtimes.kata' /etc/containerd/config.toml

# 레이블 단 노드에만 가는 RuntimeClass
kubectl label node worker-1 sandbox=gvisor
cat <<EOF | kubectl apply -f -
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata:
  name: gvisor
handler: runsc
scheduling:
  nodeSelector:
    sandbox: gvisor
EOF
kubectl get runtimeclass

# 그것을 쓰는 파드
kubectl run sandboxed --image=busybox:1.36 --restart=Never \
  --overrides='{"spec":{"runtimeClassName":"gvisor"}}' -- sleep 3600
kubectl get pod sandboxed -o wide                     # NODE가 worker-1이어야 한다
kubectl exec sandboxed -- dmesg                       # gVisor는 자기 부팅 메시지를 보여 준다
kubectl describe pod sandboxed | grep -A5 Events      # 핸들러가 없으면 FailedCreatePodSandBox
```
