# 블루/그린과 카나리를 기본 요소로 (CKAD)

CKAD의 Application Deployment(20%) 영역 중 "쿠버네티스 기본 요소로 배포 전략(블루/그린, 카나리) 쓰기"와 관련 있다. 서비스 메시 같은 추가 도구 없이 디플로이먼트·서비스·레이블만으로 web 1.0을 2.0으로 바꾸는 두 가지 방법을 따라가 본다.

디플로이먼트 하나가 파드를 하나씩 바꾸는 기본 방식은 [무중단 배포 (롤링 업데이트)](../k8s/rolling-update.mdx)에서, 메시로 파드 수와 상관없이 비율을 나누는 방식은 [서비스 메시 ② 트래픽 나누기](../feature/mesh-traffic.mdx)에서 다룬다.

## 시험에서 자주 묻는 것

| 상황 | 해야 할 일·명령 | 함정 |
| --- | --- | --- |
| 블루에서 그린으로 전환하라 | 그린 디플로이먼트 생성 → `kubectl edit svc web`(또는 `kubectl patch`)로 selector의 version 변경 | 그린 파드의 레이블이 새 셀렉터와 정확히 맞아야 한다. 틀리면 엔드포인트가 비어 요청이 실패한다 |
| 전환이 됐는지 확인하라 | `kubectl get endpoints web` 또는 `kubectl describe svc web` | 디플로이먼트만 보고 판단하지 않는다. 서비스가 실제로 고른 파드 주소를 본다 |
| 요청의 약 20%만 새 버전으로 보내라 | 기존 4개 + 카나리 1개처럼 레플리카 수를 맞추고 둘 다 셀렉터 레이블을 갖게 한다 | 셀렉터에 version을 남겨 두면 카나리 파드가 요청을 받지 못한다 |
| 카나리를 되돌려라 | `kubectl scale deployment <카나리> --replicas=0` | 기존 디플로이먼트를 고치거나 롤백할 필요는 없다 |
| 디플로이먼트 하나에서 이전 버전으로 | `kubectl rollout undo deployment <이름>` | 이것은 롤링 업데이트의 되돌리기다. 블루/그린·카나리의 되돌리기와 다르다 |
