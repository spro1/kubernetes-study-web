# Kustomize로 환경별 배포 (CKA·CKAD)

CKA의 Cluster Architecture, Installation and Configuration(25%) 영역 중 "Helm·Kustomize로 클러스터 구성요소 설치", CKAD의 Application Deployment(20%) 영역 중 "Kustomize"와 관련 있다. 같은 web 앱을 개발 환경엔 1개, 운영 환경엔 3개로 배포하면서 파일을 복사하지 않고 차이만 적는 방법을 따라가 본다.

Helm 차트·values·리비전과 GitOps 동기화는 [Helm과 GitOps](../intermediate/gitops-sync.mdx)에서 다룬다. 여기서는 Kustomize의 덧씌우기 방식에 집중한다.

## 시험에서 자주 묻는 것

| 상황 | 해야 할 일·명령 | 함정 |
| --- | --- | --- |
| overlay를 적용하라 | `kubectl apply -k overlays/prod` | `-f` 대신 `-k`를 쓴다. 파일이 아니라 kustomization.yaml이 있는 폴더를 준다 |
| 적용 전에 결과를 확인하라 | `kubectl kustomize overlays/prod` | 이 명령은 화면에 찍기만 하고 클러스터에는 적용하지 않는다 |
| overlay에서 base를 가져와라 | `resources:`에 `../../base` 같은 상대 경로 | 경로는 kustomization.yaml이 있는 폴더 기준이다 |
| 이미지 태그만 바꿔라 | `images:`에 `name`·`newTag` | base의 deployment.yaml을 직접 고치면 다른 환경도 바뀐다 |
| 레플리카 등 일부 필드만 바꿔라 | 바꿀 필드만 담은 패치 파일을 `patches:`에 건다 | 패치의 kind·name이 base 자원과 맞아야 겹쳐진다 |
| Kustomize로 배포한 것을 지워라 | `kubectl delete -k overlays/prod` | Helm처럼 `uninstall`·`rollback` 명령이 따로 없다 |

## 직접 확인해 보기

```bash
kubectl kustomize overlays/prod                      # 합친 YAML, 클러스터엔 안 보낸다
kubectl kustomize overlays/prod | grep -E 'replicas|image:'   # 패치와 새 태그가 들어갔는지
kubectl kustomize overlays/dev | grep -E 'name: dev-|namespace:'   # namePrefix와 namespace
kubectl diff -k overlays/prod                        # apply -k가 바꿀 내용
```
