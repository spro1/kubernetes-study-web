# 멀티 컨테이너 파드 — init과 사이드카 (CKAD)

CKAD 출제 영역 중 Application Design and Build(20%)의 "멀티 컨테이너 파드 패턴(사이드카, init 등)"과 "영구·임시 볼륨"에 해당한다. 한 파드 안의 여러 컨테이너가 어떤 순서로 시작하고, 무엇을 함께 쓰는지 따라가 본다. 서비스 메시 프록시처럼 자동으로 들어가는 사이드카는 [서비스 메시 ① 사이드카와 상호 인증](../feature/mesh-sidecar.mdx)에서 따로 본다.

## 시험에서 자주 묻는 것

| 상황 | 해야 할 일·명령 | 함정 |
| --- | --- | --- |
| 파드가 `Init:CrashLoopBackOff` | `kubectl describe pod web`으로 어느 init이 실패했는지 보고 `kubectl logs web -c <init 이름>` | 앱 컨테이너는 시작 전이라 로그가 없다 |
| 앱보다 먼저 DB를 기다려야 한다 | `initContainers`에 대기용 컨테이너를 넣는다 | `containers`에 넣으면 앱과 동시에 시작된다 |
| 로그 수집 사이드카 추가 | `emptyDir` 볼륨을 선언하고 두 컨테이너 모두 `volumeMounts`로 붙인다 | 한쪽에만 마운트하면 파일이 보이지 않는다 |
| 사이드카가 앱보다 먼저 떠야 한다 | `initContainers`에 넣고 `restartPolicy: Always` | `containers`에 넣으면 시작 순서를 보장하지 않는다 |
| 두 컨테이너가 같은 포트를 연다 | 한쪽 포트를 바꾼다 | 같은 파드는 IP 하나를 함께 써서 포트가 겹친다 |

## 직접 확인해 보기

```bash
kubectl get pod web                                  # Init:0/2 같은 STATUS
kubectl get pod web -o jsonpath='{.spec.initContainers[*].restartPolicy}'   # Always면 네이티브 사이드카
kubectl describe pod web                             # 컨테이너별 상태와 마운트
kubectl logs web -c init-2                           # init 컨테이너가 실패한 이유
kubectl logs web -c log-agent                        # 사이드카 로그
```
