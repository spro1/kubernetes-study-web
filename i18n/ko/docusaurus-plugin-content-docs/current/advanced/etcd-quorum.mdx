## etcd 대수와 견딜 수 있는 고장

| etcd 대수 | 쿼럼(과반) | 견딜 수 있는 고장 대수 |
| --- | --- | --- |
| 1 | 1 | 0 |
| 2 | 2 | **0** |
| 3 | 2 | 1 |
| 4 | 3 | **1** |
| 5 | 3 | 2 |

## 직접 확인해 보기

```bash
kubectl get pods -n kube-system -l component=etcd -o wide   # 컨트롤 플레인 노드마다 etcd 하나
kubectl get --raw='/readyz?verbose' | grep etcd             # API 서버가 etcd에 닿는지
export ETCDCTL_ENDPOINTS=<엔드포인트> ETCDCTL_CACERT=<CA-인증서> ETCDCTL_CERT=<클라이언트-인증서> ETCDCTL_KEY=<클라이언트-키>   # 인증서 옵션을 한 번만 지정한다
etcdctl endpoint status --cluster -w table                  # 리더가 누구인지, Raft term과 index
etcdctl endpoint health --cluster -w table                  # 살아 있는 멤버: 과반이 되는지
```
