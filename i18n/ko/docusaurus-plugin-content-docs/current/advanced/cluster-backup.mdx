# 클러스터 백업과 복구

클러스터의 상태는 여러 곳에 나뉘어 있고, 곳마다 다른 백업이 필요하다. **etcd 스냅숏**과 **Velero 백업**이 원본 클러스터에서 오브젝트 스토리지로 갔다가 새 클러스터로 돌아오는 길을 따라간다.

## 방법마다 담는 것

| 방법 | API 오브젝트 | 볼륨 데이터 | 범위 | 알맞은 상황 |
|---|---|---|---|---|
| etcd 스냅숏 | 전부, 한 순간 | 없음 | 클러스터 전체 | 컨트롤 플레인을 잃었을 때 |
| Velero(오브젝트만) | 고른 네임스페이스·레이블 | 없음 | 네임스페이스, 레이블 | 지워진 리소스, 클러스터 이전 |
| Velero + CSI 스냅숏 | 있음 | 있음, 같은 스토리지 시스템 안 | 네임스페이스 | 같은 리전 안의 빠른 복구 |
| Velero + 데이터 무버 또는 파일 시스템 백업 | 있음 | 있음, 버킷으로 복사 | 네임스페이스 | 다른 리전·다른 클러스터로 복구 |
| 데이터베이스 덤프·복제 | 없음 | 그 데이터베이스만, 일관성 있게 | 데이터베이스 하나 | 데이터베이스, 특정 시점 복구 |
| Git(GitOps) | 직접 쓴 매니페스트 | 없음 | 저장소에 있는 것 | 설정 재구성, 데이터는 아님 |

## 직접 확인해 보기

```bash
# etcd 스냅숏 (kubeadm 경로, 컨트롤 플레인 노드에서 실행)
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /backup/snapshot.db
etcdutl --write-out=table snapshot status /backup/snapshot.db   # 해시, 리비전, 키 수, 크기

# Velero
velero backup create shop-test --include-namespaces shop --wait
velero backup describe shop-test --details        # 오브젝트, 볼륨 스냅숏, 경고
velero backup logs shop-test | grep -i error
velero restore create --from-backup shop-test --namespace-mappings shop:shop-restore-test   # 원본 옆에 복구해 보기
velero restore describe <restore-name>            # 건너뛴 항목과 실패한 항목
```
