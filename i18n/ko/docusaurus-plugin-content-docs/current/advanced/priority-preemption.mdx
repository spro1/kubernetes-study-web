# 우선순위와 선점

노드가 가득 차서 자리가 없으면 새 파드는 보통 Pending으로 기다린다([파드를 어느 노드에 둘까 (스케줄링)](../k8s/scheduling.mdx)). 그런데 기다리면 안 되는 중요한 파드라면 어떻게 될까. 자원이 모자랄 때 **누구를 먼저 살릴지** 정하는 우선순위와 선점을 따라가 본다.

## 드레인과 선점 비교

| 구분 | 드레인(노드 비우기) | 선점 |
| --- | --- | --- |
| 누가 시작하나 | 운영자 | 스케줄러 |
| 왜 하나 | 노드 정비·업그레이드 | 우선순위 높은 파드의 자리 만들기 |
| PDB를 어기면 | 거절하고 기다린다 | 다른 방법이 없으면 어기고 진행한다 |
| 밀려난 파드 | 다른 노드에서 새로 만들어진다 | 컨트롤러가 다시 만들지만 자리가 없으면 Pending |

드레인과 PDB의 자세한 흐름은 [노드 비우기와 클러스터 업그레이드](../k8s/node-drain.mdx)에서 본다.

## 직접 확인해 보기

```bash
kubectl get priorityclasses                                       # 등급과 값, system-* 포함
kubectl get pods -A -o custom-columns=NAME:.metadata.name,CLASS:.spec.priorityClassName,PRIORITY:.spec.priority   # 파드마다 쓰는 등급
kubectl get events -A --field-selector reason=Preempted           # 선점으로 밀려난 파드
kubectl get pod <파드> -o jsonpath='{.status.nominatedNodeName}'   # 기다리는 파드가 들어갈 노드
kubectl get pdb -A                                                # 중단 예산(최선으로만 지켜진다)
```
