# 클러스터 여러 개를 한 무리로 운영하기

클러스터는 언젠가 하나에서 여럿이 된다. 작은 플릿(fleet, 클러스터 무리)이 커 가는 과정을 따라간다. **Git → Argo CD → 클러스터들**, **Cluster API**로 만든 새 클러스터, 클러스터끼리 나눠 쓰는 서비스, 그리고 시간이 지나며 쌓이는 설정 차이와 버전 차이를 본다.

## 멀티 클러스터 구성 요소

| 필요한 것 | 방법 | 도구 예 | 조심할 점 |
|---|---|---|---|
| 모든 클러스터에 같은 앱 | 클러스터별 제너레이터를 쓰는 GitOps | Argo CD ApplicationSet, Flux | 클러스터별 덮어쓰기가 쌓여 모든 클러스터가 특별해지는 것 |
| 클러스터 만들기와 업그레이드 | 선언적 클러스터 수명 주기 | Cluster API, Terraform, 매니지드 서비스 | 업그레이드 중 Machine 교체에는 여유 용량과 PodDisruptionBudget이 필요하다 |
| 다른 클러스터의 서비스 찾기 | 멀티 클러스터 서비스 API | GKE 멀티 클러스터 서비스, Submariner | 이름이 같은 네임스페이스는 모든 클러스터에서 주인이 같아야 한다 |
| 사용자를 건강한 클러스터로 | 글로벌 로드밸런싱 | 헬스 체크를 붙인 DNS, 애니캐스트 로드밸런서 | DNS TTL만큼 전환이 늦다 |
| 클러스터 사이 mTLS와 장애 전환 | 멀티 클러스터 메시 | Istio 멀티 프라이머리, Linkerd multicluster, Cilium Cluster Mesh | 공용 루트 CA와 클러스터 사이 네트워크 연결 |
| 어디서 무엇이 도는지 알기 | 플릿 목록 | Argo CD 클러스터 목록, Cluster API 상태, 클라우드 콘솔 | 쿠버네티스와 애드온의 버전 차이 |

## 직접 확인해 보기

```bash
kubectl config get-contexts                                    # 이 kubeconfig가 아는 클러스터
argocd cluster list                                            # Argo CD에 등록된 클러스터
kubectl get secret -n argocd -l argocd.argoproj.io/secret-type=cluster --show-labels   # 제너레이터가 고르는 레이블
kubectl get applicationset -n argocd                           # 플릿 전체용 앱 정의
kubectl get applications -n argocd                             # 클러스터마다 하나: SYNC STATUS와 HEALTH
kubectl get clusters,machinedeployments -A                     # 관리 클러스터에서 (Cluster API)
clusterctl describe cluster prod-c -n fleet                    # 컨트롤 플레인과 머신 준비 상태
clusterctl get kubeconfig prod-c -n fleet > prod-c.kubeconfig  # 새 클러스터 접속 정보
kubectl get serviceexport,serviceimport -n shop                # 멀티 클러스터 서비스 객체
for ctx in prod-a prod-b prod-c; do                            # 플릿의 버전 차이
  echo "$ctx $(kubectl --context "$ctx" version -o json | jq -r .serverVersion.gitVersion)"
done
```
