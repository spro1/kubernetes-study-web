# 쿠버네티스 카오스 엔지니어링

## 실험별로 흔히 드러나는 것

| 실험 | Chaos Mesh | LitmusChaos 장애 | 흔한 발견 | 고칠 것 |
|---|---|---|---|---|
| 파드 죽이기 | PodChaos `pod-kill` | `pod-delete` | 처리 중 요청 실패, 느린 시작 | 백오프 재시도, readiness 프로브, 우아한 종료 |
| 지연 주입 | NetworkChaos `delay` | `pod-network-latency` | 느림이 호출자에게 번짐 | 타임아웃, 서킷 브레이커 |
| 패킷 손실 | NetworkChaos `loss` | `pod-network-loss` | 오래 멈춤, 재시도 폭주 | 타임아웃, 재시도 예산 |
| 노드 비우기 | (`kubectl drain` 사용) | `node-drain` | 복제본이 한 노드에 몰림, 퇴출 공백 | PodDisruptionBudget, 토폴로지 분산 |
| 존 잃기 | NetworkChaos 분할, 클라우드 카오스 | 클라우드 장애 | 남은 용량 부족 | 존별 여유 용량, 오토스케일러 한도 |
| CPU 부하 | StressChaos `cpu` | `pod-cpu-hog` | 스로틀링, 늦은 확장 | requests와 limits, HPA 조정 |

## 직접 확인해 보기

```bash
# Chaos Mesh 설치 (containerd 런타임), 전용 네임스페이스에
helm repo add chaos-mesh https://charts.chaos-mesh.org
helm install chaos-mesh chaos-mesh/chaos-mesh -n chaos-mesh --create-namespace \
  --set chaosDaemon.runtime=containerd \
  --set chaosDaemon.socketPath=/run/containerd/containerd.sock

# 실험 전: 복제본, 분산, PDB 확인
kubectl get pods -n staging -l app=cart -o wide
kubectl get pdb -n staging

# cart 파드 하나 죽이기
cat <<'EOF' | kubectl apply -f -
apiVersion: chaos-mesh.org/v1alpha1
kind: PodChaos
metadata:
  name: kill-one-cart
  namespace: staging
spec:
  action: pod-kill
  mode: one
  selector:
    namespaces: [staging]
    labelSelectors:
      app: cart
EOF
kubectl get pods -n staging -l app=cart -w     # 대체 파드가 뜨는 것을 지켜본다

# cart 파드 하나에 2분 동안 500ms 지연 주기
cat <<'EOF' | kubectl apply -f -
apiVersion: chaos-mesh.org/v1alpha1
kind: NetworkChaos
metadata:
  name: cart-delay
  namespace: staging
spec:
  action: delay
  mode: one
  selector:
    namespaces: [staging]
    labelSelectors:
      app: cart
  delay:
    latency: '500ms'
  duration: '2m'
EOF

# 실험을 일찍 멈추기
kubectl delete podchaos kill-one-cart -n staging
kubectl delete networkchaos cart-delay -n staging
```
