# CEL과 웹훅으로 거는 어드미션 정책

파드 보안 기준은 보안 항목만 본다. 하지만 팀마다 자기 규칙이 있다. "모든 Deployment에는 team 레이블", "`:latest` 이미지 금지", "모든 컨테이너에 메모리 limit" 같은 것이다. 이런 규칙을 어드미션에서 거는 과정을 따라간다. 먼저 API 서버 안에서 CEL로, 다음은 웹훅 엔진으로 걸어 보고, 각 방식이 고장 날 때 무엇을 치르는지 본다.

## CEL 정책인가, 웹훅인가

| | ValidatingAdmissionPolicy (CEL) | 웹훅 엔진 (Kyverno, Gatekeeper) |
|---|---|---|
| 도는 곳 | API 서버 안 | 별도 파드, HTTPS로 호출 |
| 고장 나면 | 죽을 서버가 없다. 식 오류는 정책의 `failurePolicy`를 따른다 | 타임아웃 뒤 `failurePolicy` Fail(거절) 또는 Ignore(건너뜀) |
| 지연 | 프로세스 안, 네트워크 왕복 없음 | 걸리는 요청마다 네트워크 호출 한 번, 최대 `timeoutSeconds` |
| 변경(mutate) | 못 한다 (MutatingAdmissionPolicy는 따로 있는 새 종류) | 한다 |
| 기존 객체 | 검사 안 함 | 백그라운드 검사·audit 리포트 |
| 그 밖에 | `paramKind`로 파라미터 | 이미지 서명 검증, 리소스 생성, 외부 데이터 |
| 잘 맞는 곳 | 레이블·이미지 태그·limit 같은 단순 필드 규칙 | CEL로 못 쓰는 규칙, 리포트가 필요할 때 |

Deployment에 쓰는 CEL 식 예시(`object`는 들어온 객체):

```yaml
validations:
  - expression: "has(object.metadata.labels) && 'team' in object.metadata.labels"
    message: "metadata.labels.team 이 필요하다"
  - expression: "object.spec.template.spec.containers.all(c, !c.image.endsWith(':latest'))"
    message: ":latest 태그 대신 버전이나 다이제스트를 고정한다"
  - expression: "object.spec.template.spec.containers.all(c, has(c.resources.limits) && has(c.resources.limits.memory))"
    message: "모든 컨테이너에 resources.limits.memory 가 필요하다"
```

`:latest` 검사는 단순화한 것이다. 태그가 아예 없는 이미지도 `latest`이고, 레지스트리 포트(`registry:5000/app`)에도 콜론이 들어간다. 실제 규칙은 둘 다 다뤄야 한다.

## 직접 확인해 보기

```bash
kubectl get validatingadmissionpolicies                    # 정책과 검사 대상
kubectl get validatingadmissionpolicybindings              # 어떤 정책을, 어떤 동작으로, 어디에
kubectl apply -f policy.yaml -f binding.yaml               # 처음엔 validationActions: [Warn, Audit]
```
