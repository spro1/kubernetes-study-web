## 증상으로 거꾸로 찾기

| 보이는 증상 | 의심할 인증서 | 확인할 것 |
| --- | --- | --- |
| kubectl이 x509·만료 오류로 접속하지 못한다 | API 서버 인증서, 관리자 kubeconfig | 만료일 목록(kubeadm 구성이면 `kubeadm certs check-expiration`) |
| API 서버는 떠 있는데 조회·변경이 모두 실패한다 | etcd 인증서 | API 서버 로그의 etcd 접속 오류 |
| 특정 노드만 NotReady가 된다 | 그 노드의 kubelet 인증서 | 노드의 kubelet 로그 |
| 갱신했는데 증상이 그대로다 | 구성요소가 옛 인증서를 들고 있음 | 컨트롤 플레인 구성요소를 재시작했는지 |

업그레이드 순서와 노드 교체는 [노드 비우기와 클러스터 업그레이드](../k8s/node-drain.mdx)에서 이어 본다.

## 직접 확인해 보기

```bash
sudo kubeadm certs check-expiration   # 인증서별 만료일
sudo openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -enddate   # API 서버 인증서 파일
kubectl config view --raw -o jsonpath='{.users[0].user.client-certificate-data}' | base64 -d | openssl x509 -noout -enddate   # 내 kubeconfig 인증서
sudo openssl x509 -in /var/lib/kubelet/pki/kubelet-client-current.pem -noout -enddate   # kubelet 클라이언트 인증서(노드에서)
echo | openssl s_client -connect <API-서버>:6443 2>/dev/null | openssl x509 -noout -dates   # 떠 있는 API 서버가 실제로 내미는 인증서(재시작했나)
```
