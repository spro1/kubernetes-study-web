# cert-manager로 TLS 인증서 자동 발급하기

## 인증서가 멈췄을 때 볼 곳

사슬을 위에서 아래로 읽고, 처음으로 Ready나 valid가 아닌 자원에서 멈춘다.

| 자원 | 만드는 쪽 | 볼 것 | 흔히 멈추는 이유 |
|---|---|---|---|
| ClusterIssuer / Issuer | 사용자 | `Ready` 조건 | ACME URL 오류, 계정 키 시크릿 없음, DNS 제공자 자격 증명 오류 |
| Certificate | 사용자, 또는 어노테이션을 읽은 ingress-shim | `Ready`·`Issuing` 조건, `status.renewalTime` | `issuerRef`의 이름이나 kind 오류, 어느 솔버도 맡지 않는 이름 |
| CertificateRequest | cert-manager, 시도마다 하나 | `Ready`·`Approved`·`Denied` | Issuer가 준비되지 않음, 요청이 승인되지 않음 |
| Order | ACME Issuer, 요청마다 하나 | `state`: pending, valid, invalid, errored | Challenge 실패, 발급 한도 초과 |
| Challenge | ACME Issuer, 이름마다 하나 | `state`와 `reason` | DNS가 다른 곳을 가리킴, 80 포트 막힘, TXT 레코드가 아직 안 보임 |
| 시크릿 | cert-manager | `tls.crt`의 주체와 만료일 | Certificate가 Ready가 되기 전에는 만들어지지 않는다 |

Certificate가 Ready=True인데 브라우저에 여전히 옛 인증서가 보이면, 인그레스나 Gateway가 같은 네임스페이스의 같은 시크릿을 가리키는지 확인한다.

## 직접 확인해 보기

```bash
kubectl get clusterissuer                                   # Issuer별 READY
kubectl describe clusterissuer letsencrypt-prod             # ACME URL, 계정 상태
kubectl get certificate,certificaterequest,order,challenge -A   # 사슬 전체를 한 번에
kubectl describe certificate shop-tls -n shop               # 조건과 이벤트
kubectl describe challenge -n shop                          # state, reason, 셀프 체크 오류
cmctl status certificate shop-tls -n shop                   # Certificate·요청·Order·Challenge를 한 화면에
cmctl renew shop-tls -n shop                                # 지금 바로 갱신
curl -v http://shop.example.com/.well-known/acme-challenge/test   # 밖에서 80 포트가 닿는가?
dig TXT _acme-challenge.example.com +short                  # DNS-01 레코드가 보이는가?
kubectl get secret shop-tls -n shop -o jsonpath='{.data.tls\.crt}' \
  | base64 -d | openssl x509 -noout -subject -enddate      # 발급된 인증서의 이름과 만료일
```
