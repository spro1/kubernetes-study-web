# 파드 보안 기준과 securityContext

같은 파드라도 루트(관리자 계정)로 돌거나 노드의 권한을 빌려 쓰면, 컨테이너 하나가 뚫렸을 때 노드 전체가 위험해진다. 네임스페이스에 건 보안 기준이 위험한 파드를 어디서 막고, 개발자는 무엇을 고쳐야 통과하는지 따라가 본다.

## 기준별로 막는 것과 securityContext 항목

| 항목 | 무엇을 막나 | 적용할 때 생기는 일 |
| --- | --- | --- |
| baseline | 특권 컨테이너, 노드 네트워크·프로세스 공유, 노드 경로 마운트 | 일반 애플리케이션은 대부분 그대로 통과한다 |
| restricted | baseline + 루트 실행, 권한 상승, 커널 기능, seccomp 없음 | 루트로 만든 이미지는 거절되거나 시작에 실패한다 |
| `runAsNonRoot` | 컨테이너 탈출 시 노드 루트 권한 획득 | 루트로 실행하도록 만든 이미지는 시작에 실패한다 |
| `readOnlyRootFilesystem` | 실행 파일을 바꾸거나 도구를 심는 것 | 임시 파일용 쓰기 가능한 볼륨을 따로 붙여야 한다 |
| `capabilities.drop` | 네트워크 설정·파일 소유권 변경 같은 특수 권한 남용 | 1024 미만 포트를 쓰면 기능 하나를 다시 추가해야 한다 |
| `allowPrivilegeEscalation: false` | 실행 중 권한 상승 | 대부분 영향 없다 |

API 서버의 세 관문(인증·인가·어드미션) 전체는 [API 요청이 저장되기까지](./api-request-path.mdx)에서 따로 본다.

## 직접 확인해 보기

```bash
kubectl get namespaces -L pod-security.kubernetes.io/enforce,pod-security.kubernetes.io/warn   # 네임스페이스별 기준과 모드
kubectl run psa-test --image=nginx --privileged -n <네임스페이스> --dry-run=server   # baseline이 거절한다. 저장은 안 된다
kubectl get events -n <네임스페이스> --field-selector reason=FailedCreate   # 배포는 됐는데 파드가 없을 때 거절 이벤트
kubectl get pod <파드> -n <네임스페이스> -o jsonpath='{.spec.containers[*].securityContext}'   # 지금 걸린 securityContext
kubectl label --dry-run=server --overwrite namespace <네임스페이스> pod-security.kubernetes.io/enforce=restricted   # enforce로 올리기 전 걸리는 파드
```
