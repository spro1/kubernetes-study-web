# 파드에서 파드로 가는 패킷

서비스와 DNS가 "어디로 보낼지"를 정한다면, 이 레슨은 그 다음 이야기다. 패킷(네트워크로 오가는 데이터 조각)이 실제로 어떤 장치를 거쳐 다른 파드에 닿는지 노드 안쪽까지 따라가 본다. 바깥 요청의 경로는 [요청이 파드에 닿기까지](../k8s/traffic.mdx), 이름 해석은 [이름으로 찾아가기 (Service·DNS)](../k8s/service-dns.mdx)에서 다룬다.

## 증상으로 층 좁히기

| 증상 | 의심할 층 | 확인할 것 |
| --- | --- | --- |
| 새로 만든 노드가 계속 NotReady다 | CNI | CNI 플러그인이 그 노드에 설치·실행되었는지 |
| 같은 노드 파드끼리는 되는데 다른 노드 파드와만 안 된다 | 노드 간 경로 | 오버레이·직접 라우팅 구성, 노드 사이 방화벽 |
| 작은 요청은 되는데 큰 응답만 끊긴다 | 오버레이 MTU | 파드 쪽 MTU가 물리 네트워크 MTU보다 작은지 |
| 파드 IP로는 되는데 서비스 IP로는 안 된다 | 변환 규칙·서비스 | 서비스 대상(엔드포인트)에 준비된 파드가 있는지 |

## 직접 확인해 보기

```bash
kubectl get pods -o wide                                             # 파드 IP와 노드
kubectl get nodes -o custom-columns=NAME:.metadata.name,PODCIDR:.spec.podCIDR   # 노드별 파드 대역(CNI에 따라 비어 있다)
ip route                                                             # (노드에서) 다른 노드 파드 대역으로 가는 경로
kubectl get endpointslices -l kubernetes.io/service-name=<서비스>    # 서비스 IP 뒤의 파드 IP
kubectl get configmap kube-proxy -n kube-system -o jsonpath='{.data.config\.conf}' | grep mode   # kube-proxy 방식(비어 있으면 iptables)
```
