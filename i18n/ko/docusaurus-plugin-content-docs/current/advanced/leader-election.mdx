# Lease로 하는 리더 선출

kube-controller-manager, kube-scheduler, 그리고 대부분의 오퍼레이터는 가용성을 위해 복제본을 여럿 돌리지만, 한 번에 하나만 일해야 한다. 누가 그 하나인지는 API 서버의 작은 Lease 객체로 합의한다. Lease를 잡고, 갱신하고, 잃고, 넘겨받는 과정을 따라간다.

## 시간 값 셋

| 설정(client-go 이름) | 정하는 것 | kube-controller-manager 기본값 | 너무 작으면 | 너무 크면 |
|---|---|---|---|---|
| `leaseDuration` | 갱신이 없을 때 팔로워가 넘겨받기 전 기다리는 시간 | 15초 | 짧은 API 지연에도 리더가 자주 바뀐다 | 장애 뒤 넘겨받기가 느리다 |
| `renewDeadline` | 리더가 포기하기 전까지 갱신을 시도하는 시간 | 10초 | API가 잠깐 느려도 리더가 물러난다 | 팔로워가 넘겨받기 전 여유가 줄어든다 |
| `retryPeriod` | 리더가 갱신하고 팔로워가 재시도하는 주기 | 2초 | API 서버에 쓰기가 늘어난다 | 갱신이 기한을 놓칠 수 있다 |

kube-controller-manager와 kube-scheduler의 플래그는 `--leader-elect-lease-duration`, `--leader-elect-renew-deadline`, `--leader-elect-retry-period`다. `leaseDuration` > `renewDeadline` > `retryPeriod`를 지킨다.

## 직접 확인해 보기

```bash
kubectl get lease -n kube-system                     # controller-manager, scheduler 등의 HOLDER
kubectl get lease kube-controller-manager -n kube-system -o yaml   # holderIdentity, leaseDurationSeconds, renewTime, leaseTransitions
kubectl get lease kube-scheduler -n kube-system \
  -o jsonpath='{.spec.holderIdentity}{"\n"}'         # 지금 스케줄링하는 인스턴스
kubectl get lease -n kube-system -w                  # 수정 한 줄이 갱신 또는 넘겨받기 하나
kubectl get lease -n kube-node-lease                 # 노드마다 하트비트 Lease 하나
kubectl get lease <node-name> -n kube-node-lease \
  -o jsonpath='{.spec.renewTime}{"\n"}'              # kubelet의 마지막 하트비트
kubectl get leasecandidates -n kube-system           # 조정된 리더 선출을 켰을 때만
```
