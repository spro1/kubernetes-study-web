# 이미지가 만들어지고 실행되기까지

컨테이너의 원본인 이미지가 무엇으로 이루어지고, 어떤 이름을 달고, 어디에 보관되었다가 컨테이너가 되는지 따라가 본다. 빌드를 파이프라인에서 자동으로 돌리는 흐름은 [파이프라인이 도는 순서](./cicd-pipeline.mdx)에서, 노드의 kubelet·런타임이 이미지를 받아 파드를 띄우는 과정은 [파드가 뜨기까지](../k8s/pod-startup.mdx)에서 다룬다. 여기서는 이미지 자체에 집중한다.

## 헷갈리기 쉬운 짝

| 짝 | 차이 |
| --- | --- |
| 이미지 / 컨테이너 | 이미지는 읽기 전용 원본, 컨테이너는 그 이미지를 실행한 실체(프로세스) |
| RUN / CMD | RUN은 이미지를 만들 때 한 번, CMD는 컨테이너가 시작될 때마다 실행 |
| 태그 / 다이제스트 | 태그는 옮겨 붙는 이름표, 다이제스트는 내용으로 계산한 바뀌지 않는 고유값 |
| latest / 1.4.3 | latest는 저절로 최신을 가리키지 않는다. 운영에서는 판을 특정하는 태그를 쓴다 |
| 검사 안 함 / 취약점 0개 | 검사 도구가 없어 결과가 없는 것과 검사했더니 없는 것은 다른 상태 |
| EXPOSE / 실제 노출 | EXPOSE는 포트를 문서처럼 적어 둘 뿐, 이것만으로 바깥에서 접속되지 않는다 |
