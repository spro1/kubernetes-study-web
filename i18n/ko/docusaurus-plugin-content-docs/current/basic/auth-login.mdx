# 로그인은 이렇게 동작한다 (세션, JWT, OIDC)

비밀번호를 넣거나 **Google로 로그인**을 누르면, 그 뒤로는 어느 페이지에서든 사이트가 나를 알아본다. 그 과정을 따라간다. **비밀번호 확인 → 세션 쿠키나 JWT → OAuth 2.0과 OpenID Connect → 토큰 → 401과 403**.

## 세션 쿠키와 JWT

| | 세션 쿠키 | JWT (자기 완결 토큰) |
|---|---|---|
| 클라이언트가 가진 것 | 그 자체로는 뜻이 없는 무작위 ID | 누구나 읽을 수 있는 서명된 클레임(sub, exp, aud …) |
| 서버가 검사하는 법 | 세션 저장소에서 ID를 찾는다 | 키로 서명을 확인한다. 조회 없음 |
| 무효로 만들기 | 세션 기록을 지우면 바로 효과 | exp까지 기다리거나 차단 목록을 둔다 |
| 흔한 쓰임 | 서버에서 화면을 그리는 전통적인 웹 앱 | API, 발급자 하나를 같이 쓰는 서비스들, OIDC ID 토큰 |
| 주된 위험 | 세션 저장소가 의존 대상이 된다 | 긴 수명, 읽히는 payload에 넣은 비밀 |

## OIDC가 주는 세 가지 토큰

| 토큰 | 받는 쪽 | 형식 | 수명 | 보내는 곳 |
|---|---|---|---|---|
| ID 토큰 | 앱(클라이언트) | 항상 JWT | 짧다 | 아무 데도 안 보낸다. 앱이 검사하고 누가 로그인했는지 읽는다 |
| 액세스 토큰 | API(리소스 서버) | JWT 또는 불투명한 문자열 | 짧다(몇 분~한 시간) | API에 `Authorization: Bearer`로 |
| 리프레시 토큰 | ID 제공자 | 대개 불투명한 문자열 | 길다 | 토큰 엔드포인트에만 |

## 직접 확인해 보기

```bash
curl -s https://accounts.google.com/.well-known/openid-configuration | jq '{issuer, authorization_endpoint, token_endpoint, jwks_uri}'   # OIDC 디스커버리
curl -s https://www.googleapis.com/oauth2/v3/certs | jq '.keys[].kid'   # ID 토큰에 서명하는 공개 키(JWKS)

TOKEN='<JWT를 붙여 넣는다>'
echo "$TOKEN" | cut -d. -f1 | tr '_-' '/+' | base64 -d; echo   # header: alg, kid (= 패딩이 없다는 경고가 나올 수 있다)
echo "$TOKEN" | cut -d. -f2 | tr '_-' '/+' | base64 -d; echo   # payload: iss, sub, aud, exp. 누구나 읽을 수 있으니 비밀이 아니다

curl -i -H "Authorization: Bearer $TOKEN" https://api.example.com/me   # 200, 401(+ WWW-Authenticate), 403 중 무엇인지 본다
date -r 1767225600                                                     # exp 값을 시각으로 바꾼다 (macOS. GNU는 date -d @1767225600)
```
