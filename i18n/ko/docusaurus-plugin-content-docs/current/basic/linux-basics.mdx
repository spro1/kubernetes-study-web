# 쿠버네티스를 위한 리눅스 기초

쿠버네티스 노드는 모두 리눅스 서버고, 컨테이너는 모두 리눅스 프로세스다. 서버 한 대에서 앱 하나를 따라간다. 어떻게 시작하고, 어떻게 멈추고, 종료 코드가 무엇을 말하고, 왜 "permission denied"가 나고, 로그는 어디로 가는지 본다.

## 종료 코드와 시그널 한눈에 보기

| 코드 | 뜻 | 흔한 원인 | 볼 것 |
|---|---|---|---|
| 0 | 성공 | 프로그램이 정상으로 끝났다 | — |
| 1 | 일반 오류 | 프로그램이 스스로 실패를 알렸다 | 앱 로그 |
| 2 | 셸 내장 명령 오용이나 잘못된 인자 (흔한 관례) | 틀린 플래그 | 명령줄 |
| 126 | 찾았지만 실행할 수 없다 | `x` 비트가 없거나, 디렉터리이거나, 바이너리 형식이 틀렸다 | `ls -l`, `chmod +x` |
| 127 | 명령을 찾을 수 없다 | 오타, `PATH`에 없음 (또는 이미지에 없음) | `which cmd`, `echo $PATH` |
| 128 + n | 시그널 n으로 죽었다 | — | 어떤 시그널을 누가 보냈나 |
| 130 | 128 + 2, SIGINT | Ctrl+C | — |
| 137 | 128 + 9, SIGKILL | OOM 킬, 유예 시간 만료, `kill -9` | `kubectl describe pod`의 Reason, `dmesg` |
| 143 | 128 + 15, SIGTERM | 정상 종료 요청을 앱이 받지 않았거나 기본 동작으로 끝났다 | 종료 중이라면 대개 괜찮다 |

| 시그널 | 번호 | 받아서 처리할 수 있나 | 흔한 뜻 |
|---|---|---|---|
| SIGHUP | 1 | 예 | 터미널이 끊김, 관례상 "설정 다시 읽기" |
| SIGINT | 2 | 예 | Ctrl+C |
| SIGKILL | 9 | 아니요 | 지금 멈춤, 정리 없음 |
| SIGTERM | 15 | 예 | 멈춰 달라는 부탁. `kill`과 쿠버네티스의 기본값 |

## 직접 확인해 보기

```bash
# 프로세스, 부모, 사용자 (리눅스 서버나 VM에서)
echo $$                                  # 이 셸의 PID
ps -o pid,ppid,user,cmd -p $$
sleep 300 &                              # 이 셸의 자식
ps -o pid,ppid,cmd --ppid $$
id                                       # 내 UID, GID, 그룹

# 시그널과 종료 코드
sleep 300 & kill $!; wait $!; echo "exit $?"        # 143 = 128 + 15
sleep 300 & kill -9 $!; wait $!; echo "exit $?"     # 137 = 128 + 9
nosuchcmd; echo "exit $?"                           # 127
bash -c 'trap "echo got TERM; exit 0" TERM; sleep 30 & wait' & sleep 1; kill $!; wait $!   # trap이 돈다

# 권한
echo secret > demo.txt && chmod 600 demo.txt && ls -l demo.txt   # -rw-------
printf '#!/bin/sh\necho hi\n' > hi.sh; ./hi.sh; echo "exit $?"   # 126, x 비트 없음
chmod +x hi.sh && ./hi.sh

# systemd와 로그 (리눅스 서버나 kind 노드에서: docker exec -it lab-control-plane bash)
systemctl status kubelet --no-pager
journalctl -u kubelet --since "10 min ago" --no-pager | tail
ls /var/log/pods /var/log/containers | head
```
