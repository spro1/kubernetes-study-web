# 브랜치에서 머지 리퀘스트까지

## 낱말과 직접 해 보기

| 낱말 | 한 줄 뜻 | 확인하는 방법 |
| --- | --- | --- |
| 커밋 해시 | 커밋마다 붙는 고유 문자열 | `git log --oneline`으로 앞 7자리 짧은 해시와 메시지를 본다 |
| 브랜치 | 갈라져 나온 작업 줄기 | `git switch -c feature/login`으로 만들고 `git branch`로 목록을 본다 |
| 머지 리퀘스트 | 합쳐 달라는 요청과 리뷰 기록 | GitLab은 머지 리퀘스트, GitHub는 풀 리퀘스트라고 부른다. 변경(diff)은 `git diff main`으로 미리 본다 |
| 충돌 | 같은 줄을 다르게 고친 상태 | 오류가 아니다. `git status`로 충돌 파일을 찾아 사람이 고친 뒤 커밋한다 |
| 태그 | 커밋에 붙인 이름표 | `git tag v1.2.0`으로 붙인다. 이미지 태그와는 다른 것이다 |

이미지 태그에 커밋 해시나 Git 태그를 넣어 두면, 클러스터에서 도는 이미지가 어느 코드에서 나왔는지 바로 따라갈 수 있다. 지금 도는 이미지는 `kubectl describe deployment <이름>`의 Image 항목에서 본다.
