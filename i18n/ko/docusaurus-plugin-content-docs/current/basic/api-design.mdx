# HTTP API 설계

API는 그것을 부르는 모든 클라이언트와 맺는 약속이다. 엔드포인트 하나에서 공개 계약으로 자라는 주문 API를 따라가며, 일이 틀어지거나 바뀔 때 클라이언트를 지켜 주는 선택이 무엇인지 본다.

## 메서드와 상태 코드 한눈에 보기

| 메서드 | 쓰임 | 안전 | 멱등 | 흔한 성공 응답 |
|---|---|---|---|---|
| GET | 리소스나 목록 읽기 | 예 | 예 | 200 |
| POST | 컬렉션에 만들기, 동작 실행 | 아니오 | 아니오 (멱등성 키를 쓴다) | `Location`과 함께 201, 또는 200 / 202 |
| PUT | 리소스 전체 바꾸기 | 아니오 | 예 | 200 또는 204 |
| PATCH | 리소스 일부 바꾸기 | 아니오 | 보장하지 않음 | 200 또는 204 |
| DELETE | 리소스 지우기 | 아니오 | 예 | 204 |

| 상태 코드 | 뜻 | 클라이언트가 할 일 |
|---|---|---|
| 400 Bad Request | 형식이 잘못된 요청: 깨진 JSON, 틀린 타입 | 요청을 고친다. 그대로 재시도하지 않는다 |
| 404 Not Found | 그런 리소스가 없다 | 멈추거나 id를 확인한다 |
| 409 Conflict | 현재 상태와 충돌한다. 예: 오래된 버전 | 다시 읽은 뒤 변경을 재시도한다 |
| 422 Unprocessable Content | 형식은 맞지만 규칙을 어겼다 | 필드 오류를 사용자에게 보여 준다 |
| 429 Too Many Requests | 속도 제한에 걸렸다 | `Retry-After`만큼 기다린 뒤 재시도한다 |
| 500 / 502 / 503 / 504 | 서버나 업스트림이 실패했다 | 멱등한 요청만 백오프로 재시도한다 |

| | REST + JSON | gRPC | GraphQL |
|---|---|---|---|
| 계약 | OpenAPI (선택) | `.proto` 파일 (필수) | 스키마 (필수) |
| 전송 형식 | JSON 텍스트 | Protobuf 바이너리 | JSON |
| 전송 계층 | HTTP/1.1, 2, 3 | HTTP/2 | 보통 엔드포인트 하나로 HTTP POST |
| 스트리밍 | 서버 전송 이벤트, 따로 WebSocket | 기본 제공, 양방향 | 구독(subscription) |
| 잘 맞는 곳 | 공개 API, 브라우저, 캐시 | 서비스 사이, 낮은 지연 | 필요한 필드가 제각각인 프런트엔드 |

## 직접 확인해 보기

쿠버네티스 API 자체가 잘 설계된 HTTP API다. 직접 들여다본다.

```bash
kubectl proxy --port=8001 &                                   # API 서버로 가는 인증된 로컬 터널

curl -s localhost:8001/apis/apps | jq '.versions'             # 경로에 나란히 놓인 버전
curl -i localhost:8001/api/v1/namespaces/default/pods/nope    # 404와 오류 본문인 Status 오브젝트

# limit과 continue(커서)로 페이지 나누기
curl -s 'localhost:8001/api/v1/pods?limit=2' | jq -r '.metadata.continue'

curl -s localhost:8001/openapi/v3 | jq '.paths | keys | .[:5]'   # 공개된 OpenAPI 명세
kubectl get pods -A -v=6 2>&1 | grep -E 'GET|200'             # kubectl은 나눠서 묻는다: ?limit=500
kill %1                                                        # 프록시 멈추기
```
