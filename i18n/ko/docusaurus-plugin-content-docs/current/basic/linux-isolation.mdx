# 리눅스는 컨테이너를 어떻게 격리하나

컨테이너는 작은 가상 머신이 아니다. 커널이 좁은 세상을 보여 주고(**네임스페이스**) 예산을 정해 둔(**cgroup**) 호스트의 평범한 프로세스다. 컨테이너 하나가 시작돼서 OOM으로 종료되기까지 따라간다.

## 네임스페이스와 cgroup 파일 한눈에 보기

| 무엇 | 격리하거나 제한하는 것 | 확인할 곳 |
|---|---|---|
| pid 네임스페이스 | 프로세스 번호. 안에서 엔트리포인트는 PID 1 | `ls -l /proc/<pid>/ns/pid` |
| net 네임스페이스 | 인터페이스, IP 주소, 라우팅, 포트 | `ip netns`, `nsenter -t <pid> -n ip addr` |
| mnt 네임스페이스 | 마운트 테이블. 이미지가 `/`로 마운트된다 | `cat /proc/<pid>/mountinfo` |
| uts 네임스페이스 | 호스트명 | `nsenter -t <pid> -u hostname` |
| ipc 네임스페이스 | System V IPC, POSIX 메시지 큐 | `lsns -t ipc` |
| user 네임스페이스 | UID/GID 매핑(안에서는 root, 밖에서는 일반 사용자) | `cat /proc/<pid>/uid_map` |
| `cpu.max` | 할당량과 주기로 정한 CPU 상한. 넘으면 스로틀링 | `cat cpu.max`, `cat cpu.stat` |
| `cpu.weight` | 경쟁할 때 CPU를 나눠 받는 비율(요청값에서 옴) | `cat cpu.weight` |
| `memory.max` | 메모리 상한. 넘으면 OOM 킬러가 돈다 | `cat memory.max`, `cat memory.events` |

## 직접 확인해 보기

```bash
sudo unshare --pid --fork --mount-proc --uts bash    # 새 pid·uts 네임스페이스 안의 셸
ps -ef; hostname demo; hostname                      # 안에서: bash가 PID 1, 호스트명 변경은 안에만 적용
lsns                                                 # 호스트에서: 네임스페이스 목록과 첫 프로세스
PID=$(pgrep -f <컨테이너-명령> | head -1)             # 컨테이너 프로세스의 호스트 PID
ls -l /proc/$PID/ns                                  # 이 프로세스의 네임스페이스 ID
cat /proc/$PID/cgroup                                # /sys/fs/cgroup 아래 cgroup 경로
cat /sys/fs/cgroup/<그 경로>/{cpu.max,memory.max,cpu.stat,memory.events}   # 한도, 스로틀링, oom_kill
kubectl get pod <파드> -o jsonpath='{.status.containerStatuses[*].lastState.terminated.exitCode}'   # OOM 뒤에는 137
```
