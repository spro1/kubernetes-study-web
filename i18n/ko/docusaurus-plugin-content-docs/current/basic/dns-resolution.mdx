# DNS가 주소를 찾아가는 길

[주소창에 주소를 입력하면](../basic/web-request.mdx)에서는 DNS를 이름을 IP로 바꿔 주는 상자 하나로만 봤다. 여기서는 그 상자를 열어 본다. 누가 누구에게 묻는지, 왜 답을 캐시에 담아 두는지, DNS를 바꿔도 왜 바로 반영되지 않는지를 따라간다. 클러스터 안의 이름 풀이는 [이름으로 찾아가기 (Service·DNS)](../k8s/service-dns.mdx)에서 이어서 본다.

## 자주 보는 레코드

| 종류 | 담는 것 | 예시 |
|---|---|---|
| A | IPv4 주소 | `www.example.com. 300 IN A 203.0.113.10` |
| AAAA | IPv6 주소 | `www.example.com. 300 IN AAAA 2001:db8::10` |
| CNAME | 다른 이름을 가리키는 별칭. CNAME이 있는 이름에는 다른 레코드를 둘 수 없어서 영역 꼭대기(apex)에는 쓸 수 없다 | `shop.example.com. CNAME lb-123.example.net.` |
| MX | 도메인의 메일 서버와 우선순위 숫자 | `example.com. MX 10 mail.example.com.` |
| TXT | 자유 텍스트. SPF, 도메인 소유 확인 등에 쓴다 | `example.com. TXT "v=spf1 -all"` |
| NS | 영역의 권한 네임서버 | `example.com. NS ns1.example.net.` |
| SOA | 영역 메타데이터. 부정 캐시 TTL도 여기서 나온다 | `example.com. SOA ns1... hostmaster... ` |

## 응답 코드

| 코드 | 뜻 | 확인할 것 |
|---|---|---|
| NOERROR, 답 있음 | 성공 | — |
| NOERROR, 답 없음 (NODATA) | 이름은 있지만 물은 종류의 레코드가 없다(예: AAAA만 없음) | 물어본 레코드 종류 |
| NXDOMAIN | 영역에 그 이름이 없다 | 철자, 영역 파일, 방금 만들었는지(부정 캐시) |
| SERVFAIL | 리졸버가 올바른 답을 얻지 못했다 | 권한 서버 상태, 위임(NS) 설정, DNSSEC 유효성 |
| REFUSED | 서버가 정책상 답하지 않는다 | 그 리졸버를 쓸 권한이 있는지 |
| 시간 초과 (응답 없음) | 아무것도 돌아오지 않았다 | UDP/TCP 53 방화벽, resolv.conf의 nameserver |

## 직접 확인해 보기

```bash
cat /etc/resolv.conf                      # 스텁이 묻는 리졸버, search/options
getent hosts www.example.com              # 앱과 같은 방식으로 풀이(/etc/hosts 포함)
dig www.example.com                       # status:, flags, ANSWER 섹션과 TTL
dig +trace www.example.com                # 루트 → TLD → 권한 서버를 직접 따라간다
dig @8.8.8.8 www.example.com +short       # 특정 리졸버에 묻기
dig @1.1.1.1 www.example.com +short       # 리졸버끼리 캐시 비교
dig example.com NS +short                 # 권한 서버가 누구인지
dig example.com SOA                       # 마지막 필드가 부정 캐시용 MINIMUM
dig wwww.example.com | grep status        # NXDOMAIN
nslookup www.example.com                  # 윈도우를 포함해 거의 어디에나 있다
```

같은 리졸버에 `dig www.example.com`을 두 번 실행해서 TTL이 줄어드는 것을 보자. 그게 캐시다.
