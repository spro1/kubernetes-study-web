# 좋은 Dockerfile 쓰기

빌드가 된다고 좋은 Dockerfile은 아니다. 이미지 하나를 소스 트리에서 실행 중인 파드까지 따라가며, 어떤 줄이 빌드를 빠르게 하고 이미지를 작고 안전하게 만들며 깔끔하게 멈추게 하는지 본다.

## 줄별로 보는 흔한 실수와 나은 습관

| 줄 | 흔한 실수 | 나은 방법 | 이유 |
|---|---|---|---|
| `COPY` | 의존성 설치 전에 `COPY . .` | 잠금 파일 복사, 설치, 그 다음 소스 복사 | 코드를 고쳐도 전부 다시 설치하지 않는다 |
| `.dockerignore` | 없음 | `.git`, 의존성 폴더, 빌드 결과물, `.env` 제외 | 컨텍스트가 작고 캐시가 안정되며 파일이 새지 않는다 |
| `FROM` | 전체 SDK 이미지 한 스테이지 | 빌드 스테이지 + slim·distroless 런타임 스테이지 | 툴체인과 소스가 이미지에 안 들어간다 |
| `FROM` | `node:22` 같은 움직이는 태그 | `image:tag@sha256:...`, 봇이 갱신 | 같은 커밋이면 같은 이미지 |
| `USER` | 없음(root) | root가 아닌 숫자 UID | `runAsNonRoot`와 맞고 피해 범위가 작다 |
| `CMD` / `ENTRYPOINT` | 셸 형식 `CMD node server.js` | exec 형식 `CMD ["node", "server.js"]` | SIGTERM이 앱에 닿고 롤아웃이 깔끔히 멈춘다 |
| `ARG` / `ENV` / `COPY` | 토큰을 넘기거나 복사 | `RUN --mount=type=secret` | 시크릿이 레이어·메타데이터에 남지 않는다 |
| `HEALTHCHECK` | 쿠버네티스에서도 믿고 씀 | readiness·liveness·startup 프로브 | kubelet은 HEALTHCHECK를 실행하지 않는다 |

## 직접 확인해 보기

```bash
docker build -t my-app:dev .                                  # 기본으로 BuildKit을 쓴다
docker history my-app:dev                                     # 레이어마다 크기와 만든 줄
docker image inspect my-app:dev \
  --format 'user={{.Config.User}} entrypoint={{json .Config.Entrypoint}} cmd={{json .Config.Cmd}}'
docker buildx imagetools inspect gcr.io/distroless/static-debian12:nonroot   # FROM에 고정할 다이제스트
docker build --secret id=npmrc,src=$HOME/.npmrc -t my-app:dev .              # RUN --mount=type=secret,id=npmrc 와 짝
docker build --build-arg SOURCE_DATE_EPOCH=$(git log -1 --pretty=%ct) -t my-app:dev .   # 고정 타임스탬프
kubectl debug -it pod/my-app --image=busybox:1.36 --target=app # distroless 컨테이너 옆에 셸 붙이기
```
