# 요청 한 번의 아래층: TCP/IP 계층

[주소창에 주소를 입력하면](../basic/web-request.mdx)에서는 요청이 브라우저에서 서버로 가는 화살표 하나로 그려졌다. 이 레슨은 그 화살표를 열어 본다. `203.0.113.10:443`으로 가는 연결 하나를 **TCP/IP 계층**으로 따라가며, 계층마다 무엇을 붙이고 어떤 주소를 쓰며 어디서 막히는지 본다.

## 계층, 단위, 주소

| TCP/IP 계층 | OSI 계층 | 단위 | 주소 | 예시 도구 |
|---|---|---|---|---|
| 응용 | 7 (5–7) | 메시지 (HTTP 요청) | URL, 호스트 이름 | `curl -v` |
| 전송 | 4 | 세그먼트 (TCP) | 포트 | `ss -tlnp` |
| 인터넷 | 3 | 패킷 | IP 주소 | `ip route`, `traceroute` |
| 링크 | 2 (와 1) | 프레임 | MAC 주소 | `ip neigh`, `tcpdump -e` |

## 거부인가, 시간 초과인가

| 증상 | 일어난 일 | 확인할 것 |
|---|---|---|
| `Connection refused`, 즉시 | 호스트가 RST로 답했다. 그 포트·주소에서 대기하는 것이 없다 | 서버에서 `ss -tlnp`. 앱이 떠 있는지, 포트가 맞는지, `127.0.0.1`이 아니라 `0.0.0.0`에 묶였는지 |
| `Connection timed out`, 한참 뒤 | SYN에 답이 없다. 경로에서 버려졌다 | 방화벽 규칙, 보안 그룹, 라우팅(`traceroute`) |
| `No route to host` | 라우터나 방화벽이 ICMP 오류를 돌려보냈거나, 다음 홉의 ARP에 답이 없다 | `ip route`, `ip neigh`, 호스트가 켜져 있는지 |
| 연결은 되는데 큰 응답만 멈춤 | 경로 MTU가 패킷보다 작은데, 그걸 알려 줄 ICMP가 막혔다 | `ping -M do -s 1472 <호스트>`, 터널 MTU, MSS clamping |

## 직접 확인해 보기

```bash
ip route                                   # default via <게이트웨이> — 서브넷 밖으로 가는 길
ip neigh                                   # ARP·이웃 캐시: 이 랜의 IP → MAC
traceroute -n <호스트>                     # 라우터 홉 하나하나 (TTL 만료를 이용)
ss -tlnp                                   # 대기 중인 TCP 소켓과 그것을 가진 프로세스 (서버에서 실행)
curl -v http://<호스트>:8080/              # "Connected to" / "Connection refused" / 시간 초과
sudo tcpdump -ni any 'tcp port 443 and tcp[tcpflags] & (tcp-syn|tcp-rst) != 0'   # SYN, SYN-ACK, RST 보기
```
