# 워크로드 종류

파드는 가장 작은 실행 단위지만, 사용자가 파드를 직접 만드는 일은 드물다. 보통은 "파드를 어떤 방식으로 몇 개 실행할지" 정하는 관리자 자원(워크로드)을 만들고, 파드는 그 자원이 대신 만든다. 세 가지 관리자가 파드를 어떻게 다르게 다루는지 비교해 본다.

## 언제 무엇을 쓰나

| 이런 애플리케이션이라면 | 쓸 워크로드 | 개수를 정하는 것 |
| --- | --- | --- |
| 웹 화면·API 서버처럼 여러 개 중 아무거나 요청을 받아도 되는 것 | 디플로이먼트 | 레플리카 수 |
| 데이터베이스·메시지 큐처럼 각자 데이터를 들고 있는 것 | 스테이트풀셋 | 레플리카 수 (순번 이름) |
| 모든 노드에 하나씩 있어야 하는 수집기·에이전트 | 데몬셋 | 노드 수 |
| 한 번 실행하고 끝나는 이관·계산 작업 | 잡 | 성공해야 하는 횟수 |
| 매일·매주 정해진 시각에 반복하는 작업 | 크론잡 | 일정마다 잡을 하나씩 |

잡과 크론잡의 흐름은 [한 번 돌고 끝나는 일 (Job·CronJob)](../k8s/job-cronjob.mdx), 디플로이먼트의 버전 교체는 [무중단 배포 (롤링 업데이트)](../k8s/rolling-update.mdx)에서 이어서 본다.
