# 노트북에 실습 클러스터 만들기

이 사이트의 "직접 해 보기"는 모두 클러스터가 있어야 한다. **kind**(Kubernetes in Docker)로 노트북에 하나 만들자. kind에서는 쿠버네티스 노드 하나가 컨테이너 하나다. 공짜고, 1분이면 만들고, 언제든 버릴 수 있다.

## kind와 minikube 나란히 보기

둘 다 컴퓨터 한 대에 진짜 클러스터를 만든다. kind는 노드를 컨테이너로 띄운다. minikube는 노드를 컨테이너(docker 드라이버)나 VM으로 띄운다.

| 할 일 | kind | minikube |
|---|---|---|
| 만들기 | `kind create cluster --name lab` | `minikube start -p lab` |
| 멀티 노드 | `nodes` 목록을 적은 `--config lab.yaml` | `minikube start -p lab --nodes 3` |
| kubectl 컨텍스트 | `kind-lab` | `lab` (프로필 이름) |
| 로컬 이미지 넣기 | `kind load docker-image my-app:dev --name lab` | `minikube -p lab image load my-app:dev` |
| 앱에 닿기 | `kubectl port-forward`, 또는 NodePort + `extraPortMappings` | `kubectl port-forward`, 또는 `minikube service my-app` |
| 지우기 | `kind delete cluster --name lab` | `minikube delete -p lab` |

| 증상 | 흔한 원인 | 고치는 법 |
|---|---|---|
| 내 이미지가 `ErrImagePull` / `ImagePullBackOff` | 이미지가 노트북에만 있거나 태그가 `:latest`다 | `kind load docker-image` 후 고정 태그나 `imagePullPolicy: IfNotPresent`를 쓴다 |
| 파드 `Pending`, 노드 `NotReady`, `OOMKilled` | 런타임에 준 메모리·CPU가 모자란다 | Docker VM 자원을 늘리거나 노드 수를 줄인다 |
| 명령이 엉뚱한 클러스터로 간다 | 현재 컨텍스트가 다른 곳을 가리킨다 | `kubectl config use-context kind-lab` |
| 포트가 이미 쓰여 `kind create`가 실패한다 | 다른 프로세스가 `extraPortMappings`의 호스트 포트를 쓴다 | 그 포트를 비우거나 다른 `hostPort`를 고른다 |
| `localhost:8080` 연결이 거부된다 | `port-forward`가 멈췄거나 서비스 포트가 틀렸다 | 다시 실행하고 `kubectl get svc`로 포트를 본다 |

## 직접 확인해 보기

```bash
# 0. 도구 확인
docker info >/dev/null && echo "runtime ok"
kind version
kubectl version --client

# 1. 노드 3개 클러스터: 컨트롤 플레인 1, 워커 2, 호스트 포트 30080 -> NodePort 30080
cat > lab.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    extraPortMappings:
      - containerPort: 30080
        hostPort: 30080
  - role: worker
  - role: worker
EOF
kind create cluster --name lab --config lab.yaml
docker ps --format '{{.Names}}'                 # lab-control-plane, lab-worker, lab-worker2
kubectl config current-context                   # kind-lab
kubectl get nodes -o wide

# 2. 앱을 띄우고 접속
kubectl create deployment web --image=nginx:1.27 --replicas=2
kubectl expose deployment web --port=80
kubectl port-forward svc/web 8080:80             # http://localhost:8080 열기, Ctrl+C로 끝

# 3. 내 이미지: 빌드, 넣기, 실행 (:latest 말고 고정 태그)
# docker build -t my-app:dev .
# kind load docker-image my-app:dev --name lab
# kubectl create deployment my-app --image=my-app:dev

# 4. 노드 비우기 연습
kubectl drain lab-worker --ignore-daemonsets
kubectl get pods -o wide                         # 파드가 lab-worker2로 옮겨 갔다
kubectl uncordon lab-worker

# 5. 정리
kind delete cluster --name lab
```
