# 쿠버네티스에서 개발 루프 돌리기

안쪽 루프는 하루에도 수십 번 되풀이하는 일이다. 코드를 고치고, 돌아가는 것을 본다. 쿠버네티스에서 이걸 손으로 하면 빌드, 푸시, 배포, 기다리기가 된다. 파일 저장 한 번을 따라가며 도구가 이 루프를 어떻게 줄이는지 본다.

## 루프의 어느 부분에 어떤 도구를 쓰나

| 필요 | 도구 예 | 하는 일 | 주의 |
|---|---|---|---|
| 저장하면 감시·빌드·배포 | Skaffold(`skaffold dev`), Tilt(`tilt up`) | 빌드, 태그, 렌더링, 배포, 로그를 잇는다 | kubectl 컨텍스트부터 확인 |
| 작은 수정은 빌드 생략 | Skaffold `sync`, Tilt `live_update` | 실행 중인 컨테이너에 파일 복사 | Skaffold는 컨테이너에 `tar` 필요, 이미지와 어긋남 |
| 로컬에선 레지스트리 없이 | `kind load`, kind에 연결한 로컬 레지스트리 | 이미지를 노드에 바로 넣는다 | 로컬 클러스터에서만 |
| 앱 확인 | `kubectl port-forward`, `kubectl logs -f`, 도구 UI | 포트와 로그를 터미널로 가져온다 | 맨 kubectl은 파드가 재시작되면 포워딩이 끊긴다 |
| 운영과 비슷한 설정 | Helm 값 파일, Kustomize 오버레이 | 운영과 같은 템플릿, 개발용 설정 | 개발용 차이는 작게 |
| 진짜 의존 서비스 | Telepresence, mirrord | 로컬 프로세스가 공유 클러스터에 붙는다 | 남의 트래픽을 가져갈 수 있다 |
| 모두 같은 도구 | Dev Containers(`devcontainer.json`) | 툴체인을 컨테이너에 고정 | kind를 쓰려면 컨테이너 안 Docker 설정 |

## 직접 확인해 보기

```bash
kubectl config current-context            # kind-lab이면 Skaffold가 로컬로 본다(푸시 없음)
skaffold init                             # Dockerfile과 매니페스트로 skaffold.yaml 만들기
skaffold dev --port-forward               # 감시, 빌드, 배포, 로그; Ctrl+C로 정리
skaffold render -p dev                    # dev 프로필이 적용할 매니페스트 출력
tilt up                                   # Tiltfile 읽기; UI는 http://localhost:10350
tilt down                                 # tilt up이 배포한 것 지우기
kubectl port-forward svc/my-app 8080:80   # 도구가 속에서 하는 일
kubectl logs -f deploy/my-app             # 디플로이먼트의 파드 하나에서 로그 보기
```
