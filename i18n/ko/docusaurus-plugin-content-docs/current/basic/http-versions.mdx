# HTTP/1.1, HTTP/2, HTTP/3

웹 페이지 하나는 파일 수십 개를 받아야 뜬다. 요청의 뜻(메서드, 경로, 헤더, 상태 코드)은 모든 HTTP 버전에서 같다. 달라지는 것은 **바이트를 나르는 방식**이다. 한 번에 요청 하나씩, TCP 연결 하나에 스트림 여럿, 또는 UDP 위의 QUIC 스트림. 상태 코드는 [주소창에 주소를 입력하면](../basic/web-request.mdx)에서 다룬다.

## 세 버전 비교

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
|---|---|---|---|
| 전송 계층 | TCP (+ TLS) | TCP + TLS (h2), 서비스 간에는 암호화 없는 h2c | UDP 위의 QUIC, TLS 1.3 내장 |
| 메시지 형식 | 글자 줄 | 스트림 위의 바이너리 프레임 | QUIC 스트림 위의 바이너리 프레임 |
| 한 연결에서 동시에 오가는 요청 | 응답 하나씩 | 섞여 오가는 스트림 여럿 | 서로 독립인 스트림 여럿 |
| 헤더 압축 | 없음 | HPACK | QPACK |
| HOL 블로킹 | 연결마다, HTTP 수준 | 패킷 손실 시 TCP 수준 | 데이터를 잃은 스트림만 |
| 첫 요청 전 왕복 (새 연결, TLS 1.3) | 2 | 2 | 1 (0-RTT 재접속 시 0) |
| 버전을 정하는 방법 | 기본값 | ALPN `h2` | `Alt-Svc` 헤더나 DNS HTTPS 레코드, 그다음 ALPN `h3` |
| 명세 | RFC 9112 | RFC 9113 | RFC 9114 |

## 직접 확인해 보기

```bash
curl -sv --http1.1 -o /dev/null https://<도메인>/ 2>&1 | grep -E 'ALPN|^> GET|^< HTTP'   # HTTP/1.1로 고정
curl -sv --http2   -o /dev/null https://<도메인>/ 2>&1 | grep -E 'ALPN|^< HTTP'          # ALPN으로 h2 제안
curl -sI https://<도메인>/ | grep -i alt-svc                                             # 서버가 h3를 알리는지
curl -s --http3 -o /dev/null -w '%{http_version}\n' https://<도메인>/                    # HTTP/3 지원으로 빌드된 curl 필요
openssl s_client -connect <도메인>:443 -alpn h2 </dev/null 2>/dev/null | grep ALPN        # "ALPN protocol: h2"
```

브라우저 개발자 도구의 Network 표 머리글을 오른쪽 클릭해 **Protocol** 열을 켜면 요청마다 `http/1.1`, `h2`, `h3`가 보인다.
