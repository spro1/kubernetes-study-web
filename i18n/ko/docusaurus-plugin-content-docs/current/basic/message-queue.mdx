# 메시지 큐가 서비스를 떼어 놓는 방식

주문 서비스는 **이벤트** 하나를 발행한다. 배송과 이메일은 저마다 자기 속도로 그것을 읽는다. 이벤트를 **프로듀서 → 토픽 파티션 → 컨슈머 그룹 → 오프셋 커밋** 순서로 따라간 뒤, 컨슈머가 죽거나 뒤처지거나 끝내 처리할 수 없는 메시지를 만났을 때 무슨 일이 생기는지 본다.

## 전달 보장

| 보장 | 얻는 방법 | 장애 때 생기는 일 | 쓰는 곳 |
|---|---|---|---|
| 최대 한 번 (at-most-once) | 처리하기 전에 오프셋을 커밋한다 | 메시지를 잃을 수 있다 | 일부 표본 지표처럼 빈 곳이 생겨도 괜찮은 데이터 |
| 최소 한 번 (at-least-once) | 처리한 뒤 오프셋을 커밋한다 | 메시지가 두 번 처리될 수 있다 | 일반적인 기본값. 멱등한 컨슈머와 함께 쓴다 |
| 정확히 한 번 (exactly-once) | 카프카 멱등 프로듀서와 트랜잭션, `isolation.level=read_committed` 컨슈머 | 카프카 안에서의 읽기-처리-쓰기는 한 번만 일어난다 | 카프카 토픽에서 카프카 토픽으로 가는 스트림 처리. 이메일·결제 호출처럼 카프카 밖의 부수 효과는 여전히 멱등 키가 필요하다 |

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic orders   # 파티션별 Leader, Replicas, Isr
kafka-console-producer.sh --bootstrap-server localhost:9092 --topic orders \
  --property parse.key=true --property key.separator=:        # 입력 예: order-42:created
kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic orders \
  --group shipping --from-beginning --property print.key=true --property print.partition=true
kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group shipping   # CURRENT-OFFSET, LOG-END-OFFSET, LAG
```
