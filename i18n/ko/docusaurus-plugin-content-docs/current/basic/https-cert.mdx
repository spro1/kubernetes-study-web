# HTTPS와 인증서

HTTPS 연결은 "상대가 정말 그 서버가 맞는가"를 인증서로 확인하는 데서 시작한다. 브라우저가 인증서를 어떻게 믿는지, 내부망에서 경고가 자주 뜨는 이유, 만료되면 어떤 일이 생기는지 따라가 본다.

## 경고·오류 원인별 할 일

| 보이는 증상 | 원인 | 할 일 |
| --- | --- | --- |
| "안전하지 않음" 경고 (내부망 첫 접속) | 사설 인증서라 발급 기관을 믿지 않음 | 회사 사설 CA를 PC 신뢰 목록에 등록 |
| 주소 불일치 경고 | 인증서의 도메인과 접속한 주소가 다름 (IP로 직접 접속 등) | 인증서에 적힌 도메인으로 접속 |
| 어느 날 갑자기 접속·통신 실패 | 인증서 만료 | 인증서 갱신. 갱신 자동화·만료 알림 마련 |
| 노드가 Harbor에서 이미지를 못 받음 | 노드가 Harbor의 사설 인증서를 믿지 않음 | 노드 신뢰 목록에 사설 인증서 등록 |

더 읽을거리: [인그레스 TLS (쿠버네티스 문서)](https://kubernetes.io/ko/docs/concepts/services-networking/ingress/#tls) · [kubeadm 인증서 관리](https://kubernetes.io/docs/tasks/administer-cluster/kubeadm/kubeadm-certs/) · [cert-manager](https://cert-manager.io/docs/)
