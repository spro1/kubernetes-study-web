# SSH 키로 서버에 들어가기까지

노트북에서 프라이빗 서브넷의 서버까지 로그인 한 번을 따라간다. 어느 키가 내가 누구인지 증명하고, 어느 키가 서버가 진짜임을 증명하는지, 배스천이 연결을 어떻게 이어 주는지, 클라우드에서는 무엇이 22번 포트를 대신하는지 본다.

## SSH 오류와 그 뜻

| 메시지 | 원인 | 고치는 법 |
|---|---|---|
| `Are you sure you want to continue connecting (yes/no...)?` | 처음 접속이라 호스트 키가 `known_hosts`에 없다 | 믿을 만한 곳에서 받은 지문과 비교한 뒤 yes |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` | 호스트 키가 `known_hosts`와 다르다: 서버 재구축, IP 재사용, 또는 중간자 | 주인이나 콘솔로 확인한 뒤 `ssh-keygen -R host` |
| `WARNING: UNPROTECTED PRIVATE KEY FILE!` | 개인 키를 남도 읽을 수 있다 | `chmod 600 ~/.ssh/id_ed25519` |
| `Permission denied (publickey)` | 사용자가 틀렸거나, 키가 `authorized_keys`에 없거나, 서버 쪽 권한이 틀렸거나, 엉뚱한 키를 냈다 | `ssh -v`, 서버 로그, 모드 700 / 600을 본다 |
| `Connection timed out` | 방화벽·보안 그룹이 22번을 막거나, 프라이빗 IP로 가는 길이 없다 | 규칙을 보거나, 배스천을 거치거나, SSM / IAP를 쓴다 |
| `Connection refused` | 호스트에는 닿지만 그 포트에서 듣는 프로세스가 없다 | sshd가 도는지, 다른 포트인지 본다 |
| `Host key verification failed.` | no라고 답했거나, 배치 모드가 모르는 호스트를 거부했다 | 확인한 키를 먼저 `known_hosts`에 넣는다 |

## 직접 확인해 보기

```bash
# 키 쌍 만들기 (패스프레이즈 포함) 와 확인
ssh-keygen -t ed25519 -C "you@laptop" -f ~/.ssh/id_ed25519
ssh-keygen -lf ~/.ssh/id_ed25519.pub         # 내 키의 지문
ls -l ~/.ssh                                 # 개인 키는 -rw------- 여야 한다

# 에이전트에 한 번 올리기
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
ssh-add -l

# 서버에 공개 키 넣기 (비밀번호는 이번이 마지막)
ssh-copy-id -i ~/.ssh/id_ed25519.pub dev@server.example.com

# 배스천 건너가기: 한 번만, 또는 ~/.ssh/config로
ssh -J dev@bastion.example.com dev@10.0.2.15
cat >> ~/.ssh/config <<'EOF'
Host app-server
  HostName 10.0.2.15
  User dev
  ProxyJump dev@bastion.example.com
EOF
ssh -v app-server                            # -v는 어떤 키를 냈고 왜 실패했는지 보여 준다

# 서버에서: 키만 허용
sudo sshd -t && sudo sshd -T | grep -Ei 'passwordauthentication|kbdinteractive|permitrootlogin'
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys

# 호스트 키가 바뀌었고, 정상임을 확인했다면
ssh-keygen -R server.example.com

# 클라우드, 22번 포트 없이
aws ssm start-session --target i-0123456789abcdef0
gcloud compute ssh my-vm --zone us-central1-a --tunnel-through-iap
```
