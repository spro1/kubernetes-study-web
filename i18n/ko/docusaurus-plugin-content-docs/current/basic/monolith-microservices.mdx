# 모놀리스, 모듈러 모놀리스, 마이크로서비스

쇼핑몰은 애플리케이션 하나로 시작한다. 커지면 누군가 서비스로 쪼개자고 한다. 같은 **결제(checkout)** 요청을 **모놀리스**, **모듈러 모놀리스**, **마이크로서비스**에서 차례로 따라가며, 쪼갤 때마다 무엇을 얻고 무엇을 치르는지 본다.

## 얻는 것과 치르는 것

| | 모놀리스 | 모듈러 모놀리스 | 마이크로서비스 |
|---|---|---|---|
| 배포 단위 | 하나 | 하나 | 서비스마다 하나 |
| 내부 호출 | 함수 호출 | 모듈 인터페이스를 거친 함수 호출 | 네트워크 호출(HTTP, gRPC, 이벤트) |
| 데이터 | DB 하나, 테이블 공유 | DB 하나, 모듈별 테이블 소유 | 서비스별 DB |
| 트랜잭션 | 전체에 걸친 로컬 트랜잭션 | 모듈에 걸친 로컬 트랜잭션 | 서비스 안에서만, 서비스 사이는 사가 |
| 확장 | 앱 전체 | 앱 전체 | 서비스마다 |
| 팀 독립성 | 낮음 | 중간 | 높음(데이터와 API가 나뉘어 있다면) |
| 디버깅 | 프로세스 하나, 로그 하나 | 프로세스 하나, 로그 하나 | 분산 추적 필요 |
| 운영 비용 | 낮음 | 낮음 | 높음: 서비스마다 파이프라인·대시보드·온콜 |

## 직접 확인해 보기

```bash
# 사슬의 가용성: 99.9%짜리 필수 서비스 5개
python3 -c 'print(round(0.999**5 * 100, 2), "%")'        # 약 99.5%

# 호출 10번이 필요한 요청이 1% 확률로 느린 호출을 한 번 이상 만날 확률
python3 -c 'print(round((1 - 0.99**10) * 100, 1), "%")'  # 약 9.6%

# 배포 단위는 몇 개이고, 각자 따로 나가는가?
kubectl get deploy -n shop
kubectl rollout history deploy/payments -n shop

# 서비스들이 DB를 공유하는가? 각자 받은 DB 호스트를 비교한다
kubectl get deploy -n shop -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.template.spec.containers[*].env[?(@.name=="DB_HOST")].value}{"\n"}{end}'

# 결제 한 번이 처음부터 끝까지 얼마나 걸리나?
curl -s -o /dev/null -w 'total %{time_total}s\n' https://shop.example.com/checkout
```
