# 가속기를 조건으로 받기 (DRA 심화)

쿠버네티스는 오랫동안 가속기를 "GPU 몇 장"으로만 나눠 줬다. **DRA(Dynamic Resource Allocation, 동적 리소스 할당)** 는 "어떤 조건의 장치를, 어떻게 나눠서"까지 적어 요청하는 방식이다. LLM 서빙에서는 GPU와 고속 네트워크 카드를 **함께** 받거나 GPU 한 장을 나눠 쓸 때 이 방식이 필요하다. DRA의 기본 흐름은 [조건으로 GPU 받기 (DRA)](../k8s/dra.mdx)에서 먼저 보고, 여기서는 할당량·여러 장치 묶음·대기 상황까지 이어서 본다.

## 기본 DRA 레슨과 달라진 점

| 구분 | 기본 흐름 | 이 레슨에서 더한 것 |
| --- | --- | --- |
| 요청 단위 | 파드 하나, 장치 하나 | Deployment 레플리카마다 요청서 하나 |
| 장치 묶음 | GPU 한 종류 | GPU와 네트워크 카드를 제약으로 맞춰 함께 |
| 배포 전 확인 | 없음 | ResourceQuota로 장치 수 상한, 필요하면 Kueue로 줄 세우기 |
| 대기 원인 | 조건 불일치 | 할당량 초과와 장치 부족을 구분해서 본다 |

더 읽을거리: [동적 리소스 할당](https://kubernetes.io/docs/concepts/resource-management/dynamic-resource-allocation/) · [리소스 쿼터](https://kubernetes.io/docs/concepts/policy/resource-quotas/) · [Kueue](https://kueue.sigs.k8s.io/docs/overview/)
