# 추론 API 요청이 응답을 받기까지

모델 서버가 준비되면 클라이언트는 OpenAI 호환 API로 모델을 부른다. 요청 하나가 **로드밸런서 → API 게이트웨이 → 라우팅 → 모델 서버**를 지나 돌아온다. 키가 틀리거나 한도를 넘은 요청이 어디서 걸러지는지도 함께 본다.

## 요청이 걸러지는 곳

| 상황 | 걸리는 곳 | 응답 |
| --- | --- | --- |
| 키 없음·틀린 키·폐기된 키 | API 게이트웨이 (인증 서비스) | 401 |
| 한도 초과 | API 게이트웨이 | 429 |
| 레플리카가 모두 바쁨 | 모델 서버 대기열 | 늦은 첫 토큰 |
| 게이트웨이 우회 | NetworkPolicy가 없으면 걸리지 않는다 | 그대로 통과 |

## 직접 확인해 보기

```bash
curl -s http://<게이트웨이>/v1/models -H "Authorization: Bearer $API_KEY"   # OpenAI 호환 API, 예: vLLM (2단계)
curl -s -o /dev/null -w '%{http_code}\n' http://<게이트웨이>/v1/models   # 키 없이: 401이어야 한다 (3단계)
curl -sN http://<게이트웨이>/v1/completions -H "Authorization: Bearer $API_KEY" -H 'Content-Type: application/json' -d '{"model":"<모델>","prompt":"Hello","max_tokens":32,"stream":true}'   # 토큰이 흘러 돌아온다 (7단계)
kubectl get networkpolicy -n <네임스페이스>             # 모델 파드에는 게이트웨이만 닿는지 (4단계)
curl -s http://<엔진>:8000/metrics | grep -E 'vllm:(num_requests_waiting|time_to_first_token_seconds)'   # 레플리카 대기열과 TTFT
```
