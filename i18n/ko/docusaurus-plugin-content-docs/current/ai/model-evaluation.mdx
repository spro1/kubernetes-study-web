# 배포 전후에 모델 평가하기

새 모델, 프롬프트, 양자화는 채팅 몇 번에서는 멀쩡해 보여도 실제 업무에서 깨질 수 있다. 평가는 "괜찮아 보인다"를 비교할 수 있는 숫자로 바꾼다. 배포 전에는 오프라인으로, 배포 뒤에는 실제 트래픽으로 잰다.

## 어떤 일에 어떤 평가를 쓰나

| 방법 | 잘 맞는 곳 | 주의할 점 |
|---|---|---|
| 정확 일치 | 짧은 답, 라벨, ID | 대소문자·공백·문장부호를 먼저 정규화한다 |
| pass@k | 단위 테스트가 있는 코드 | 사용자가 보는 것은 pass@1이다. 테스트가 튼튼해야 한다 |
| 형식 검사 | JSON, 도구 호출, 스키마 | 형식이 맞아도 내용이 맞는 것은 아니다 |
| LLM 심판 | 요약, 답변, 열린 답 | 위치·길이·자기 선호 편향. 사람으로 보정한다 |
| 사람 검토 | 작은 표본, 새 업무, 심판 보정 | 느리고 비싸다. 기준을 분명히 한다 |
| 안전·거절 평가 | 해로운 요청 거절, 멀쩡한 요청 응답 | 지나친 거절과 모자란 거절을 함께 본다 |
| 온라인 카나리·A/B | 실제 트래픽, 실제 지연 | 트래픽이 충분해야 하고 자동 되돌리기가 필요하다 |

## 직접 확인해 보기

```bash
# 기준 모델과 후보에 같은 평가를 돌린다 (둘 다 OpenAI 호환 API로 서빙)
lm_eval --model local-completions --tasks gsm8k \
  --model_args model=chat-model,base_url=http://baseline:8000/v1/completions \
  --output_path results/baseline --log_samples
lm_eval --model local-completions --tasks gsm8k \
  --model_args model=chat-model,base_url=http://candidate:8000/v1/completions \
  --output_path results/candidate --log_samples

# 점수를 나란히 비교한다
find results -name 'results_*.json' -exec jq -c '{file: input_filename, results}' {} \;

# 온라인 카나리를 지켜본다 (Argo Rollouts로 배포한다면)
kubectl argo rollouts get rollout chat-model -n llm --watch
```
