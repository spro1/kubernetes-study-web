# GPU 사이에서 데이터가 오가는 길

분산 학습은 매 스텝마다 멈춰서 그래디언트를 주고받는다. 그래서 GPU 사이의 네트워크가 전체 속도를 정한다. GPU 하나에서 다른 GPU로 가는 데이터를 노드 안에서, 그다음 노드 사이에서 따라가고, 쿠버네티스가 RDMA NIC를 파드에 어떻게 넘겨주는지 본다.

## 증상과 원인

| 증상 | 그럴듯한 원인 | 확인할 것 |
|---|---|---|
| NCCL 로그에 `NET/Socket` | 파드에 RDMA 장치가 없거나 `NCCL_IB_DISABLE=1` | 파드 안의 `ibv_devinfo`, 리소스 요청, Multus 어노테이션 |
| RDMA 장치는 있는데 NCCL이 메모리 등록에 실패 | 메모리를 고정할 수 없다 | `IPC_LOCK` 권한, 컨테이너 안의 `ulimit -l` |
| `NET/IB`인데 `GDRDMA`가 없다 | GPUDirect RDMA가 꺼져 있거나 GPU와 NIC가 멀다 | nvidia-peermem 또는 DMA-BUF 지원, `nvidia-smi topo -m` |
| RoCE가 부하가 낮을 땐 되다가 규모가 커지면 무너진다 | PFC나 ECN이 모든 구간에서 같지 않다 | NIC·스위치의 pause·ECN 카운터 |
| RoCE 연결이 실패하거나 멈춘다 | GID 인덱스나 RoCE 버전이 틀렸다 | `NCCL_IB_GID_INDEX`, 장치의 GID 테이블 |
| 노드 안 all-reduce가 느리다 | NVLink 경로가 없고 트래픽이 소켓을 넘는다 | `nvidia-smi topo -m`, `nvidia-smi nvlink --status` |
| 느린 노드 하나가 작업 전체를 끌어내린다 | 불량 케이블, 낮은 속도로 링크가 잡힘, 상한 포트 | `ibstat`이나 `ethtool`의 링크 속도, 노드별 all_reduce_perf |

## 직접 확인해 보기

```bash
nvidia-smi topo -m                 # NV# = NVLink, PIX/PXB = 같은 PCIe 스위치, SYS = CPU 소켓을 넘음
ibv_devinfo                        # RDMA 장치, state PORT_ACTIVE, link_layer InfiniBand 또는 Ethernet
kubectl get network-attachment-definitions -A          # Multus가 붙일 수 있는 보조 네트워크
kubectl get node gpu-node-1 -o jsonpath='{.status.allocatable}'   # GPU와 RDMA 리소스
kubectl exec trainer-0 -- ip -br addr                  # 기본 CNI의 eth0, Multus의 net1

# 두 파드 사이 RDMA 대역폭(perftest), 양쪽 모두 GPU 메모리 사용
kubectl exec trainer-0 -- ib_write_bw -d mlx5_0 --use_cuda=0 -a              # 서버
kubectl exec trainer-1 -- ib_write_bw -d mlx5_0 --use_cuda=0 -a 10.10.0.11   # 클라이언트, 서버의 net1 IP

# 노드 2대 x GPU 8개 NCCL all-reduce (MPI=1로 빌드한 nccl-tests)
mpirun -np 16 -N 8 -x NCCL_DEBUG=INFO -x NCCL_DEBUG_SUBSYS=INIT,NET \
  ./build/all_reduce_perf -b 8 -e 8G -f 2 -g 1 2>&1 | grep -E 'NET/|busbw|GDRDMA'
```
