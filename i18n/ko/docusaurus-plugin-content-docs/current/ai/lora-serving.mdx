# 베이스 모델 하나로 LoRA 어댑터 여러 개 서빙하기

## vLLM LoRA 설정

| 플래그·설정 | 정하는 것 | 주의할 점 |
|---|---|---|
| `--enable-lora` | 어댑터 기능 켜기 | 없으면 어댑터 모델 이름을 모른다 |
| `--lora-modules 이름=경로` | 시작할 때 등록하는 어댑터 | 이 이름이 클라이언트가 보내는 `model`이다 |
| `--max-loras` | 한 배치에 들어가는 서로 다른 어댑터 수 상한 (기본값 1) | 슬롯마다 GPU 메모리를 잡아 KV 캐시가 줄어든다 |
| `--max-lora-rank` | 받아들이는 가장 큰 어댑터 랭크 (기본값 16) | 서빙할 가장 큰 랭크에 맞춘다. 더 크면 메모리 낭비다 |
| `--max-cpu-loras` | 호스트 메모리에 두는 어댑터 수 | `--max-loras` 이상이어야 한다. 없으면 디스크나 저장소에서 읽는다 |
| `VLLM_ALLOW_RUNTIME_LORA_UPDATING=True` | `/v1/load_lora_adapter`, `/v1/unload_lora_adapter` 켜기 | 호출자가 파일을 올릴 수 있으니 믿을 수 있는 망에서만 쓴다 |

| 증상 | 흔한 원인 | 해결 |
|---|---|---|
| 일부 어댑터에서만 지연이 튄다 | 요청 때마다 어댑터를 바꿔 끼움 | GPU 슬롯·CPU 캐시 늘리기, 어댑터 친화 라우팅 |
| 어댑터가 올라가지 않는다 | 랭크가 `--max-lora-rank`보다 크거나, 다른 베이스로 학습함 | 상한을 올리거나 서빙 중인 베이스로 다시 학습 |
| 같은 프롬프트인데 레플리카마다 답이 다르다 | 어댑터 이름 하나에 파일 버전이 여럿 | `sql-lora-v3`처럼 바뀌지 않는 이름 |

## 직접 확인해 보기

```bash
# 베이스 모델을 띄우면서 어댑터 하나를 등록한다
vllm serve meta-llama/Llama-3.2-3B-Instruct --enable-lora \
  --lora-modules sql-lora=jeeejeee/llama32-3b-text2sql-spider \
  --max-loras 4 --max-lora-rank 64 --max-cpu-loras 8

curl -s localhost:8000/v1/models | jq '.data[] | {id, parent}'   # 어댑터는 parent = 베이스 모델로 보인다

# 모델 이름으로 어댑터를 고른다
curl -s localhost:8000/v1/completions -H 'Content-Type: application/json' \
  -d '{"model": "sql-lora", "prompt": "List all users older than 30 in SQL:", "max_tokens": 64}'

# 동적 로딩 (VLLM_ALLOW_RUNTIME_LORA_UPDATING=True로 띄운 서버, 믿을 수 있는 망에서만)
curl -s -X POST localhost:8000/v1/load_lora_adapter -H 'Content-Type: application/json' \
  -d '{"lora_name": "sql-lora-v3", "lora_path": "/adapters/sql-lora-v3"}'
curl -s -X POST localhost:8000/v1/unload_lora_adapter -H 'Content-Type: application/json' \
  -d '{"lora_name": "sql-lora"}'

curl -s localhost:8000/metrics | grep vllm:lora_requests_info   # 실행 중·대기 중인 어댑터
```
