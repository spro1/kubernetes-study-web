# 모델이 처음 뜨기까지 (콜드 스타트)

일반 웹 서비스의 파드는 몇 초면 뜬다. LLM 레플리카는 수십 GB가 넘는 **모델 가중치**를 읽어 가속기 메모리에 올리고 엔진을 준비해야 해서 몇 분씩 걸리기도 한다. 이처럼 레플리카가 처음 기동해 첫 요청을 받을 수 있게 되기까지의 시간을 **콜드 스타트**라고 한다. 파드가 뜨는 일반 과정은 [파드가 뜨기까지](../k8s/pod-startup.mdx)에 있으니, 여기서는 LLM이라서 길어지는 부분에 집중한다.

## 단계별로 볼 것과 줄이는 방법

| 단계 | 확인할 곳 | 줄이는 방법 |
| --- | --- | --- |
| 이미지 받기 | 파드 이벤트(Pulling, Pulled) | 이미지 미리 받기, 가까운 레지스트리 |
| 가중치 받기 | 엔진 로그, 네트워크 사용량 | 모델 로컬 캐시 |
| 가속기 적재 | 엔진 로그의 적재 시간 | NVMe, GPUDirect Storage |
| 엔진 준비 | 엔진 로그의 준비 시간 | 컴파일 캐시 재사용, 미리 컴파일 |

## 직접 확인해 보기

```bash
kubectl get pod <파드> -w                             # Pending → ContainerCreating → Running → Ready
kubectl get events -n <네임스페이스> --field-selector involvedObject.name=<파드>   # 이미지 Pulling/Pulled 시간 (2단계)
kubectl logs -f <파드>                                # 가중치 적재·준비 시간 (3~5단계)
kubectl get pod <파드> -o jsonpath='{.spec.containers[*].startupProbe}'   # 기동 프로브가 적재 시간을 덮는지 (6단계)
kubectl get pod <파드> -o jsonpath='{.status.containerStatuses[*].restartCount}'   # 재시작이 있으면 활성 프로브가 적재를 끊은 것
curl -s -o /dev/null -w '%{http_code}\n' http://<엔진>:8000/health   # 예: vLLM. 엔진이 준비되면 200
```
