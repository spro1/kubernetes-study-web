# 쿠버네티스에서 GPU 모니터링

GPU 노드는 비싸다. 그리고 파드가 모두 Running이어도 GPU는 바쁘거나, 놀거나, 과열되거나, 고장 나 있을 수 있다. GPU 지표를 카드에서 Prometheus까지 따라가고, 어떤 숫자가 실제 일을 보여 주는지, 어떤 오류가 노드를 비워야 한다는 뜻인지 본다.

## 주요 DCGM 지표

DCGM 익스포터 4.9는 기본 지표 상당수를 DCGM 4.7 이름으로 바꾸고 일부 단위도 바꿨다(예: 퍼센트 → 0~1 비율, MiB → 바이트). 쓰는 익스포터 버전에 맞는 열을 본다.

| 익스포터 4.8까지 | 익스포터 4.9부터 | 알려 주는 것 | 쓰는 곳 |
|---|---|---|---|
| `DCGM_FI_DEV_GPU_UTIL` (%) | `DCGM_FI_DEV_GPU_UTIL_RATIO` | 커널이 하나라도 돈 시간 | 바쁜가 노는가, 얼마나 찼는지는 아님 |
| `DCGM_FI_PROF_SM_ACTIVE` | `DCGM_FI_PROF_SM_UTIL_RATIO` | SM에 일이 있던 사이클 비율 | 실제 연산 사용량 (기본 꺼짐) |
| `DCGM_FI_PROF_SM_OCCUPANCY` | `DCGM_FI_PROF_SM_OCCUPANCY_RATIO` | 최대 대비 상주 워프 | 커널 튜닝 (기본 꺼짐) |
| `DCGM_FI_PROF_PIPE_TENSOR_ACTIVE` | `DCGM_FI_PROF_TENSOR_UTIL_RATIO` | 텐서 코어 활동 | 학습·추론의 행렬 연산 |
| `DCGM_FI_PROF_DRAM_ACTIVE` | `DCGM_FI_PROF_DRAM_UTIL_RATIO` | 메모리 대역폭 활동 | 디코딩처럼 메모리에 묶인 작업 |
| `DCGM_FI_DEV_FB_USED` / `_FREE` (MiB) | `DCGM_FI_DEV_FB_USED_BYTES` / `_FREE_BYTES` | GPU 메모리 | 학습의 메모리 부족 위험 |
| `DCGM_FI_DEV_POWER_USAGE` | `DCGM_FI_DEV_BOARD_POWER_WATTS` | 소비 전력 | 전력 한도 스로틀링 |
| `DCGM_FI_DEV_GPU_TEMP` | `DCGM_FI_DEV_GPU_TEMP_CELSIUS` | GPU 온도 | 냉각 문제 |
| `DCGM_FI_DEV_SM_CLOCK` (MHz) | `DCGM_FI_DEV_SM_CLOCK_HERTZ` | 현재 SM 클럭 | 느려짐 감지 |
| `DCGM_FI_DEV_XID_ERRORS` | `DCGM_FI_DEV_XID_ERROR` | 마지막 XID 오류 값 | 하드웨어 결함 알람 |
| `DCGM_FI_DEV_UNCORRECTABLE_REMAPPED_ROWS` | `DCGM_FI_DEV_ROW_REMAP_UNCORRECTABLE_TOTAL` | 고칠 수 없는 오류로 재매핑된 행 | 비우고 리셋 |
| `DCGM_FI_DEV_ROW_REMAP_FAILURE` | `DCGM_FI_DEV_ROW_REMAP_FAILED` | 재매핑 실패 | GPU 교체 |

흔한 XID와 보통의 대응(GPU와 드라이버에 맞는 NVIDIA XID 카탈로그를 확인한다):

| XID | 뜻 | 보통의 대응 |
|---|---|---|
| 79 | GPU가 버스에서 떨어졌다 | cordon, drain, 리셋이나 재부팅. 반복되면 보고 |
| 48 | 2비트(고칠 수 없는) ECC 오류 | 영향받은 작업 재시작. 재매핑이 뒤따르면 비우고 리셋 |
| 13, 31, 43 | 대개 애플리케이션 결함(잘못된 커널, 잘못된 주소) | 먼저 애플리케이션을 본다. GPU가 멀쩡하면 노드 조치는 필요 없다 |

## 직접 확인해 보기

```bash
# 모든 GPU 노드에 익스포터가 떠 있나?
kubectl get daemonset -A | grep -i dcgm

# 원시 지표 읽기 (GPU Operator의 서비스 이름. 네임스페이스와 이름은 환경에 맞춘다)
kubectl -n gpu-operator port-forward svc/nvidia-dcgm-exporter 9400:9400 &
curl -s localhost:9400/metrics | grep -E '^DCGM_FI_(DEV_GPU_UTIL|PROF_)' | head
curl -s localhost:9400/metrics | grep -E 'XID|REMAP'       # 오류와 행 재매핑

# 시계열에 pod 레이블이 붙어 있나?
curl -s localhost:9400/metrics | grep -m3 'pod="'

# 노드에서: 커널 로그의 XID와 GPU 자체 정보
sudo dmesg | grep -i xid
nvidia-smi -q -d ECC,ROW_REMAPPER

# 고장 난 GPU 노드를 서비스에서 빼기
kubectl cordon gpu-node-1
kubectl drain gpu-node-1 --ignore-daemonsets --delete-emptydir-data
```
