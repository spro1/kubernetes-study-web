# 모델 하나를 여러 GPU로 학습하기

## 병렬 방식 고르기

| 방식 | GPU마다 가지는 것 | 통신 | 쓸 때 |
| --- | --- | --- | --- |
| DDP (데이터 병렬) | 모델 전체, 그래디언트, 옵티마이저 상태 | 스텝마다 그래디언트 all-reduce 한 번 | 모델과 옵티마이저 상태가 GPU 한 장에 들어갈 때 |
| ZeRO-1 / ZeRO-2 | 가중치 전체, 옵티마이저 상태(와 그래디언트)의 조각 | DDP와 거의 같음 | 옵티마이저 상태가 들어가지 않을 때 |
| FSDP / ZeRO-3 | 가중치·그래디언트·옵티마이저 상태의 조각 | 가중치 all-gather, 그래디언트 reduce-scatter, DDP의 약 1.5배 | 가중치와 상태를 합치면 GPU 한 장에 들어가지 않을 때 |
| 텐서 병렬 | 모든 레이어의 일부 | 레이어마다 집합 통신 | 레이어가 너무 클 때. NVLink로 묶인 한 노드 안에 둔다 |
| 파이프라인 병렬 | 레이어 구간 | 스테이지 사이 활성값 | 모델이 한 노드에 비해 너무 깊을 때. 마이크로 배치가 필요하다 |

## 직접 확인해 보기

```bash
kubectl get clustertrainingruntimes                       # TrainJob이 쓸 수 있는 런타임, 예: torch-distributed
kubectl get trainjobs -n <namespace>                      # Kubeflow Trainer v2 작업
kubectl get jobset -n <namespace>                         # TrainJob이 만든 JobSet
kubectl get pods -n <namespace> -l jobset.sigs.k8s.io/jobset-name=<trainjob> -o wide   # 노드마다 파드 하나
kubectl logs -n <namespace> <pod> | grep -E "NCCL INFO|rank"   # NCCL_DEBUG=INFO일 때: 전송 방식과 링
kubectl exec -n <namespace> <pod> -- nvidia-smi topo -m   # 노드 안 GPU 사이가 NVLink인지 PCIe인지
# 컨테이너 안: GPU마다 프로세스 하나, 노드 2대, rank 0 파드에서 랑데부
torchrun --nnodes=2 --nproc-per-node=2 --rdzv-backend=c10d --rdzv-endpoint=<rank0-host>:29400 --rdzv-id=run1 train.py
```
