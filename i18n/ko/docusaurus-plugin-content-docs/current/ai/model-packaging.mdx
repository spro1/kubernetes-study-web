# 모델이 배포 가능해지기까지

Hugging Face에 모델이 있다고 서빙 Pod가 곧장 빨리 뜨지는 않는다. 수십~수백 GB의 가중치를 **가져오고 → 배포용으로 포장하고 → GPU 노드에 미리 내려받아** 두어야 한다. 각 단계가 무엇을 하고 어디에 무엇을 남기는지 따라가 본다.

## 모델 파일을 두는 방법 비교

| | 시작할 때 원본에서 받기 | PVC에 풀어 두기 | OCI 아티팩트 + 노드 캐시 |
| --- | --- | --- | --- |
| 첫 기동 시간 | 매번 길다 | 볼륨 성능에 달렸다 | 캐시가 있으면 짧다 |
| 버전 관리 | 리비전 고정에 달렸다 | 경로 규칙으로 직접 관리 | 태그·다이제스트 |
| 신경 쓸 것 | 외부 네트워크, 토큰 | 여러 노드에서 읽을 수 있는 스토리지 | 노드 디스크 용량, 이미지 GC |

## 직접 확인해 보기

```bash
kubectl get jobs -n <네임스페이스>                      # 가져오기·빌드 Job 진행 (2·5단계)
kubectl get job <이름> -n <네임스페이스> -o jsonpath='{.spec.backoffLimit} {.spec.activeDeadlineSeconds}'   # 재시도 횟수와 시간 제한
kubectl get daemonsets -A -o wide                    # GPU 노드에 미리 받기 DaemonSet이 떴는지 (7단계)
kubectl describe pod <파드> | grep -iE 'pulling|pulled'   # 모델 받는 시간 (8단계)
crictl images                                        # 노드에서 캐시가 있는지
```
