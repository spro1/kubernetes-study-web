# 클러스터 밖으로 나가는 트래픽 (이그레스)

결제 파드가 알려진 출발지 IP만 받는 파트너 API를 부른다. 패킷이 클러스터를 나가는 길을 따라간다. **파드 → 노드 SNAT → NAT 게이트웨이 → 파트너** 순서다. 그다음 정책으로 이그레스를 막고, 트래픽에 고정 출발지 IP를 준다.

## 이그레스를 통제하는 방법

| 필요 | 도구 | 고르는 기준 | 한계 |
| --- | --- | --- | --- |
| 모두 막고 몇 길만 열기 | 네트워크 정책 이그레스 | 파드·네임스페이스 레이블, ipBlock CIDR, 포트 | 호스트 이름 없음. CNI가 정책을 지원해야 적용됨 |
| 호스트 이름으로 허용 | CNI 확장, 예: Cilium `toFQDNs` | DNS 응답에서 알아낸 이름 | CNI 전용 CRD. 파드가 클러스터 DNS 경로로 이름을 물어야 함 |
| 일부 파드에 고정 출발지 IP | 이그레스 게이트웨이, 예: Cilium Egress Gateway | 고른 파드와 목적지 CIDR | 게이트웨이 노드에 의존. 특정 CNI 기능 필요 |
| 선언한 외부 호스트만, L7 가시성 | 서비스 메시, 예: Istio `REGISTRY_ONLY` + ServiceEntry + 이그레스 게이트웨이 | 호스트 이름, 포트, 프로토콜 | 사이드카·프록시는 우회 가능. 네트워크 정책과 함께 씀 |
| VPC 전체에 공인 IP 하나 | 클라우드 NAT 게이트웨이 | 라우팅 테이블 | 모든 워크로드가 IP를 공유 |

## 직접 확인해 보기

```bash
# 바깥에서는 어떤 출발지 IP가 보이나?
kubectl run egress-test --rm -it --image=curlimages/curl --restart=Never -- curl -s https://ifconfig.me
kubectl get networkpolicy -n <namespace>                      # 어떤 정책이 있고 POD-SELECTOR는 무엇인지
kubectl describe networkpolicy <name> -n <namespace>          # 허용된 이그레스: 포트와 ipBlock
kubectl get pods -n kube-system -l k8s-app=kube-dns --show-labels   # DNS 규칙이 골라야 할 레이블
kubectl get ciliumnetworkpolicy -A                            # Cilium: toFQDNs 규칙
kubectl get ciliumegressgatewaypolicy                         # Cilium: 이그레스 게이트웨이 정책 (클러스터 범위)
hubble observe --verdict DROPPED --traffic-direction egress   # Cilium Hubble: 막힌 나가는 흐름
kubectl get serviceentry -A                                   # Istio: 선언된 외부 호스트
```
