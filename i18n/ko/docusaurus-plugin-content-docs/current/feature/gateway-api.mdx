# 게이트웨이 API HTTPRoute가 파드에 닿기까지

요청 하나를 게이트웨이 API로 따라간다. **GatewayClass → Gateway → HTTPRoute → 서비스 → 파드** 순서다. 경로(HTTPRoute)가 리스너에 어떻게 붙는지, 붙지 않을 때 `status.parents`가 무엇을 말하는지 본다.

## status.parents 읽기

HTTPRoute의 `status.parents` 항목 하나는 `parentRef` 하나에 대응하고, 그 Gateway의 컨트롤러가 쓴 조건을 담는다.

| 조건 | reason | 뜻 | 고치는 법 |
|---|---|---|---|
| Accepted=True | Accepted | Gateway가 경로를 받았다 | — |
| Accepted=False | NotAllowedByListeners | 어느 리스너의 `allowedRoutes`도 이 경로(네임스페이스·종류)를 허용하지 않는다 | 리스너의 `allowedRoutes`를 바꾸거나, 경로의 네임스페이스에 셀렉터와 맞는 레이블을 단다 |
| Accepted=False | NoMatchingListenerHostname | 경로의 `hostnames`와 맞는 리스너 호스트가 없다 | 경로 호스트를 리스너 호스트(예: `*.example.com`)에 맞춘다 |
| Accepted=False | NoMatchingParent | parentRef의 `sectionName`이나 `port`와 맞는 리스너가 없다 | 있는 리스너를 가리키도록 parentRef를 고친다 |
| Accepted=Unknown | Pending | 컨트롤러가 아직 경로를 처리하지 않았다 | GatewayClass가 Accepted인지, 컨트롤러가 살아 있는지 본다 |
| ResolvedRefs=True | ResolvedRefs | 모든 backendRef를 찾았다 | — |
| ResolvedRefs=False | RefNotPermitted | backendRef가 ReferenceGrant 없이 다른 네임스페이스를 가리킨다 | 대상 네임스페이스에 ReferenceGrant를 만든다 |
| ResolvedRefs=False | BackendNotFound | 가리킨 서비스가 없다 | 이름·네임스페이스·포트를 고치거나 서비스를 만든다 |
| ResolvedRefs=False | InvalidKind | backendRef의 group이나 kind를 모르거나 지원하지 않는다 | 서비스나 구현체가 지원하는 종류를 가리킨다 |

`status.parents`가 비어 있으면 어느 컨트롤러도 경로를 처리하지 않은 것이다. parentRef의 이름·네임스페이스와 GatewayClass를 확인한다.

## 직접 확인해 보기

```bash
kubectl get gatewayclass                             # CONTROLLER와 ACCEPTED
kubectl get gateway -A                               # CLASS, ADDRESS, PROGRAMMED
kubectl describe gateway infra-gw -n infra           # 리스너, allowedRoutes, attachedRoutes
kubectl get httproute -A                             # 경로별 HOSTNAMES
kubectl get httproute store -n shop \
  -o jsonpath='{range .status.parents[*].conditions[*]}{.type}={.status} {.reason}{"\n"}{end}'   # Accepted / ResolvedRefs
kubectl get referencegrant -A                        # 다른 네임스페이스 참조를 누가 허락했는지
```
