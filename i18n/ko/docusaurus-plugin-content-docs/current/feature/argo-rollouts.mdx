# Argo Rollouts로 점진적 배포하기

보통 디플로이먼트는 파드를 바꾸고 잘되기를 바랄 뿐이다. **Rollout**이 새 버전에 트래픽을 조금씩 늘려 보내고, 단계마다 Prometheus에서 성공률을 확인하고, 확인에 실패하면 스스로 중단하는 과정을 따라간다.

## 카나리냐 블루/그린이냐, 그리고 명령

| | 카나리 | 블루/그린 |
|---|---|---|
| 트래픽이 옮겨 가는 방식 | 단계마다(`setWeight`), 파드 수나 트래픽 라우터로 | active 셀렉터가 바뀔 때 한꺼번에 |
| 추가 용량 | 카나리 파드만(라우터를 쓰면 안정 버전은 다 떠 있음) | `scaleDownDelaySeconds`가 지날 때까지 한 벌 더 |
| 사용자보다 먼저 시험 | 실제 사용자 일부 | `previewService`와 `prePromotionAnalysis` |
| 자동 확인 | 배경 분석이나 `analysis` 단계 | `prePromotionAnalysis`, `postPromotionAnalysis` |
| 정확한 비율 | `trafficRouting`이 필요(인그레스, 메시, 게이트웨이 API 플러그인) | 필요 없음 |

| 명령 | 하는 일 |
|---|---|
| `kubectl argo rollouts get rollout web --watch` | 단계, 비중, ReplicaSet, AnalysisRun을 실시간으로 |
| `kubectl argo rollouts promote web` | 지금의 멈춤을 풀고 다음 단계로 |
| `kubectl argo rollouts promote web --full` | 남은 단계, 멈춤, 분석을 모두 건너뜀 |
| `kubectl argo rollouts abort web` | 트래픽을 안정 버전으로 돌리고 멈춤. 스펙은 바꾸지 않음 |
| `kubectl argo rollouts retry rollout web` | 중단된 Rollout을 같은 스펙으로 다시 시작 |
| `kubectl argo rollouts undo web` | 템플릿을 이전 리비전으로 되돌림 |

## 직접 확인해 보기

```bash
kubectl create namespace argo-rollouts
kubectl apply -n argo-rollouts -f https://github.com/argoproj/argo-rollouts/releases/latest/download/install.yaml
kubectl apply -f https://raw.githubusercontent.com/argoproj/argo-rollouts/master/docs/getting-started/basic/rollout.yaml   # 예제 Rollout (레플리카 5)
kubectl apply -f https://raw.githubusercontent.com/argoproj/argo-rollouts/master/docs/getting-started/basic/service.yaml
kubectl argo rollouts get rollout rollouts-demo --watch          # 다른 터미널에 띄워 둔다
kubectl argo rollouts set image rollouts-demo rollouts-demo=argoproj/rollouts-demo:yellow   # 카나리 시작
kubectl argo rollouts promote rollouts-demo                      # 끝없는 멈춤을 푼다
kubectl argo rollouts set image rollouts-demo rollouts-demo=argoproj/rollouts-demo:red
kubectl argo rollouts abort rollouts-demo                        # 안정 버전으로, 상태 Degraded
kubectl get analysisrun                                          # Rollout이 분석을 쓴다면 결과
```
