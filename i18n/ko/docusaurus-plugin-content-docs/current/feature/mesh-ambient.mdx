# 서비스 메시 ④ 사이드카 없는 앰비언트 모드

앰비언트 모드는 메시 프록시를 파드 밖으로 뺀다. 노드마다 하나씩 도는 **ztunnel**이 L4에서 mTLS와 신원을 맡고, 필요한 곳에만 **웨이포인트** 프록시를 두어 L7 기능을 더한다. ztunnel만으로 되는 것과, 조용히 안 되는 것을 본다.

## 어디서 무엇이 도는가

| 기능 | 사이드카 모드 | 앰비언트, ztunnel만 | 앰비언트 + 웨이포인트 |
|---|---|---|---|
| 메시에 넣기 | 주입 레이블 후 파드 재시작 | `istio.io/dataplane-mode=ambient`, 재시작 없음 | 같음, 여기에 `istio.io/use-waypoint` |
| mTLS와 워크로드 신원 | 사이드카 | ztunnel (HBONE, 포트 15008) | ztunnel |
| principal·네임스페이스·포트를 보는 AuthorizationPolicy | 사이드카 | ztunnel | ztunnel 또는 웨이포인트 |
| 메서드·경로·헤더를 보는 AuthorizationPolicy | 사이드카 | 적용 안 됨: ALLOW는 전부 거부, DENY는 아무것도 못 막음 | 웨이포인트, `targetRefs`로 붙임 |
| HTTPRoute, 재시도, 타임아웃, 헤더 라우팅 | 사이드카 | 무시됨 | 웨이포인트 |
| VirtualService | 사이드카 | 무시됨 | 웨이포인트 (Alpha) |
| 지표 | L4와 L7 | L4(TCP)만 | L4와 L7 |
| 프록시 수 | 파드마다 하나 | 노드마다 하나 | 노드마다 하나 + 웨이포인트 |

## 직접 확인해 보기

```bash
kubectl label namespace shop istio.io/dataplane-mode=ambient   # 네임스페이스를 메시에 넣기
kubectl get pods -n shop                                       # 여전히 READY 1/1, 재시작 없음
kubectl get daemonset ztunnel -n istio-system                  # 노드마다 ztunnel 하나
istioctl ztunnel-config workloads                              # 메시 파드는 PROTOCOL HBONE
kubectl logs -n istio-system -l app=ztunnel | grep -E "inbound|outbound"   # 연결과 신원
istioctl waypoint apply -n shop --enroll-namespace             # 웨이포인트를 만들고 네임스페이스에 레이블
kubectl get gateways.gateway.networking.k8s.io -n shop        # waypoint, 클래스 istio-waypoint, PROGRAMMED
kubectl get namespace shop -L istio.io/dataplane-mode,istio.io/use-waypoint   # 어떤 레이블이 붙었는지
```
