# Scaling on Events with KEDA

A queue consumer can sit at low CPU while thousands of messages wait. Follow **KEDA** as it reads the backlog, drives an HPA, scales to zero and back, and decides what to do when it cannot reach the queue.

## ScaledObject fields that change behavior

| Field | Default | What it controls |
|---|---|---|
| `minReplicaCount` | 0 | Lowest replica count. Above 0, the activation threshold is ignored |
| `maxReplicaCount` | 100 | Highest replica count passed to the HPA |
| `pollingInterval` | 30 s | How often the operator checks each trigger |
| `cooldownPeriod` | 300 s | Wait after the last active trigger before going to 0. Only for 1 → 0 |
| `initialCooldownPeriod` | 0 s | Wait after creation before the first scale to 0 |
| `idleReplicaCount` | unset | Replicas when no trigger is active (only 0 is supported, and it must be below `minReplicaCount`) |
| `fallback.failureThreshold` / `fallback.replicas` | none | After this many failed polls, scale to this count |
| `advanced.horizontalPodAutoscalerConfig.behavior` | HPA defaults | Scale-up and scale-down speed for 1 ↔ N |
| trigger `activation…` (e.g. `activationLagThreshold`) | 0 | Metric must be above this to wake from 0 |

## Try it yourself

```bash
kubectl get scaledobject -A                          # READY, ACTIVE, FALLBACK, TRIGGERS
kubectl describe scaledobject orders                 # Conditions and events from the operator
kubectl get hpa keda-hpa-orders                      # The HPA KEDA created
kubectl describe hpa keda-hpa-orders                 # Current external metric value and scaling events
kubectl get --raw "/apis/external.metrics.k8s.io/v1beta1" | head -c 400   # KEDA metrics server is registered
kubectl get triggerauthentication,clustertriggerauthentication -A
kubectl get scaledjob,jobs -A                        # ScaledJob and the Jobs it created
kubectl logs -n keda deploy/keda-operator | tail     # Scaler errors (adjust namespace to your install)
```
