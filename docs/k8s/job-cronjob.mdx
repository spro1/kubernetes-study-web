# Run Once and Finish (Job · CronJob)

A program that builds a monthly report does not need to stay up. It just needs to run once and finish. Follow the Job that handles this kind of work, and the CronJob that stamps out Jobs on a schedule.

## Concurrency policy at a glance

| `concurrencyPolicy` | When the previous run is still going | Good for |
| --- | --- | --- |
| `Allow` (default) | Creates a new Job that runs alongside | Runs that do not affect each other |
| `Forbid` | Skips this scheduled run | Work on the same data that must not overlap |
| `Replace` | Deletes the running Job and starts a new one | Work where only the latest run matters |

## Try it yourself

```bash
kubectl get cronjob -A                               # SCHEDULE and LAST SCHEDULE
kubectl create job try-job --image=busybox -- sh -c 'echo done'   # Throwaway Job
kubectl get job try-job                              # COMPLETIONS reaches 1/1
kubectl logs job/try-job                             # Logs live in the Job's Pod
kubectl delete job try-job                           # Clean up (deletes its Pod too)
```
