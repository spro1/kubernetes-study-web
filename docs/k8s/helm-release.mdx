## Reading release status

`helm status shop` and `helm history shop` show one status per revision.

| Status | Meaning | What to do |
|---|---|---|
| deployed | The current revision. Its objects were accepted by the API server | Still check the Pods: without `--wait`, deployed does not mean ready |
| superseded | An older revision that was replaced | Nothing. It is history you can roll back to |
| failed | The apply was rejected, a hook failed, or `--wait` timed out | Read `helm history` and the Pods' events, fix the values, upgrade again or roll back |
| pending-install / pending-upgrade / pending-rollback | An operation started and did not finish (for example, the CLI was killed) | New operations fail with "another operation is in progress". Roll back to the last good revision |
| uninstalled | Removed with `helm uninstall --keep-history` | `helm rollback` can bring it back |

## Try it yourself

```bash
helm create demo                                        # Scaffold a chart: Chart.yaml, values.yaml, templates/
helm show values ./demo | head -20                      # Defaults you can override
helm template shop ./demo --set replicaCount=3          # Render only, no cluster
helm install shop ./demo -n shop --create-namespace --set replicaCount=3
helm upgrade shop ./demo -n shop --set replicaCount=2 --wait --timeout 3m
helm history shop -n shop                               # REVISION, STATUS, DESCRIPTION
helm get values shop -n shop                            # Values you supplied
kubectl get secret -n shop -l owner=helm                # One Secret per revision
helm rollback shop 1 -n shop                            # Writes a new revision
```
