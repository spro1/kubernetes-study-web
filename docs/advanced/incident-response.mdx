## Incident phases at a glance

| Phase | Goal | Who | Common mistake |
|---|---|---|---|
| Detect | Know users are hurting | Alerting, on-call | Paging on causes (CPU, disk) instead of symptoms |
| Acknowledge | Someone owns it | On-call | Silent pages that escalate because nobody acked |
| Declare | Start a coordinated response | On-call, then IC | Declaring too late, or arguing about severity |
| Coordinate | One plan, one channel | Incident commander | IC fixing things instead of leading |
| Mitigate | Stop user impact | Operations lead, subject experts | Debugging the root cause while users wait |
| Communicate | Keep everyone informed | Communications | No next-update time, so people ask the responders |
| Resolve | Confirm recovery holds | IC | Closing as soon as one graph looks better |
| Learn | Prevent a repeat | Whole team | Blaming a person; action items with no owner |

Common mitigations and their limits:

| Mitigation | When it helps | Watch out |
|---|---|---|
| Roll back | A recent deploy or config change | Does not undo data or schema changes |
| Fail over | One region, zone or cluster is bad | The other side needs enough capacity |
| Shed load | Overload, retry storms | Pick what to drop (low-priority traffic first) |
| Feature flag off | One feature causes the damage | The flag must exist and be tested |
| Scale out | Real demand above capacity | Does not help when a dependency is the bottleneck |

## Try it yourself

```bash
# What changed recently? Rollout history and recent events
kubectl rollout history deployment/checkout -n shop
kubectl get events -n shop --sort-by=.lastTimestamp | tail -20

# Mitigate: roll back to the previous revision and wait for it
kubectl rollout undo deployment/checkout -n shop
kubectl rollout status deployment/checkout -n shop

# Record why, so the timeline shows it later
kubectl annotate deployment/checkout -n shop \
  kubernetes.io/change-cause="incident 2026-11-27: roll back v42" --overwrite

# Which alerts are firing right now (Alertmanager CLI)
amtool --alertmanager.url=http://localhost:9093 alert query
```
