# CRDs and Operators

Built-in Kubernetes resources have no concept like "a database" or "a nightly backup". So you register a new resource kind (CRD) and attach a program that handles it (an operator). Most tools, such as Istio (service mesh), Velero (backup) and the NVIDIA GPU Operator, are built on this pattern. The `Database` below is an example resource for illustration.

## Working back from the symptom

| Symptom | Likely cause | What to check |
| --- | --- | --- |
| A CR was created hours ago and status is still empty | No controller (operator) to handle it, or it is stopped | Whether the controller Pod runs, its logs, the CR's events |
| After upgrading a tool, saving with new fields is rejected | Helm did not update the CRD, so the old schema remains | The CRD update steps in the tool's upgrade guide |
| After removing a tool, the namespace never leaves Terminating | The operator that clears CR finalizers was deleted first | Finalizers on the remaining CRs |
| All backup schedules disappeared at once | A CRD deletion removed every CR of that kind | History of tool removal and upgrades |
