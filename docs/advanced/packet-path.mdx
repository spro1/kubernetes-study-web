# A Packet from Pod to Pod

Services and DNS decide "where to send". This lesson covers what comes next. We follow a packet (a chunk of data on the network) through the actual devices it crosses, down inside the node, until it reaches another Pod. The path of outside requests is in [How a Request Reaches a Pod](../k8s/traffic.mdx), and name resolution is in [Finding Services by Name (Service·DNS)](../k8s/service-dns.mdx).

## Narrowing down the layer by symptom

| Symptom | Layer to suspect | What to check |
| --- | --- | --- |
| A new node stays NotReady | CNI | Whether the CNI plugin is installed and running on that node |
| Pods on the same node talk, but not across nodes | Cross-node routing | Overlay or direct routing setup, firewalls between nodes |
| Small requests work, large responses get cut | Overlay MTU | Whether the Pod-side MTU is smaller than the physical MTU |
| Works via Pod IP, fails via Service IP | NAT rules / Service | Whether the Service targets (endpoints) include ready Pods |

## Try it yourself

```bash
kubectl get pods -o wide                                             # Pod IP and node
kubectl get nodes -o custom-columns=NAME:.metadata.name,PODCIDR:.spec.podCIDR   # Pod range per node (empty with some CNIs)
ip route                                                             # (On a node) routes to other nodes' Pod ranges
kubectl get endpointslices -l kubernetes.io/service-name=<service>   # Pod IPs behind the Service IP
kubectl get configmap kube-proxy -n kube-system -o jsonpath='{.data.config\.conf}' | grep mode   # kube-proxy mode (empty = iptables)
```
