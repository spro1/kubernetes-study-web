# Control Plane HA and etcd Quorum

Production clusters run an odd number of control plane (master) nodes, such as three, behind a single shared address. Let's follow etcd's majority agreement (quorum) to see why three, and what stops when some of them go down.

## etcd members and tolerated failures

| etcd members | Quorum (majority) | Failures tolerated |
| --- | --- | --- |
| 1 | 1 | 0 |
| 2 | 2 | **0** |
| 3 | 2 | 1 |
| 4 | 3 | **1** |
| 5 | 3 | 2 |

## Try it yourself

```bash
kubectl get pods -n kube-system -l component=etcd -o wide   # One etcd member per control plane node
kubectl get --raw='/readyz?verbose' | grep etcd             # Can the API server reach etcd?
export ETCDCTL_ENDPOINTS=<endpoint> ETCDCTL_CACERT=<ca.crt> ETCDCTL_CERT=<client.crt> ETCDCTL_KEY=<client.key>   # Cert flags once, for the commands below
etcdctl endpoint status --cluster -w table                  # Who is leader, Raft term and index
etcdctl endpoint health --cluster -w table                  # Members alive: is a majority up?
```
