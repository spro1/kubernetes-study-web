# What a Managed Database Does for You

A managed database hands the engine, the OS and the hardware to the cloud provider. Follow one Amazon RDS for PostgreSQL instance (Cloud SQL and Azure Database work much the same) through **failover, restore, maintenance and a connection storm**, and see which parts are still your job.

## Who does what

| Task | Provider | You |
|---|---|---|
| Hardware, OS, engine install | Runs and patches them | Pick the instance class and engine version |
| High availability | Keeps the standby, detects failure, flips DNS | Turn Multi-AZ on; make the app reconnect and retry |
| Read scaling | Creates and feeds replicas | Send reads to the replica endpoint; handle lag |
| Backups | Daily snapshots, logs, point-in-time restore | Set retention; run restore drills; repoint the app after a restore |
| Maintenance | Applies patches and minor versions in the window | Choose the window; plan major upgrades (blue/green) |
| Settings | Offers parameter groups | Create your own group; reboot for static parameters |
| Connections | Sets max_connections from memory; offers a proxy | Size pools; add a proxy such as RDS Proxy or PgBouncer |
| Storage and encryption | Grows storage up to a limit; encrypts with KMS | Set the maximum; enable encryption at creation |
| Schema, queries, indexes | — | All yours |

Same ideas, other names: Google Cloud SQL calls Multi-AZ "high availability (regional instance)" and uses database flags; Azure Database for PostgreSQL flexible server calls it "zone-redundant high availability" and uses server parameters.

## Try it yourself

These are AWS CLI examples.

```bash
aws rds describe-db-instances --db-instance-identifier mydb \
  --query 'DBInstances[].[Endpoint.Address,MultiAZ,AvailabilityZone,SecondaryAvailabilityZone,StorageEncrypted,MaxAllocatedStorage]'
dig +short mydb.xxxx.ap-northeast-2.rds.amazonaws.com             # Where the endpoint CNAME points now
aws rds reboot-db-instance --db-instance-identifier mydb --force-failover   # Drill a failover (staging!)
aws rds describe-events --source-identifier mydb --source-type db-instance --duration 60   # failover started / completed
aws rds describe-db-instances --db-instance-identifier mydb \
  --query 'DBInstances[].[LatestRestorableTime,BackupRetentionPeriod,PreferredBackupWindow,PreferredMaintenanceWindow]'
aws rds restore-db-instance-to-point-in-time --source-db-instance-identifier mydb \
  --target-db-instance-identifier mydb-restored --restore-time 2026-11-27T05:02:00Z \
  --db-parameter-group-name my-pg17                                # A NEW instance with its own endpoint
aws rds describe-pending-maintenance-actions                      # Required and optional updates
aws rds describe-db-parameters --db-parameter-group-name my-pg17 \
  --query "Parameters[?ParameterName=='max_connections']"         # Often a formula based on memory
```

```sql
SHOW max_connections;
SELECT count(*), state FROM pg_stat_activity GROUP BY state;     -- who holds connections
```
