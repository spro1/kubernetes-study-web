# Who Owns What (IaaS · PaaS · SaaS)

A web service that ran in the company server room is moving to the cloud. Depending on how you move it, what your team must handle changes a lot. Split the service into six layers and follow where the line of responsibility moves.

## Responsibility by model at a glance

| Model | We manage | Provider manages | Examples (AWS · Azure · GCP) |
| --- | --- | --- | --- |
| On-premises | Everything from hardware to data | Nothing | Company server room or data center |
| IaaS | OS, runtime, app, data | Hardware, virtualization | EC2 · Virtual Machines · Compute Engine |
| PaaS | App, data | Hardware, virtualization, OS, runtime | Elastic Beanstalk · App Service · App Engine |
| SaaS | Data, accounts, permissions | Everything up to the app | Business services like Microsoft 365 and Google Workspace |

## Try it yourself

```bash
cat /etc/os-release                                  # OS version: yours to patch on IaaS
uname -r                                             # Kernel version
kubectl version                                      # Control plane version (provider-run if managed)
kubectl get nodes -o wide                            # Node OS image and kernel: who patches these?
aws s3api get-public-access-block --bucket <bucket>   # Is storage open to anyone? (AWS example)
```
