# When a Whole Region Goes Down

Spreading across availability zones protects you from one data center failing. It does not help when the whole region has an outage, or when someone deletes a table by mistake. Follow a store as it prepares a second region and then has to use it.

## The four DR strategies

These ranges follow the AWS disaster recovery whitepaper. Your real numbers come from drills.

| Strategy | What runs in region B | RPO | RTO | Standing cost |
|---|---|---|---|---|
| Backup and restore | Only backup copies; infrastructure is created from IaC on the day | Hours (since the last backup) | Hours | $ |
| Pilot light | Live data (replica); app off or scaled to zero | Seconds to minutes (replication lag) | Tens of minutes | $$ |
| Warm standby | A smaller full copy that can serve traffic right away | Seconds to minutes | Minutes | $$$ |
| Multi-site active-active | Full capacity, serving users all the time | Near zero | Near zero | $$$$ |

Whatever the strategy, keep backups as well: only a point-in-time copy undoes a deleted table or encrypted data.

## Try it yourself

These are AWS examples. Other clouds have the same building blocks under different names.

```bash
# Copy a DB snapshot to the recovery region (run against the destination region; encrypted snapshots also need --kms-key-id)
aws rds copy-db-snapshot --region ap-northeast-1 \
  --source-db-snapshot-identifier arn:aws:rds:ap-northeast-2:<account>:snapshot:<snapshot> \
  --target-db-snapshot-identifier <snapshot>-dr

aws ec2 copy-snapshot --region ap-northeast-1 --source-region ap-northeast-2 --source-snapshot-id <snap-id>   # Disk snapshot copy

aws backup describe-backup-vault --backup-vault-name <vault>          # Locked: is the vault lock on?
aws route53 list-health-checks                                         # Health checks behind DNS failover
aws route53 get-health-check-status --health-check-id <id>             # What each checker sees right now
dig +noall +answer shop.example.com                                    # The TTL clients will cache
```

Restore drill checklist: pick a backup at random → restore into an empty environment → start the app against it → check the newest record's time (your RPO) → write down the total time (your RTO) and every manual step.
