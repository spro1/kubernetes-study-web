# How a CDN Serves a Request

A CDN (content delivery network) keeps copies of your responses in many edge locations close to users. Follow one file from the first miss to a cache hit, then see what goes wrong after a deploy and with private pages. The basic web request is in [When You Type an Address](../basic/web-request.mdx).

## Response headers to read

| Header | Example | What it tells you |
|---|---|---|
| Cache-Control | `public, max-age=31536000, immutable` | Who may store the response and for how long. `s-maxage` is for shared caches only. `private` and `no-store` keep it out of the CDN |
| Age | `120` | Seconds the response has been in a cache. Missing or 0 usually means it came fresh from the origin |
| ETag | `"5d8c72a5"` | Version tag of the content. Used in `If-None-Match` to get `304 Not Modified` |
| Last-Modified | `Tue, 24 Nov 2026 03:10:00 GMT` | Older way to revalidate, with `If-Modified-Since` |
| Vary | `Accept-Encoding` | Request headers that are part of the cache key. `Vary: *` or many values cut the hit rate |
| Hit header (vendor-specific) | `X-Cache: Hit from cloudfront`, `cf-cache-status: HIT` | The CDN's own verdict: HIT, MISS, EXPIRED, BYPASS and so on. The name and values differ by vendor |

## Try it yourself

```bash
dig +short www.example.com                         # A CNAME to the CDN's hostname means the CDN is in front
curl -sI https://<your-site>/<file> | grep -iE 'cache-control|^age|etag|x-cache|cf-cache-status'   # 1st call: likely MISS
curl -sI https://<your-site>/<file> | grep -iE 'cache-control|^age|etag|x-cache|cf-cache-status'   # 2nd call: HIT, Age grows
curl -sI -H 'If-None-Match: "<etag from above>"' https://<your-site>/<file> | head -1     # 304 if unchanged
curl -sI https://<your-site>/account | grep -i cache-control   # Personal pages should say private or no-store
```
