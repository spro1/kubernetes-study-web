# Splitting a Model Across GPUs (TP, PP, EP)

A 70B model in 16-bit weights takes about 140 GB. One 80 GB GPU cannot hold it, let alone its KV cache. Follow the same model as it is **copied, split by layer width, split by layer depth and spread by expert**, and see what each choice sends between GPUs.

## Four ways to split, compared

| Kind | What is split | Traffic between GPUs | Where it fits |
|---|---|---|---|
| Data parallel (DP) | Nothing: full copies | None while serving | More throughput when one copy fits |
| Tensor parallel (TP) | The matrices inside every layer | All-reduce about twice per layer, every step | Inside one node, over NVLink or similar |
| Pipeline parallel (PP) | The layer stack, into stages | Activations at each stage boundary, point to point | Across nodes, when one node is not enough |
| Expert parallel (EP) | MoE experts, placed on different GPUs | All-to-all token routing every MoE layer | MoE models, combined with DP or TP for attention |

They combine. A large deployment can be TP inside each node, PP across nodes, and DP for many such replicas.

## Try it yourself

```bash
nvidia-smi topo -m                                    # NV# = NVLink between GPUs, SYS/PHB = slower paths
vllm serve <model> --tensor-parallel-size 4           # e.g. vLLM: one node, 4 GPUs
vllm serve <model> --tensor-parallel-size 4 \
  --pipeline-parallel-size 2                          # 8 GPUs over 2 nodes (needs a multi-node runtime such as Ray)
vllm serve <moe-model> --tensor-parallel-size 8 --enable-expert-parallel   # MoE experts spread over GPUs
kubectl get leaderworkerset -A                        # Groups and their size
kubectl get pods -L leaderworkerset.sigs.k8s.io/worker-index   # 0 = leader, 1.. = workers
```
