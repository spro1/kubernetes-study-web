# Splitting Prefill and Decode (P/D Disaggregation)

Prefill (reading the prompt) is compute-heavy; decode (writing the answer) is memory-read-heavy. Mixing them on one accelerator makes them get in each other’s way. **Prefill/decode disaggregation** runs the two phases on different accelerators and hands the KV cache from prefill to decode so the answer can continue.

## What to check on Kubernetes

- On Kubernetes, prefill and decode run as separate workloads, and the endpoint picker (EPP) from the Gateway API Inference Extension pairs them per request. llm-d is one open-source project that packages this setup.
- Scale prefill and decode replicas separately. If TTFT grows on long-input workloads, add prefill replicas; if TPOT grows on long-output workloads, add decode replicas.
- RDMA is a prerequisite. Nodes need RDMA-capable NICs, and those devices must be attached to the Pods. Check the engine logs to confirm the KV transfer uses RDMA and has not fallen back to TCP.
- Before switching, measure TTFT and TPOT for single and disaggregated serving side by side at your real concurrency. If TTFT gets worse at low load, the case for splitting is weak.
