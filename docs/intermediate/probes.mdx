# Health checks — alive, and ready for requests?

A running container does not guarantee that the application works. Here we follow what the kubelet asks with three periodic checks (probes), and what it does with each answer. How a dead container comes back is covered in [When a Pod Dies (Self-Healing)](../k8s/self-healing.mdx).

## Probe mistakes and their results

| Probe | Common mistake | Result | Fix |
| --- | --- | --- | --- |
| liveness | Also checks the DB connection | When the DB slows briefly, all pods restart at once | Check only that the process is alive |
| liveness | Initial delay shorter than startup time | Restarts before ready, ending in `CrashLoopBackOff` | Add a startup probe or raise the delay |
| readiness | Not set at all | Requests reach new pods before they are ready, causing errors on every update | Expose an endpoint that reports readiness |
| readiness | Always returns success | Takes requests even when a dependency is down, returning errors to users | Check needed dependencies here |
| startup | Missing on a slow-starting app | Liveness fails first and restarts it mid-start | Allow the maximum startup time |
