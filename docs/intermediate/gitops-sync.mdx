# Helm and GitOps

With many manifests, you must track two things separately: "what did I install together" and "is the cluster in the right state now". Helm solves the first, GitOps the second. Here we follow how a Helm release and a GitOps sync tool (for example Argo CD or Flux) keep the cluster in line.

## Push vs. pull

| Aspect | Push (CI/CD pipeline deploy) | Pull (GitOps) |
| --- | --- | --- |
| Who applies | External CI/CD tool | GitOps tool inside the cluster |
| When | Once, when a run is triggered | Continuously (periodic comparison) |
| Source of truth | The tool's deploy config and run history | Git repository |
| Reverting | Pick an earlier version from history and reapply | Revert to an earlier commit in Git and the tool follows |
| Direct edits | Stay until the next deploy | Detected as drift and may be reverted |

## Try it yourself

```bash
helm list -A                                         # Releases and their current revision
helm history <release> -n <namespace>                # Revisions, rollbacks included
helm get values <release> -n <namespace>             # values that filled the chart
argocd app get <app>                                 # Argo CD: Synced or OutOfSync
argocd app diff <app>                                # Drift between Git and the cluster
flux get kustomizations -A                           # Flux: ready state and applied revision
```
