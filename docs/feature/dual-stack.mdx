# IPv4/IPv6 Dual-Stack Networking

A cluster that hands out both IPv4 and IPv6 addresses. Follow how the control plane, the CNI, Services and DNS each get a second address family, and where applications trip over it. The layers underneath are in [Under One Request: TCP/IP Layers](../basic/tcp-ip-layers.mdx).

## Service ipFamilyPolicy

| ipFamilyPolicy | ClusterIPs | On a single-stack cluster | Typical use |
| --- | --- | --- | --- |
| SingleStack (default) | One, from the first Service range or the family in `ipFamilies` | Works | Existing Services, apps not yet tested on IPv6 |
| PreferDualStack | Two when the cluster is dual-stack | Falls back to one | Most Services once the app listens on both families |
| RequireDualStack | Always two | Creation fails | Services that must be reachable over both families |

Headless Services without a selector that do not set `ipFamilyPolicy` default to RequireDualStack. The first entry in `ipFamilies` is the primary family and cannot be changed on an existing Service.

## Try it yourself

```bash
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"  "}{.spec.podCIDRs}{"\n"}{end}'   # One Pod CIDR per family
kubectl get pod <pod> -o jsonpath='{.status.podIPs}'                       # Two entries on dual-stack
kubectl get svc <svc> -o jsonpath='{.spec.ipFamilyPolicy} {.spec.ipFamilies} {.spec.clusterIPs}'
kubectl patch svc <svc> -p '{"spec":{"ipFamilyPolicy":"PreferDualStack"}}'   # Add the second family in place
kubectl run dns-test --rm -it --image=busybox:1.36 --restart=Never -- nslookup -type=AAAA <svc>.<namespace>.svc.cluster.local
kubectl exec <pod> -- ss -ltn       # If the image has ss: 0.0.0.0:8080 = IPv4 only, [::]:8080 = IPv6 too
```
