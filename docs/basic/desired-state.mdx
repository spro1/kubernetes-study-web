# Desired State and the Control Loop

You do not tell Kubernetes "do this". You write down "it should look like this", and controllers keep comparing that with how things are now and fix the difference. Follow this comparison loop, and how resources find each other with labels and selectors. How a Pod starts, part by part, is covered in [How a Pod Starts](../k8s/pod-startup.mdx).

## Myths and facts

| Common myth | In reality |
| --- | --- |
| If apply succeeds, all Pods are up | Only the desired state is recorded. The actual state takes time to catch up |
| Lack of resources causes an error | No error. Pods wait as Pending and keep retrying until room opens up |
| Users edit status too | Kubernetes fills status. Users write only spec |
| A Service finds targets by Pod name | It uses a label selector. New Pods with matching labels join automatically |
| A wrong selector is rejected on save | It saves fine, with 0 targets |

The control loop actually bringing a Pod back continues in [When a Pod Dies (Self-Healing)](../k8s/self-healing.mdx).
