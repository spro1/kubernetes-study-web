# The Inner Dev Loop on Kubernetes

The inner loop is what you repeat dozens of times a day: change code, see it run. On Kubernetes, doing it by hand means build, push, deploy and wait. Follow one file save and see how tools shorten that loop.

## Which tool for which part of the loop

| Need | Example tools | What it does | Watch out |
|---|---|---|---|
| Watch, build, deploy on save | Skaffold (`skaffold dev`), Tilt (`tilt up`) | Chains build, tag, render, deploy and logs | Check the kubectl context first |
| Skip rebuilds for small edits | Skaffold `sync`, Tilt `live_update` | Copies files into the running container | Needs `tar` in the container for Skaffold; drift from the image |
| No registry locally | `kind load`, a local registry wired to kind | Puts the image straight into the nodes | Only for local clusters |
| See the app | `kubectl port-forward`, `kubectl logs -f`, tool UIs | Brings ports and logs to your terminal | Forward stops when the Pod restarts with plain kubectl |
| Production-like config | Helm values file, Kustomize overlay | Same templates as prod, dev settings | Keep dev differences small |
| Real dependencies | Telepresence, mirrord | Local process joins a shared cluster | Can take traffic from others |
| Same tools for everyone | Dev Containers (`devcontainer.json`) | Pins the toolchain in a container | Docker-in-container setup for kind |

## Try it yourself

```bash
kubectl config current-context            # kind-lab means Skaffold treats it as local (no push)
skaffold init                             # generate skaffold.yaml from Dockerfile and manifests
skaffold dev --port-forward               # watch, build, deploy, stream logs; Ctrl+C cleans up
skaffold render -p dev                    # print the manifests the dev profile would apply
tilt up                                   # read the Tiltfile; UI on http://localhost:10350
tilt down                                 # remove what tilt up deployed
kubectl port-forward svc/my-app 8080:80   # what the tools do under the hood
kubectl logs -f deploy/my-app             # stream logs from one Pod of the Deployment
```
