## Physical server vs VM vs container

| Type | What it has on its own | Traits |
| --- | --- | --- |
| Physical server | All hardware and the OS | One program per server leaves resources unused |
| Virtual machine | Its own OS | The hypervisor allocates and isolates resources. Heavy, since it carries a whole OS |
| Container | Only programs and libraries | Shares the kernel. Starts in seconds, and many more fit on one server |

Where a container's source (the image) comes from is the next lesson. How a container actually starts on a node is in [How a Pod Starts](../k8s/pod-startup.mdx).

## Try it yourself

```bash
nproc; free -h; df -h                                # CPU, memory, disk (on a Linux server)
ps -ef | head                                        # Processes and their PIDs
kubectl get nodes -o custom-columns=NAME:.metadata.name,CPU:.status.capacity.cpu,MEMORY:.status.capacity.memory   # Node size
kubectl top nodes                                    # CPU and memory use per node (needs metrics-server)
kubectl get pod <pod> -o jsonpath='{.status.containerStatuses[*].lastState.terminated.reason}'   # OOMKilled after a memory limit?
```
