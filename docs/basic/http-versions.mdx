# HTTP/1.1, HTTP/2 and HTTP/3

A page needs dozens of files. The meaning of each request (method, path, headers, status) is the same in every HTTP version. What changes is **how the bytes travel**: one request at a time, many streams on one TCP connection, or streams over QUIC on UDP. Status codes are covered in [When You Type an Address](../basic/web-request.mdx).

## The three versions compared

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
|---|---|---|---|
| Transport | TCP (+ TLS) | TCP + TLS (h2), cleartext h2c between services | QUIC over UDP, TLS 1.3 built in |
| Message format | Text lines | Binary frames on streams | Binary frames on QUIC streams |
| Requests per connection at once | One response at a time | Many interleaved streams | Many independent streams |
| Header compression | None | HPACK | QPACK |
| Head-of-line blocking | Per connection, at HTTP level | At TCP level, when a packet is lost | Only the stream that lost data |
| Round trips before the first request (new connection, TLS 1.3) | 2 | 2 | 1 (0 with 0-RTT resumption) |
| How the version is chosen | Default | ALPN `h2` | `Alt-Svc` header or DNS HTTPS record, then ALPN `h3` |
| Spec | RFC 9112 | RFC 9113 | RFC 9114 |

## Try it yourself

```bash
curl -sv --http1.1 -o /dev/null https://<domain>/ 2>&1 | grep -E 'ALPN|^> GET|^< HTTP'   # Forces HTTP/1.1
curl -sv --http2   -o /dev/null https://<domain>/ 2>&1 | grep -E 'ALPN|^< HTTP'          # Offers h2 via ALPN
curl -sI https://<domain>/ | grep -i alt-svc                                             # Does the server advertise h3?
curl -s --http3 -o /dev/null -w '%{http_version}\n' https://<domain>/                    # Needs a curl built with HTTP/3
openssl s_client -connect <domain>:443 -alpn h2 </dev/null 2>/dev/null | grep ALPN        # "ALPN protocol: h2"
```

In browser DevTools, right-click the Network table header and turn on the **Protocol** column to see `http/1.1`, `h2` or `h3` per request.
