# Reverse Proxies and Load Balancing

Almost every request you serve passes through a reverse proxy such as nginx, HAProxy or Envoy before your code sees it. Follow one request through an L4 load balancer and an L7 proxy and see how a backend is chosen and checked, what headers get added, and where 502 and 504 come from.

## L4 or L7, and what each status code means

| | L4 load balancer | L7 reverse proxy |
|---|---|---|
| Works on | TCP or UDP connections | HTTP requests |
| Sees | IP and port (SNI with TLS passthrough) | Host, path, headers, cookies |
| Decides | Once per connection | Per request |
| Client IP for the app | Kept or via PROXY protocol, depending on mode | `X-Forwarded-For` or `Forwarded` header |
| Can do | Any protocol, very fast | Path routing, rewrites, retries, auth, header changes |
| Examples | Cloud network LB, IPVS, HAProxy `mode tcp` | nginx, HAProxy `mode http`, Envoy, cloud application LB |

| Status from the proxy | Meaning | Common cause | Check |
|---|---|---|---|
| 502 Bad Gateway | Upstream refused, reset or sent an invalid response | App crashed, wrong port, upstream closed an idle keep-alive connection | App logs, upstream port, idle timeouts |
| 503 Service Unavailable | No backend can take the request | All backends failed health checks, or none are configured | Health check results, endpoints behind the proxy |
| 504 Gateway Timeout | Upstream did not answer within the proxy timeout | Slow query or downstream call, timeout set too low | Upstream response time, `proxy_read_timeout` or the route timeout |

## Try it yourself

```bash
curl -sv -o /dev/null https://example.com/ 2>&1 | grep -iE '^< (server|via|x-cache)'   # Which proxy answered
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://example.com/           # Status and total time
curl -s -H 'X-Forwarded-For: 1.2.3.4' http://localhost:8080/ip   # Does your app trust a forged header? (your own test endpoint)
nginx -T 2>/dev/null | grep -E 'proxy_(connect|read|send)_timeout|keepalive|real_ip'   # Effective nginx timeouts and trust settings
echo 'show servers state' | socat stdio /var/run/haproxy.sock   # HAProxy backend state (needs a stats socket)
curl -s localhost:9901/clusters | grep health_flags              # Envoy admin: health of each upstream host
kubectl logs -n ingress-nginx deploy/ingress-nginx-controller | grep -E '" 50[234] '   # 502/503/504 in Ingress access logs
```
