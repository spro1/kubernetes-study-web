# Choosing an LLM Serving Engine

Many engines can serve the same open model, and most of them look alike from the outside. See what they share, where they really differ, and how to run a comparison that answers the question for your own model, hardware and traffic.

## Engines at a glance

Status checked against each project's own README and docs. Features move fast, so check again before you decide.

| Engine | Good fit | Hardware | Notes |
|---|---|---|---|
| vLLM | General-purpose serving, widest model coverage | NVIDIA, AMD, Intel GPUs, CPUs; TPU, Gaudi, Ascend and more via plugins | `vllm serve`, structured output, multi-node, large community |
| SGLang | Prefix-heavy workloads such as agents and multi-turn chat | NVIDIA, AMD, TPU, NPU, CPU, Apple Silicon | RadixAttention prefix cache, structured output, multi-node |
| TensorRT-LLM | Peak performance on NVIDIA GPUs | NVIDIA only | `trtllm-serve` or Triton TensorRT-LLM backend |
| NVIDIA Dynamo | Multi-node, disaggregated serving at data-center scale | Depends on the engine below | Orchestrates SGLang, TensorRT-LLM or vLLM; not an engine itself |
| Hugging Face TGI | Existing deployments only | — | Maintenance mode: minor fixes only, project recommends vLLM or SGLang |
| llama.cpp | Local and edge, CPU or small GPUs, GGUF models | CPU, Apple, NVIDIA, AMD, Vulkan and more | `llama-server` with an OpenAI-compatible endpoint |
| Ollama | Easy local use for developers | Desktop and server GPUs, CPU | Pull-and-run models, own API plus OpenAI-compatible routes |

## Try it yourself

```bash
# Serve a model with vLLM (any engine with an OpenAI-compatible API works the same way below)
vllm serve Qwen/Qwen2.5-7B-Instruct --port 8000

curl -s localhost:8000/v1/models                     # the served model name
curl -s localhost:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"Qwen/Qwen2.5-7B-Instruct","messages":[{"role":"user","content":"Hi"}],"max_tokens":32}'

# Same benchmark against each engine: fixed lengths, fixed concurrency, goodput at your SLO (ms)
vllm bench serve --backend openai-chat --base-url http://localhost:8000 \
  --endpoint /v1/chat/completions --model Qwen/Qwen2.5-7B-Instruct \
  --dataset-name random --random-input-len 2000 --random-output-len 200 \
  --num-prompts 500 --max-concurrency 32 \
  --percentile-metrics ttft,tpot --goodput ttft:1000 tpot:50

kubectl get pods -l app=llm -o wide                  # engine Pods and their nodes
kubectl get inferenceservice -A 2>/dev/null          # if KServe is installed
```
