# Evaluating a Model Before and After Deploy

A new model, prompt or quantization can look fine in a few chats and still break real tasks. Evaluation turns "looks fine" into numbers you can compare: offline before deploy, then online on real traffic.

## Which evaluation for which job

| Method | Good for | Watch out |
|---|---|---|
| Exact match | Short answers, labels, IDs | Normalize case, spaces and punctuation first |
| pass@k | Code with unit tests | pass@1 is what users see; tests must be strong |
| Format checks | JSON, tool calls, schemas | Valid format does not mean right content |
| LLM-as-judge | Summaries, replies, open answers | Position, length and self-preference bias; calibrate with humans |
| Human review | Small samples, new tasks, judge calibration | Slow and costly; use a clear rubric |
| Safety and refusal evals | Harmful requests refused, benign ones answered | Track both over-refusal and under-refusal |
| Online canary or A/B | Real traffic, real latency | Needs enough traffic and an automatic rollback |

## Try it yourself

```bash
# Run the same eval against baseline and candidate (both serve an OpenAI-compatible API)
lm_eval --model local-completions --tasks gsm8k \
  --model_args model=chat-model,base_url=http://baseline:8000/v1/completions \
  --output_path results/baseline --log_samples
lm_eval --model local-completions --tasks gsm8k \
  --model_args model=chat-model,base_url=http://candidate:8000/v1/completions \
  --output_path results/candidate --log_samples

# Compare the scores side by side
find results -name 'results_*.json' -exec jq -c '{file: input_filename, results}' {} \;

# Watch the online canary (if you deliver with Argo Rollouts)
kubectl argo rollouts get rollout chat-model -n llm --watch
```
