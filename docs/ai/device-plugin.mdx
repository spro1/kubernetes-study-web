# How GPUs and NPUs become node resources (device plugins)

Out of the box, Kubernetes only knows about CPU and memory. Plugging a GPU or NPU into a server does not let Pods request it. A **device plugin** is what advertises the device to Kubernetes as a resource. Follow a device from the node until it is attached to a Pod.

## Device plugins vs DRA

| | Device plugin | DRA |
| --- | --- | --- |
| How you request | Count only (`nvidia.com/gpu: 1`) | Device class + attribute criteria |
| What the node reports | Device count and health per resource name | Per-device attributes (ResourceSlice) |
| Who picks the device | The kubelet on the node | The scheduler |
| Sharing | Node-side settings (MIG, time-slicing, etc.) | Expressed in the claim, if the driver supports it |

The basic DRA flow is covered in [Requesting GPUs by Criteria (DRA)](../k8s/dra.mdx). The next lesson, [Getting Accelerators by Criteria (DRA in Depth)](./accelerator-allocation.mdx), follows an AI workload that gets a GPU and a network card together by criteria.
