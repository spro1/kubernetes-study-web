# Getting a Model Ready to Deploy

A model on Hugging Face does not make a serving Pod start fast. Tens to hundreds of GB of weights have to be **pulled → packaged for deployment → pre-pulled onto GPU nodes**. Follow what each stage does and what it leaves behind.

## Ways to deliver model files

| | Download at startup | Unpack onto a PVC | OCI artifact + node cache |
| --- | --- | --- | --- |
| First start time | Long, every time | Depends on volume performance | Short when cached |
| Versioning | Depends on pinned revision | Managed by path conventions | Tags and digests |
| What to watch | External network, tokens | Storage readable from many nodes | Node disk size, image GC |

## Try it yourself

```bash
kubectl get jobs -n <namespace>                      # Import and build Job progress (steps 2, 5)
kubectl get job <name> -n <namespace> -o jsonpath='{.spec.backoffLimit} {.spec.activeDeadlineSeconds}'   # Retry count and time limit
kubectl get daemonsets -A -o wide                    # Pre-pull DaemonSet ready on GPU nodes (step 7)
kubectl describe pod <pod> | grep -iE 'pulling|pulled'   # Model pull time (step 8)
crictl images                                        # On the node: is the cache there?
```
