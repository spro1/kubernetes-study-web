# From Training Job to Model

GPUs are shared by many teams. Instead of running training and evaluation Jobs right away, you put them in a **queue** and run them when the team’s GPU quota has room. Using Kueue as the example, follow a Job as it waits, runs, leaves artifacts, and becomes a version in a model registry.

## Run directly vs queue

| | Run the Job directly | Kueue queue |
| --- | --- | --- |
| When GPUs run short | Some Pods start and hold GPUs while others stay Pending | The whole Job waits suspended |
| Fairness across teams | First come, first served | Per-team quota, borrowing, preemption |
| Finding the waiting reason | Read Pod events one by one | Workload status message |

## Try it yourself

```bash
kubectl get localqueues -n <namespace>               # Team queue the Job names (step 1)
kubectl get job <name> -n <namespace> -o jsonpath='{.spec.suspend}'   # true until Kueue admits it (step 2)
kubectl get workloads -n <namespace>                 # One Workload per Job, admitted or not
kubectl describe workload <name> -n <namespace>      # Why it waits: quota, queue, preemption
kubectl describe clusterqueue <name>                 # Quota usage and borrowing (step 4)
```
